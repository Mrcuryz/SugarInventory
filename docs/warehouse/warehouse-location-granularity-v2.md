# 库位粒度统一方案 V2

更新时间：2026-08-30

## 1. 业务结论

库存实际管理只精确到库位，不再区分库位内部的左/右侧、排号或层数。现场、Web、DT50 和 Agent 只要求用户选择或扫描一个库位；容量由库位的 `max_capacity` 与 `cur_capacity` 表达。

## 2. 数据库兼容策略

- 不修改数据库结构，不迁移或改写历史库存。
- 新库存仍需满足现有字段和唯一约束，统一由后端写入隐藏兼容值：`side=左`、`layer=1`。
- `row_number` 仅作为后端生成的技术序号，不代表现场物理排号，不进入任何用户输入、回答、卡片或操作提示。
- 现有历史记录中的左右、排、层保留原值，但业务查询、出库和调拨不再把这些字段作为用户选择条件。

## 3. 业务规则

- 入库：用户只提供托盘码、目标库位及表单中的日期、数量、单位、备注；后端校验目标库位剩余容量并分配隐藏兼容坐标。
- 连续扫码入库：DT50 先扫库位码，再连续扫托盘码，确认时只提交库位名称和托盘码。
- 调拨：用户只选择目标库位；预览和提交按目标库位剩余容量校验，目标内部坐标由后端生成。
- 出库：按托盘或库位内库存选择，不再按左/右侧排序或筛选。
- 自动入库：解析、修改和确认均不再要求侧别；服务端统一应用兼容策略。
- 容量：新增和修改库位以最大容量为准；旧 `max_rows` 字段只保留数据库兼容含义。

## 4. Agent 与 MCP 契约

精确成品入库预览使用仓库级协议 V2：

```json
{
  "previewVersion": 2,
  "items": [
    {
      "code": "BT0019N1",
      "warehouseName": "1号库位",
      "entryDate": "2026-08-30",
      "quantity": 1,
      "unit": "0",
      "remark": "可选备注"
    }
  ]
}
```

协议不接受或返回 `side`、`rowNumber`、`layer`。主 Agent 仍遵守“模型理解 → 专家决策 → 工具调用 → 结果分析”的统一链路，物流专家只基于用户可理解的库位级事实作出决策。

## 5. 展示规则

- 仓库平面图展示库位状态、当前容量、最大容量和库存记录，不渲染左右区、排或层。
- 库存、托盘、任务和流转记录只显示库位名称。
- 所有对话卡片和弹窗不显示、不默认、不要求侧别。
- 内部审计可以保存稳定实体 ID，但用户可见审计摘要不输出兼容坐标。

## 6. 验证要点

- 同一库位连续入库多板时不会因旧排数配置误报“已满”。
- 超过 `max_capacity - cur_capacity` 的整批入库或调拨必须整体阻断。
- Web、DT50、Agent 和 MCP 请求均不包含库位内部坐标。
- 历史库存仍可查询、出库和调拨，不要求先执行数据迁移。
- 所有写入继续使用既有权限、事务、幂等和审计边界。
