# 生产日报移动端交互设计（安卓 App 实施对照）

> 2026-10-31。用于确认手机端的页面与填写体验，不改变已经确认的生产日报字段和业务规则。

## 1. 设计依据与边界

现有日报由四个固定分区组成：多晶车间、红糖车间、单晶车间、全厂汇总。后端字段目录共包含 62 个固定指标（20、13、20、9），另有 5 个可增删产品行的分组。每条指标或产品行都有五个手工数值字段和备注；桌面 Web 使用九列表格展示，不能直接缩放到手机屏幕。

移动端保留现有能力：按日期查看、填写制表信息、填写各分区、管理产品行、保存草稿、提交分区或整张日报、查看历史、导入与导出 Excel。业务规则继续沿用已确认方案：没有必填数值；空白不同于 0；所有小计、累计、比率和全厂汇总均由用户填写；提交后仍可修改；产品单位固定为“件”；不增加计算、审核或车间级权限。

当前仓库已包含 `dt50-app/` 原生 Android 工程，使用 Java 与 XML 布局，现有 DT50 真机页面以约 360dp 宽的竖屏为设计基准。微信小程序仍是独立工程；日报应接入 DT50 App 的登录、权限和导航体系，并沿用它的蓝白色卡片视觉。

可点击的设计评审原型：[生产日报移动端原型](原型/生产日报移动端原型.html)。原型使用演示数据，保存、提交和文件操作均不连接后端。原生实现位于 `dt50-app/app/src/main/java/com/laibin/sugarinventory/dt50/ProductionDailyReportActivity.java`，接入现有接口与权限。

## 2. 页面结构

采用“日期总览 → 车间 → 指标组”三级结构。每次只展示当前任务需要的内容；各级保留返回位置、日期和未保存状态。日报日期用大日号、年月和星期组合展示，单击日历按钮打开包含历史日报状态的月视图，避免重复显示长日期与系统日期输入框。

| 页面 | 主要内容 | 主要操作 |
|---|---|---|
| 日报总览 | 业务日期、整表状态、制表日期/制表人、四个分区状态和最后修改信息 | 切换日期、打开日历与历史、编辑制表信息、进入分区、提交整张、更多操作 |
| 分区页 | 分区状态、最后修改人/时间、有序的指标组入口 | 进入指标组、保存草稿、提交本分区 |
| 指标组页 | 当前填写字段、固定指标或产品行列表 | 连续录入、打开单项全部字段、增删与排序产品 |

总览建议布局：

```text
生产日报                   更多 ⋯
31   2026年10月 · 星期六     日历
前一天           今天         后一天
草稿 · 上次修改 10:30
制表信息  制表日期 / 制表人         ›

多晶车间       草稿 · 王某 10:20    ›
红糖车间       已提交 · 李某 09:40  ›
单晶车间       待填写               ›
全厂汇总       草稿 · 张某 11:05    ›

底部：日历与历史       提交整张日报
```

分区页先显示“原料及在制品、产品分组、综合指标”等组卡片，不默认展开几十个输入框。组卡片展示组名和项目数量，产品组可展示已有产品名称摘要；不显示“完成百分比”，因为日报没有必填项。总览与分区页都显示清晰的“未保存”“本机暂存”“已保存”状态，避免把本机输入误认为已写入服务器。车间与分组使用对应的线性图标，不用名称首字代替图标。

## 3. 大量字段的录入方式

### 3.1 按字段连续录入

指标组页顶部固定显示可左右滑动的字段标签：当日实绩、折成吨、月累计（件）、月累计（吨）、年累计（吨）、备注。这六项就是 Web 日报现有的表头；移动端标签只是用来切换当前连续录入的列，没有新增业务字段或计算口径。下方始终是一列项目名称和一列输入值，纵向滚动，不出现宽表或页面横向滚动。切换录入列时保留当前组与滚动位置。

```text
多晶车间 / 原料及在制品
连续录入：当日实绩 | 折成吨 | 月累计…

出糖油      单位：桶        [ 12.5 ]  ›
化糖        单位：锅        [      ]  ›
白糖用量    单位：包        [ 20   ]  ›
……

底部：保存草稿       提交本车间
```

这种视图适合按一列连续录入。点击任意项目的右侧图标打开单项编辑页/底部弹层，纵向展示该项目的五个数值和备注，适合逐项核对和补全。返回列表后，保留先前选择的字段。列表行可简要标示“其他字段已填”，但不能仅因折叠而隐藏已有数据的存在。未提交的空输入使用中性的“点击填写”，不使用破折号表示空白；显示值时依然保留空白与数值 0 的差别。

仅当分区已提交时，才对**所有数值及备注都为空**的固定指标或已选产品行显示醒目的“未填／可补录”提示，并在分区与当前组顶部显示数量。它是补录提醒，不是提交条件；某项只有一列空白而其他列已填写时，不计入“整项未填”。保存修改后，分区按现有规则返回草稿，提醒随状态撤下。

固定指标名称和单位只读。单位与数值字段标题分开显示，不能把“吨”“件”“%”自行替换为计算结果。长项目名允许换行，完整字段名始终可见。数值右对齐、使用等宽数字；输入框、点击区和底部按钮需适配安卓触控及软键盘，不能被软键盘或系统导航栏遮住。

### 3.2 产品行

产品组沿用同一录入模式，但每个产品以卡片/列表行显示产品名称、固定单位“件”和当前选择字段的值。组顶部提供“新增产品”；进入产品详情可搜索并选择现有产品、填写五个数值和备注。选择列表只显示该产品组允许的成品/半成品类型。单晶车间产品组原有的“出糖罐数”“种子产量”仍排在产品行之前，小计仍排在产品行之后。

每条产品行提供“上移 / 下移”“删除”，可选增加拖动排序，但不把拖动作为唯一排序入口。删除有已填内容的行时确认；仅移除日报行，不删除产品主数据。空白占位产品行可展示，但保存请求中忽略完全空白行；有任何数值或备注时必须选产品。产品单位只读并固定为“件”。

### 3.3 输入与校验

- 数值输入使用小数键盘；输入过程中以文本保存，提交时按十进制字符串传输，避免 JavaScript 浮点数改变精度。
- 空输入传 `null`；明确输入的 `0` 保持为 `0`，不预填 0，也不自动计算或四舍五入。
- 按数据库 `DECIMAL(18,6)` 的容量提示超长或超过六位小数；不额外发明“必须大于零”等业务限制。
- 输入键盘的“下一项”移动到同一字段的下一个项目；错误提示定位到具体项目和字段，而不只在页顶弹一次提示。
- 备注使用多行输入；文字长度沿用服务端上限 500 字。制表人与制表日期仍可留空。

## 4. 保存、提交与多人编辑

底部固定“保存草稿 / 提交本分区”，主按钮随键盘弹出调整位置。修改后立即显示“未保存”，点击保存并收到服务端成功响应后才显示“已保存”。退出页面、切换日期或返回总览时，如有未保存内容，应提示保存或继续编辑；可按用户、日期、分区暂存本机输入，网络失败时保留并可重试。退出登录时清理本机暂存数据。

现有保存接口以**整分区**为单位，带 `version`，服务端会重写该分区的指标值和产品行。因此移动端在一个分区里编辑任意字段时，必须维护并提交完整的分区数据，不能只发送当前指标组或当前选中的一列。成功后使用响应中的新版本；遇到版本冲突时保留本机未保存输入，提示服务器已由他人更新，并让用户先查看最新内容，不能静默覆盖或自动丢弃本机输入。

点击“提交本分区”或“提交整张日报”时，先保存当前所有未保存的表头/分区内容；任一保存失败或发生版本冲突就停止提交。现有 `submitSection` 和 `submitReport` 接口不携带版本号，存在“保存成功后、提交前被他人修改”的竞态。若产品要求严格保证提交的是用户刚核对的数据，实施前需给提交接口增加版本前置条件；仅在前端重新读取一次无法完全消除该竞态。

提交没有必填校验；已提交内容仍能编辑，修改并保存后按现有规则回到“草稿”。没有填写权限时完整显示只读数据，隐藏编辑、保存和提交操作；导入、导出按既有权限控制。

## 5. 辅助操作

“日历与历史”合并成一个底部弹层，可从日期卡片或总览底部进入。按月显示日期，草稿与已提交日期用不同色点标识；下方列出该月已保存的历史日报，点日期直接打开。没有保存记录的日期显示为“待填写”。日历提供上月、下月、回到今天，日期卡片提供前一天、后一天和今天。Excel 导入与导出保留在“更多”中，避免占用主录入区域。

导入仍须先确认“将覆盖 Excel 所属日期的整张日报”。若存在未匹配产品，展示待匹配产品清单和对应分区，逐个选择后再确认保存；不能把待匹配预览当成已保存。导出继续使用后端现有 Excel 文件，手机端交给系统文件保存/分享界面，不重新在客户端拼装表格。

视觉上使用现有移动端的浅灰蓝背景、白色卡片、蓝色主操作色和低对比度分割线；状态用文字加颜色表示，不只依靠颜色。固定操作栏留出系统安全区，字号与触控区应按实际安卓设备验收，尤其检查 360–430 dp 宽度与软键盘展开状态。

## 6. 实施与验收要点

核心读写复用现有 `GET /api/production/daily-reports/{reportDate}`、分区/表头保存、提交、产品选项、历史与 Excel 接口，数据库字段无需因排版而调整。原生页面已复用 `dt50-app/` 的登录令牌、权限和导航体系；原型文件本身不执行任何网络请求。

验收至少覆盖：四分区及全部组和固定指标都可访问；五个数值及备注在手机端可完整查看与填写；空白和 0 不混淆；长产品名、大数与六位小数不截断；产品增删排序与单晶前后指标顺序正确；切换日期/退后台/断网不丢未保存输入；多人同分区编辑出现版本冲突时不覆盖他人数据；保存后再提交、提交后再修改的状态正确；仅查看权限下无写入入口；导入待匹配与导出流程可完成。
