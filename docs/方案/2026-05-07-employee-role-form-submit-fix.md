# 员工管理表单提交修复说明

## 问题

员工管理下的用户新增、角色新增表单会把空字符串 `id: ""` 一并提交到后端。
后端员工与角色接口的 `id` 字段为 `Integer`，空字符串无法反序列化为整数，请求会在进入 Controller 前失败，表现为点击确认后无法完成提交。

## 修复

- 用户管理新增表单初始 `id` 改为 `null`。
- 角色管理新增表单初始 `id` 改为 `null`。
- 新增用户、新增角色提交时从请求体中移除 `id` 字段。
- 编辑场景继续保留已有数字 `id`，不影响更新接口。

## 追加修复

- 员工管理操作按钮兼容新旧权限码：`employee:*` 与历史 `user:*` 都可提交。
- 后端员工新增、编辑、删除接口同步兼容 `employee:*` 与历史 `user:*` 权限。
- 用户编辑、角色编辑、权限分配、角色启停、角色删除成功后，刷新当前登录用户权限缓存。
- 前端请求拦截器补充 403/500 等 HTTP 错误提示，避免操作被后端拒绝时页面没有明确反馈。

## CORS 修复

- 全局 CORS 原先只允许 `GET`、`POST`、`OPTIONS`。
- 员工编辑、角色编辑、权限分配、角色启停使用 `PUT`，角色删除使用 `DELETE`，浏览器预检会被后端拒绝为 `Invalid CORS request`。
- 已补充允许 `PUT`、`DELETE`、`PATCH`，这些管理端操作可以正常跨域提交。

## 角色管理交互补充

- 角色启用/停用前增加二次确认，避免误点直接改变角色状态。
- 分配权限抽屉增加全局“全选/清空”按钮。
- 每个权限模块标题右侧增加模块级“全选/清空”按钮。
