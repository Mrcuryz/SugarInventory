# 传统库存与二维码托盘库存写入边界

日期：2026-08-12

## 结论

传统出入库接口作为兼容通道保留，但只允许处理 `inventory.pallet_code_id IS NULL` 的无二维码库存。任何已经绑定二维码的库存必须通过托盘任务状态机执行出库、调拨或生产领料，传统接口不得更新或删除该类库存。

## 原因

历史 Web 和小程序仍调用 `/api/in-stock/add`、`/api/out-stock/out`、`/api/out-stock/transferOut` 和 `/api/out-stock/stack-out`。二维码流程同时维护 `inventory`、`pallet_code`、`pallet_task`、流转记录和库存事件。如果传统出库直接删除二维码关联的 `inventory`，会留下仍为 `INSTOCK` 的托盘和未闭合任务。

## 实施规则

1. 所有传统出库查询必须包含 `pallet_code_id IS NULL`。
2. 所有传统出库候选行必须在事务内使用 `FOR UPDATE` 锁定。
3. 栈式出库必须按请求产品过滤，不能消费同库位中的其他产品。
4. 传统出库的更新和删除语句再次校验 `pallet_code_id IS NULL`；受影响行数不是 1 时整笔事务失败。
5. 传统调拨只搬运无二维码库存，调入后仍保持无二维码兼容库存身份。
6. 找不到无二维码库存时返回明确业务提示，引导用户通过托盘任务出库，不能回退到二维码库存。

## 当前非目标

- 本次不移除历史 Web 或小程序入口。
- 本次不把传统接口注册为 Agent/MCP 写工具。
- 本次不改变二维码托盘任务的确认、取消或审计协议。

## 验收重点

- 仅有二维码库存的库位调用传统出库时应失败，且托盘、任务和库存保持不变。
- 同库位同时存在传统库存和二维码库存时，传统出库只能消费无二维码记录。
- 并发传统出库不能重复消费同一库存行。
- 栈式出库不能消费请求产品之外的库存。
