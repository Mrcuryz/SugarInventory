## 1. 已确认的第一版目标

第一版新增一套“共享填写型生产日报”：

1. 每个业务日期对应一张生产日报。
2. 有查看权限的用户可以查看整张日报。
3. 有填写权限的用户可以填写和修改整张日报，不再按车间或部门限制可编辑范围。
4. 用户及操作权限继续使用现有角色、权限和用户管理，由甲方管理员自行分配。
5. 暂时不新增车间实体、车间成员关系或专门的人员配置功能；需要表达车间归属时使用现有“部门”概念。
6. 多晶、红糖、单晶和全厂汇总仍按样表作为四个固定报表分区展示。
7. 报表所有数值均由用户手工填写，包括当日实绩、折成吨、月累计、年累计、小计、产率、单耗及全厂汇总。
8. 系统不根据生产订单、库存、产品重量或其他日报自动计算任何数值。
9. 固定指标的名称、分区和单位严格按样表，不允许用户新增、删除或改名。
10. 产品行允许新增、修改、删除和调整顺序；新增时必须选择现有产品。
11. 所有产品行单位统一为“件”，用户不可修改。
12. 没有任何产品时，页面和 Excel 中仍保留一条空产品行。
13. 不设置必填项，不设置历史修改期限。
14. 暂时不需要审核；提交后仍可继续修改。
15. “制表人”由用户手工填写。
16. 全厂汇总中的手工数据由厂长填写，但第一版不在系统内校验填写人身份，由甲方通过填写权限控制。

## 2. 当前项目分析

### 2.1 技术基础

- 后端：Java 21、Spring Boot 3.1.3、Spring Security、MyBatis-Plus。
- 前端：Vue 3、Element Plus、Pinia、Vue Router。
- 后端已经引入 Apache POI 和 `poi-ooxml`，可以直接实现服务端 Excel 导出。
- 项目已有统一 `Result<T>`、`PageResult<T>`、`BusinessException`、`ErrorCode`、`@PreAuthorize` 和 `@LogOperation` 体系。
- 前端已有权限 Store、路由权限和菜单过滤机制。

### 2.2 现有生产模块

当前生产模块包含煮糖批次、生产订单、半成品领用、产出登记与贴码、生产订单产出查询和只读生产分析报表。

这些数据尚未完全覆盖线下生产日报，因此第一版日报不读取、不汇总也不修改上述业务数据。日报是一套独立的手工登记数据。

### 2.3 现有“生产日报”相关概念

#### `production_report_record`

现有 `production_report_record` 由智能报数入库确认流程写入，保存原始文本、入库 JSON、消耗 JSON、任务 ID 和托盘码等执行留痕。该表不能满足多人共享填写、固定指标、动态产品行和 Excel 版式要求，因此不复用。

#### 只读“生产登记产出日报”

分析模块已经存在根据 `production_order_output` 生成的只读生产登记产出日报/趋势，并支持通用 XLSX 导出。

它表达“系统已经登记的生产订单产出事实”，本次功能表达“用户手工填写的公司生产日报”。两者继续独立，避免数据口径混淆。

本次新增功能代码统一命名为 `ProductionDailyReport`，现有分析报表保持原名称和实现。

### 2.4 产品与现有选择器

现有产品主数据包含产品 ID、名称、产品状态（成品/半成品）、产品类型、包装方式、单件重量和每板数量。

现有前端 `productCascader.js` 已提供“产品状态 -> 产品类型 -> 产品”的级联选项构造，生产订单页面也已有按成品/半成品选择产品的交互。

第一版复用：

- `buildProductCascaderOptions`；
- `productCascaderProps`；
- Element Plus `el-cascader`；
- 产品 ID、名称、状态和类型。

需求所说的“产品类型：成品/半成品”对应现有产品模型的 `status`，页面上显示为“产品状态”，避免与 `productType` 混淆。

产品单位统一使用“件”，页面和服务端都不接受用户修改产品单位。

### 2.5 用户、部门与权限

- 登录用户继续使用现有 `user`、`role`、`permission` 和 `role_permission`。
- 员工名册 `employee_roster` 已有自由文本 `department` 字段。
- 第一版不新增车间表、部门表或用户与车间的关联表。
- “部门”只作为日报固定分区的业务称呼；第一版不读取员工名册部门、不做用户与部门匹配，也不作为后端编辑权限条件。
- 只要拥有生产日报填写权限，用户即可填写四个分区的全部数据。

## 3. 样表结构与数据类型

### 3.1 整体结构

样表只有一个 Sheet，使用 A:T 共 20 列，左右各 10 列：

- 左侧：多晶车间和全厂汇总；
- 右上：红糖车间；
- 右下：单晶车间和说明。

页面和 Excel 均严格显示样表中的“车间”列名以及“多晶车间、红糖车间、单晶车间”文字。后端 `department_code` 仅是内部字段命名，语义上复用现有部门概念，不影响页面文案。

| 字段 | 第一版处理方式 |
|---|---|
| 车间/部门 | 固定分区，不可自由新增 |
| 项目分区 | 固定，如原料及在制品、半成品、产品、综合指标 |
| 项目/产品 | 固定指标不可改名；产品行必须选择产品 |
| 单位 | 固定指标锁定；产品行统一为“件”且不可修改 |
| 当日实绩 | 手工填写 |
| 折成吨 | 手工填写 |
| 月累计(件) | 手工填写 |
| 月累计(吨) | 手工填写 |
| 年累计(吨) | 手工填写 |
| 备注 | 手工填写 |

样表中的业务日期和制表日期不同，因此分别保存：

- `report_date`：日报业务日期；
- `prepared_date`：制表日期，由用户手工填写，允许留空；
- `prepared_by_name`：用户手工填写的制表人。

### 3.2 空值与零

- 空白表示没有填写或不适用。
- 0 表示用户明确填写为 0。
- 后端、前端和 Excel 必须保留两者差异。
- 页面初始化不能把空值自动改成 0。

### 3.3 数字不自动计算

第一版不实现产品折吨、小计、月/年累计、产率、结晶率、种子占比、单耗、全厂汇总或任何跨部门/跨日期计算。所有这些单元格都作为普通手工数值字段保存和导出。

|---|---|---|
| 多晶 | 半成品 | 半成品 |

同一产品允许出现在同一部门的不同产品分区。第一版不额外限制同一产品在同一分区重复出现；如甲方后续要求，再增加校验。

### 5.2 产品行字段

每条产品行保存产品 ID、产品名称/状态/类型快照、单位、五个手工数值、备注和行顺序。

单位规则：产品行始终保存“件”，不读取或修改产品表中的包装方式。

### 5.3 空产品行

当某个产品分区没有任何产品时：

- 页面显示一条空白产品行；
- Excel 导出保留一条空白产品行；
- 空白行仅是展示占位，不写入数据库；
- 用户填写了数量、单位或备注后，必须选择产品才能保存；
- 完全空白的占位行在保存时忽略。

### 5.4 顺序调整

产品行允许通过行尾拖拽图标调整顺序，后端保存 `display_order`，不额外引入拖拽库。

## 6. 简化权限设计

不新增车间或部门数据权限，只新增日报操作权限：

| 权限 | 用途 |
|---|---|
| `production:daily-report:view` | 查看日报详情和历史列表 |
| `production:daily-report:edit` | 新建、保存、修改和提交整张日报 |
| `production:daily-report:export` | 导出 Excel |

权限规则：

- 有 `view` 可查看四个分区完整数据；
- 有 `edit` 可编辑四个分区、制表人和任意历史日期；
- 有 `export` 可导出；
- 不检查当前用户属于哪个部门；
- 不检查当前用户是否为厂长；
- 甲方管理员通过现有角色管理页面分配以上权限。

管理员角色在迁移中默认获得三个权限；其他角色不自动授予，由甲方配置。

保存、提交和导出继续使用现有操作日志机制。日志只记录日期、分区和操作类型，不记录整张日报 JSON。

## 8. 保存、提交与并发

### 8.1 保存粒度

- 顶部“制表人”单独保存。
- 多晶、红糖、单晶、全厂汇总按分区独立保存。
- 保存一个分区时，固定指标值和产品行在一个事务中写入。
- 不做自动保存，用户点击“保存草稿”后写入。

分区独立保存可以减少多人同时编辑不同分区时的覆盖风险，同时不引入车间权限。

### 8.2 提交

- 有 `edit` 权限的用户可以提交任意分区或整张日报。
- 提交不做必填校验，允许空值。
- 提交后不锁定，仍可修改。
- 已提交分区再次修改并保存后，状态回到 DRAFT；用户可以再次提交。
- 不提供审核、退回或锁定流程。

### 8.3 历史修改

任何日期都允许新建或修改；不限制补录天数、修改次数，也不因月份或年份结束自动锁定。

### 8.4 乐观锁

虽然不限制编辑人，仍保留最低限度的并发保护：

- 顶部信息和每个分区分别携带 `version`；
- 保存时版本不一致返回 409；
- 前端提示日报已被其他用户更新，允许加载最新数据；
- 禁止最后写入者静默覆盖他人已经保存的内容。

## 9. API 设计

所有接口继续返回项目统一 `Result<T>`；历史列表返回 `Result<PageResult<VO>>`。

### 9.1 查看

| 方法 | Path | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/production/daily-reports/{reportDate}` | view | 获取某日完整日报；无记录时返回固定空模板，不写库 |
| GET | `/api/production/daily-reports` | view | 按日期和状态分页查询历史日报 |

日报专用产品接口避免要求日报用户额外获得产品管理页面权限，返回结构继续适配现有级联选择器。

### 9.3 Excel 导入与导出

| 方法 | Path | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/production/daily-reports/import` | edit | 解析 XLS/XLSX；完全匹配时直接保存，否则返回待匹配预览 |
| POST | `/api/production/daily-reports/import/confirm` | edit | 确认并事务性保存已完成产品匹配的整张日报 |
| GET | `/api/production/daily-reports/{reportDate}/export` | export | 导出某日 XLSX |

文件名：`来冰公司yyyyMMdd生产日报表.xlsx`。

导入日期取 Excel 标题中的 `yyyyMMdd`。格式、固定指标或数字解析失败时拒绝导入。产品无法唯一匹配时，后端返回包含原产品名称和错误状态的整表预览且不写数据库；用户完成选择并确认后，在一个事务中覆盖该日期的表头和四个车间分区并回到草稿状态。

## 10. 前端页面设计

### 10.1 路由与菜单

- 路由：`/production/daily-reports`
- 菜单：一级菜单“生产日报”，位于“操作日志”下方
- 页面主标题：`生产日报`
- 路由权限：`production:daily-report:view`
- 编辑和导出按钮分别检查 `edit`、`export`。

### 10.2 单页布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 生产日报 [上一日][业务日期][今日][下一日] 制表日期[____] 制表人[____]│
│ 当前状态：草稿/已提交                    [导入] [导出] [保存顶部]│
├──────────────────────────────────────────────────────────────────────┤
│ 多晶 │ 红糖 │ 单晶 │ 全厂汇总：显示保存状态和最后修改人             │
├──────────────────────────────────────────────────────────────────────┤
│ ▼ 多晶车间                                   [保存草稿] [提交]       │
│ 原料及在制品：固定指标                                               │
│ 半成品：动态产品行 [新增产品]                                        │
│ 直接成品：动态产品行 [新增产品]                                      │
│ 装包或二次加工成品：动态产品行 [新增产品]                            │
│ 综合指标：固定指标                                                   │
├──────────────────────────────────────────────────────────────────────┤
│ > 红糖车间                                                           │
├──────────────────────────────────────────────────────────────────────┤
│ > 单晶车间                                                           │
├──────────────────────────────────────────────────────────────────────┤
│ > 全厂汇总                                                           │
└──────────────────────────────────────────────────────────────────────┘
```

所有有编辑权限的用户都可以展开并修改任意分区。页面不根据当前用户部门改变默认分区、可见内容或编辑范围。

### 10.3 避免横向滚动

宽屏使用一行九列：

```text
项目 | 单位 | 当日实绩 | 折成吨 | 月累计(件) | 月累计(吨) | 年累计(吨) | 备注 | 操作
```

页面使用 CSS Grid：项目和备注为弹性列，数值列使用紧凑宽度，所有容器设置 `min-width: 0`，不设置页面级横向滚动。

较窄桌面自动变为两层：

```text
第一层：项目 / 单位 / 当日实绩 / 折成吨 / 操作
第二层：月累计(件) / 月累计(吨) / 年累计(吨) / 备注
```

### 10.4 固定指标

- 指标名和单位只读。
- 五个数值栏都按样表显示并允许手工填写；不适用时允许留空。
- 小计、综合指标、产率和单耗也使用普通输入框，不显示公式标识。
- 没有必填星号。
- 保存时只校验合法数字和字段长度，不校验业务公式。

### 10.5 产品行

- 各产品分区提供“新增产品”。
- 新增行采用行内编辑。
- 复用现有产品级联选择器。
- 产品单位统一显示为“件”，不提供单位输入框。
- 所有数值由用户填写，不展示自动折吨结果。
- 支持编辑、删除，并通过拖拽图标调整顺序。
- 删除只删除日报行，不删除产品。
- 产品为空且整行为空时作为占位行保留。

### 10.6 提交后修改

- 已提交分区仍展示输入框和编辑按钮。
- 用户修改并保存后状态变成“草稿”。
- 页面不出现管理员退回、审核通过或锁定按钮。

### 10.7 正式页面文案约束

正式页面保持简洁，只显示完成操作所必需的内容：页面标题、字段名称、数据、状态、操作按钮以及必要的校验或错误提示。

不展示说明性横幅、页面副标题、分区说明或规则解释，例如“由某人手工填写”“固定项目，不可增加或删除”“由有权限的人员共同填写”等。产品选择、固定单位和固定指标限制通过控件行为体现，不在页面重复说明。

## 11. Excel 导入与导出设计

### 11.1 数据来源

Excel 只输出数据库中保存的手工值：

- 不写 Excel 公式；
- 不在导出时重新计算；
- 不读取生产订单或库存补值；
- 空值导出为空单元格；
- 0 导出为数字 0。

### 11.2 模板处理

实施时将样表复制到项目资源目录，不能依赖开发机桌面路径：

```text
src/main/resources/templates/production-daily-report-template.xlsx
```

由于产品行数量动态变化，导出器使用 Apache POI 根据样表样式重建行、边框和合并区域。模板作为版式和样式来源，不把固定坐标当成唯一数据位置。

### 11.3 布局

- 保留 A:J、K:T 左右双区布局。
- 左侧为多晶和全厂汇总，右上为红糖，右下为单晶和说明。
- 产品行按实际数量展开。
- 没有产品时每个产品分区至少导出一条空白行。
- 小计和综合指标位置随产品行数量下移。
- 制表人使用用户保存的 `prepared_by_name`。
- 制表日期使用用户保存的 `prepared_date`；未填写时导出为空。
- 固定指标名称和单位按样表，产品单位统一为“件”。

打印设置：A4 横向，固定一页宽；动态行较少时尽量一页高，过多时允许纵向分页，不产生横向第二页。

### 11.4 固定说明

导出保留样表说明：

1. 统计产率不含翻包及二次加工成品；
2. 以上数据是根据每天生产情况汇总，不涉及最终销售的产品；
3. 糖油桶的在制品不在统计内；
4. 调拨到柳冰的糖油不在统计内。

### 11.5 导入规则

- 支持 `.xlsx` 和 `.xls`，单个文件不超过 10MB；
- 识别当前系统导出格式和项目内保存的原始双栏样表；
- 从标题读取日报日期，从表头读取制表人和制表日期；
- 固定指标按车间、分组和指标名称映射，不依赖产品行的固定行号；
- 产品按名称和成品/半成品类型与产品管理数据唯一匹配；
- 产品无法匹配或存在重名时保留原名称，产品选择框标红并显示“未找到匹配产品”；
- 待匹配状态只在页面预览，不写数据库；用户可逐行选择产品，也可取消并恢复原日报；
- 全部产品匹配后点击“保存导入”，后端在一个事务中覆盖整张日报；
- Excel 中的产品全部自动匹配时直接完成保存；页面切换到 Excel 所属日期并显示导入数据。

## 12. 与其他模块的边界

第一版生产日报：

- 不修改库存、生产订单、二维码、托盘或入出库任务；
- 不读取智能报数或生产订单产出生成默认值；
- 不与现有只读生产分析日报互相覆盖；
- 只读取产品主数据用于选择产品和默认单位。

如果产品选择器中缺少产品，甲方管理员先在现有产品管理中新增；日报不允许自由输入产品名绕过产品主数据。

## 13. 最小校验规则

第一版仅保留必要技术校验：

- 业务日期格式合法；
- 制表日期已填写时格式合法；
- 产品行一旦填写任意内容，就必须选择有效产品；
- 产品 ID 必须存在；
- 数值栏必须是可解析的十进制数或空值；
- 文本长度不能超过数据库长度；
- 乐观锁版本一致；
- 用户具有对应操作权限。

第一版不校验必填指标、数值正负、小计、折吨、累计、产率和单耗公式、用户部门、历史修改期限以及产品重复。
