# 生产管理模块二期改造方案：煮糖批次与来源追溯

## 背景

一期生产管理已经打通生产订单、半成品领用、订单码预打印、实际产出核销和入库任务。现场进一步提出：机破或筛分前的上游糖源通常以“煮糖锅数、桶数、重量”表达，一批煮糖结果可能被多个生产订单使用，也可能产出多个规格产品。

因此二期不把“煮糖锅数 -> 桶糖 -> 板/件产品”做成简单计算器，而是新增“煮糖批次”作为生产订单的上游来源台账。

## 业务口径

- 煮糖批次是生产订单的上游主数据，不是二维码库存，也不是 `production_order_material`。
- “桶”当前仅作为计量单位，不拆成独立对象；后续如现场需要单桶贴码，可在现有批次引用记录上扩展桶级明细。
- 每桶重量默认 11kg，但必须允许用户修改。
- 每批实际桶数默认 180 桶，但必须允许用户修改。
- 一个煮糖批次可以被多个生产订单引用。
- 生产订单创建后到完成前，引用量先作为预占，防止超卖。
- 生产订单完成后，预占转为正式消耗。
- 生产订单取消或删除时，未消耗的预占释放。

## 余量计算

可用剩余量以引用记录实时聚合为准：

```text
可用剩余 = 批次总量 - 已完成消耗 - 当前预占
```

当用户引用煮糖批次时，系统需要加锁校验剩余。如果不足，提示：

```text
当前剩余 xx，其中 yy 被 A订单、B订单 占用
```

引用单位由用户选择：

- 桶：默认单位，按 `数量 × 每桶重量` 折算 kg。
- kg：按 `数量 / 每桶重量` 折算桶。

## 数据模型

### production_boiling_batch

记录煮糖批次本身：

- 批次号
- 煮糖日期
- 班组 / 机组 / 人员
- 糖类或产品快照
- 锅数
- 实际桶数
- 每桶重量 kg
- 总重量 kg
- 状态：DRAFT / AVAILABLE / USED_UP / CANCELED
- 原始报数文本
- 备注

### production_boiling_batch_usage

记录生产订单对煮糖批次的引用和预占：

- 煮糖批次 ID
- 生产订单 ID / 订单号
- 引用单位：BUCKET / KG
- 用户输入数量
- 折算桶数
- 折算 kg
- 状态：RESERVED / CONSUMED / RELEASED / CANCELED
- 创建人和时间

## 状态流转

```text
煮糖批次 AVAILABLE
  -> 生产订单引用后生成 RESERVED 用量
  -> 订单完成：RESERVED -> CONSUMED
  -> 订单取消/删除：RESERVED -> RELEASED
  -> 批次无剩余：AVAILABLE -> USED_UP
```

## 页面设计

生产管理新增页面：煮糖批次。

列表按日期筛选和分组展示：

- 批次号
- 煮糖日期
- 班组
- 桶数
- 每桶重量
- 总量
- 已预占
- 已消耗
- 剩余
- 状态
- 操作

详情展示：

- 批次基础信息
- 余量摘要
- 生产订单引用记录
- 去向追溯分为两个 Tab：物料流向图、流转明细表
- 物料流向图按 nodes + edges 有向图展示煮糖批次、生产订单、实际产出、订单码/二维码、入库库位、下游领用订单及成品入库
- 流转明细表按时间展示引用、产出、入库、领用/消耗和下游成品入库记录

生产订单新建页增加“上游煮糖批次来源”：

- 选择煮糖批次
- 选择单位：桶 / kg，默认桶
- 输入本次使用量
- 展示当前剩余、本次使用后剩余

生产订单详情页增加“上游煮糖批次来源”，与二维码半成品领用并列展示。

## 与现有流程关系

煮糖批次只补齐生产订单上游来源，不改变一期主链路：

```text
煮糖批次
  -> 生产订单来源引用
  -> 生产订单预打印订单码
  -> 现场贴码
  -> 确认实际产出
  -> 生成入库任务
  -> 入库
  -> 库存和流转记录
```

`production_order_material` 继续表示已扫码领用的半成品二维码库存；煮糖批次来源用独立引用表记录。

### 去向追溯组装规则

追溯数据由现有业务关联实时查询，不新增或手工维护追溯树表：

1. production_boiling_batch_usage 取得直接引用煮糖批次的半成品生产订单。
2. production_order_output、production_order_output_code 和订单标签批次取得实际产出及二维码。
3. inventory、pallet_task、pallet_flow_record 取得真实入库库位；待入库任务的目标库位不视为已入库流向。
4. production_order_material 按 pallet_code_id + pallet_cycle_no 匹配下游领用订单，防止可复用二维码跨轮次串链。
5. 继续查询下游订单的实际产出、二维码和最终入库库位，允许同一来源分支到多个下游订单。
6. 查询不到后续数据时保留已能确认的节点和明细，不影响批次详情打开。

追溯接口返回兼容旧树字段，同时以 nodes、edges、timeline 作为新版页面的数据源。前端按边关系计算拓扑层级，不依赖固定数组顺序。

## 后续扩展

- 智能报数可解析“6.18煮”“18桶”“700kg”等文本，先生成煮糖批次草稿和订单来源建议。
- 如现场要求每桶贴码，可新增桶级明细表，并让 `production_boiling_batch_usage` 引用具体桶号。
- 去向图可进一步扩展到客户订单、销售出库和批次召回。
