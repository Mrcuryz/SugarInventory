# 生产日报产品双模式选择说明

## 背景

生产日报的产品行原先只提供“产品状态 → 产品类型 → 具体产品”三级选择器。该方式适合不清楚产品名称时按分类浏览，但在已知产品名称的日常录入场景中操作层级偏多。

本次在不移除原有选择器的前提下，增加产品名称模糊搜索，并把两种方式收纳到同一个紧凑产品选择控件中，避免挤占日报表格空间。

## 页面交互

1. 日报表格仍只显示一个产品选择单元格，已选择时显示产品名称，未选择时显示“请选择产品”。
2. 点击单元格后打开轻量弹层，顶部提供两个入口：
   - **名称搜索**：默认入口，输入产品名称后在当前日报分组允许的产品中进行本地模糊匹配；
   - **分类选择**：保留原有三级产品选择器。
3. 搜索结果同时展示产品名称、产品状态和产品类型，点击后立即回填日报行并关闭弹层。
4. 如果全量产品中存在相似产品、但其产品状态不适用于当前日报分组，提示用户切换分组或检查产品状态，不提供快捷新增，避免创建重复产品。
5. 如果全量产品中也没有搜索结果：
   - 有 `product:view` 和 `product:create` 权限时，显示“未找到‘搜索词’产品，**去新增？**”；
   - 无新增权限时，提示联系有权限的管理员。

## 快捷新增链路

点击蓝色“去新增？”后跳转到产品管理页，并携带一次性路由参数：

```text
/product?createProduct=1&productName=<搜索词>&source=production-daily-report
```

产品管理页会：

1. 自动打开“新增产品”表单；
2. 自动把搜索词填入“产品名称”；
3. 立即清理一次性路由参数，避免页面刷新或再次激活时重复弹窗；
4. 其余产品类型、状态、包装、重量、每板件数和筛网仍由用户确认，不进行推断。

生产日报页使用路由缓存，跳转到产品管理页不会主动丢弃当前内存中的日报录入内容；返回日报页时会刷新产品选项，使刚新增的产品可以被选择。正式离开前仍建议按现有流程保存日报草稿。

## 数据与接口边界

- 模糊搜索复用生产日报初始化时加载的产品选项，不新增后端接口或数据库结构；
- 日报分组的 `allowedProductStatuses` 仍是产品可选范围的唯一业务约束；
- 产品创建继续使用产品管理现有 `POST /api/products` 接口和权限校验；
- 搜索词只预填产品名称，不自动提交，不猜测其他产品字段。

## 验收要点

- 名称包含匹配、忽略输入空格；
- 名称精确/前缀匹配优先于类型或状态匹配；
- 选择搜索结果后正确回填产品 ID；
- 分类选择器仍能正常使用；
- 无结果文案和蓝色快捷新增入口正常展示；
- 快捷新增跳转参数正确，产品管理表单自动打开并预填；
- 无权限用户不能进入快捷新增；
- 不适用于当前分组的既有产品不会被误判为“未找到”。
