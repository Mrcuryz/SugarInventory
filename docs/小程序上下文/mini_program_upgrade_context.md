# 小程序升级改造上下文

## 1. 背景与目标

当前项目为**冰糖仓储管理系统**。后端已完成二维码 / 托盘码主链路改造，Web 管理端也已完成一轮较大的 UI 和功能升级。下一阶段需要对**微信小程序端**进行整体重构。

### 本轮小程序改造的核心判断
- 旧小程序的 **WXML / WXSS 基本没有保留价值**，旧版 HTML/CSS 设计思路会干扰新版升级。
- 可保留的主要是 **JS 业务层逻辑**，例如：
  - 微信登录、手机号绑定、工号绑定
  - request 封装
  - API 调用逻辑
  - 状态枚举 / 字典映射
  - 部分页面的数据组织、校验、分页、debounce 等逻辑
- 小程序**不是 Web 端的缩小版**，而是面向仓储现场“流动作业”的移动端执行工具。

### 本轮最核心的两个能力
1. **连续扫码作业**
   - 面向入库、出库、调拨等操作
   - 连续扫码
   - 扫一个码即创建一条任务
   - 任务进入页面下方“任务池 / 列表”
   - 支持统一确认、统一取消、逐条处理

2. **单码全链路查询**
   - 对单个托盘码扫码后，直接查看该码所有关键信息：
     - 当前状态
     - 产品信息
     - 位置
     - 化验数据
     - 流转记录
     - 当前任务
     - 可执行操作

---

## 2. 小程序与 Web 的职责分工

### Web 端负责
- 统筹规划
- 全局查看
- 复杂配置
- 批量管理
- 仓库平面图、库存汇总、单据中心、配置类后台能力

### 小程序端负责
- 现场扫码
- 流动作业
- 快速确认
- 快速查询
- 面向作业员的低输入、低认知负担交互

因此，小程序的设计原则应是：
- **扫码优先**
- **任务驱动**
- **单手操作**
- **现场低认知负担**
- **最少点击 / 最少输入 / 最快完成任务**

### 7.2 工作台首页
#### 页面定位
现场人员打开小程序后的工作入口页。

#### 推荐结构
顶部：
- 欢迎语
- 当前用户
- 日期 / 班次
- 今日待办数量

中间：
- 快捷作业卡片
  - 连续扫码入库
  - 连续扫码出库
  - 连续扫码调拨
  - 单码查询

下部：
- 最近扫码
- 最近任务
- 系统提示 / 公告

#### 目标
让用户打开小程序后，立刻知道下一步该做什么。

---

### 7.3 扫码作业页（最核心页面）
#### 页面定位
新小程序的主入口和最高频页面。

#### 支持模式
- 入库
- 出库
- 调拨
- 仅查询

#### 页面结构
顶部：
- 作业模式切换
- 当前模式说明

中部：
- 大号扫码按钮
- 最近一次扫码结果提示
- 成功 / 失败反馈

底部：
- 本次扫码任务池列表
- 每条任务的摘要信息
- 批量操作栏

#### 核心交互
- 扫一个码 -> 后端校验 -> 创建一条任务 -> 进入任务池
- 支持连续扫码，不要求用户每次退回上级页面
- 支持：
  - 防重复扫码
  - 同码重复扫描提示
  - 删除单条待办
  - 清空当前扫描池
  - 批量确认
  - 批量取消

#### 必须保证
- 反馈快
- 提示清晰
- 任务池状态明确
- 失败原因可理解

---

### 7.4 托盘详情页（单码总入口）
#### 页面定位
扫单个码后进入的全链路详情页。

#### 页面内容
##### 摘要区
- 托盘码
- 当前状态
- 产品名称
- 产品状态
- 生产日期

##### 位置区
- 当前库位
- 左 / 右
- 排号
- 层号

##### 化验区
- 是否有化验
- 最近化验摘要
- 查看化验详情

##### 流转区
- 绑定 / 入库 / 调拨 / 出库 / 消耗 / 取消
- 用时间线展示

##### 当前任务区
- 是否有待处理任务
- 任务类型
- 任务状态
- 创建时间

##### 底部操作区
根据当前状态动态显示，例如：
- 创建入库任务
- 确认入库
- 创建出库任务
- 创建调拨任务
- 查看流转记录
- 查看化验详情

#### 页面目标
一个页面回答：
- 这个码是什么
- 现在在哪
- 发生过什么
- 现在还能做什么

#### 页面目标

## 13. 对 Codex 的最终要求

### 本轮目标不是
- 直接美化旧页面
- 把所有旧页面逐个修补
- 继续沿用旧版 WXML / WXSS 结构

### 本轮目标是
- **以扫码为中心重建小程序骨架**
- **优先做好扫码作业页、托盘详情页、任务中心**
- **让小程序成为现场流动作业端，而不是缩小版后台**

### 开发策略建议
- **先新建，不删旧页**：新页面跑通后，再逐步替换旧入口
- **先搭公共层**：先建 api / utils / components / 样式规范
- **优先主链闭环**：扫码 -> 任务 -> 确认 -> 详情
