# 小程序视觉重构与弹层交互收口任务单

## 1. 文档目的
本文件用于给 Codex 提供下一轮小程序改造的明确目标。  
这一轮不是继续做结构微调，而是要解决两个核心问题：

1. **整体 UI 视觉升级不足，页面虽已重构结构，但仍然缺少真正的产品气质**
2. **弹层 / 表单打开时背景仍可滑动，存在明确交互缺陷**

本轮目标是：

> 把当前小程序从“结构正确的新版内部工具”，推进到“视觉更成熟、交互更稳定的现场作业产品”。

---

## 2. 当前问题判断

从最新页面结果看：

- 工作台、任务、扫码、查询、我的、托盘详情等页面，结构已经比旧版清楚很多
- 托盘详情页也已经按“摘要 + Tab + 底部操作”方向改过
- 但整体视觉语言几乎没有实质升级
- 更多还是“把旧视觉语言下的模块重新排列”

因此当前用户感受是：

> **结构变了，但 UI 没真正变。**

同时还存在一个必须立刻修复的交互问题：

> **所有表单弹层 / 模态框 / 底部面板打开时，背景页面仍然可以上下滑动。**

这属于明确 bug，不是审美问题。

---

## 3. 本轮总目标

本轮必须同时完成两件事：

### 目标 A：做一轮真正的视觉系统重构
不是“再调一点布局”，而是重建这套小程序的移动端设计系统，包括：
- 图标体系
- 卡片体系
- 按钮体系
- 状态标签体系
- Tab / segmented control
- 空态 / 加载态 / 异常态
- 弹层 / 遮罩体系
- 页面背景、阴影、圆角、间距体系

### 目标 B：收口弹层交互
无论是表单弹窗、底部操作面板、模态框、抽屉式面板，只要打开，就必须锁住背景滚动。

---

# 第一部分：视觉重构任务

## 4. 明确要求：本轮是“视觉重构”，不是“结构修修补补”

### 当前不满意点
- 页面结构虽然变清楚了，但看起来仍像普通内部小程序
- 设计语言不够统一
- 高级感不足
- 精致度不足
- 现场作业感不够强
- 产品感弱于预期

### 本轮要求
Codex 必须把注意力从“模块顺序”转移到“视觉系统”本身，不允许只继续做这些表面修改：
- 挪标题
- 加一点留白
- 改成卡片
- 调几个边距
- 分成几个 Tab

这些不够。

必须真正改到：
- 颜色
- 按钮
- 图标
- 卡片
- 标签
- 空态
- 弹层
- 分段切换器
- 页面主次视觉

---

## 5. 统一设计系统要求

## 5.1 图标体系
### 问题
当前图标虽然有替换，但整体仍然没有形成完整统一风格。

### 要求
- 全站统一线性图标
- 描边粗细一致
- 圆角风格一致
- 默认态为深灰
- 激活态为主蓝
- 不再混用旧的黑实心图标、旧 tabBar 图标、老式粗线条图标

### 作用范围
- tabBar
- 工作台快捷入口
- 查询中心模块入口
- 我的页常用入口
- 帮助中心入口
- 托盘详情页辅助图标
- 空态提示图标

### 验收标准
- 用户一眼能看出是同一套图标体系
- 不再有“有些地方很新、有些地方很旧”的割裂感

---

## 5.2 色彩语义
### 要求
全局固定语义色：

- 蓝：主操作 / 当前选中 / 主入口 / 主 CTA
- 绿：成功 / 确认 / 正常
- 橙：待处理 / 警告 / 预警
- 红：失败 / 危险 / 删除 / 作废
- 灰：禁用 / 次信息 / 占位 / 背景辅助

### 禁止
- 不同页面相同状态使用不同颜色
- 随意使用高饱和色抢视觉
- 第二阶段提示标签做得比正式内容还抢眼

### 验收标准
- 状态语义稳定
- 页面之间颜色规则一致

---

## 5.3 卡片体系
### 问题
虽然页面普遍用了卡片，但卡片只是“白底盒子”，还没有形成产品层级。

### 要求
统一卡片系统：
- 圆角
- 阴影
- 边框（如有）
- 内边距
- 模块间距
- 卡片标题字号
- 卡片说明字号
- 卡片辅助标签位置

### 目标
卡片不再只是“把内容包起来”，而是真正形成信息层级。

### 验收标准
- 首页、任务页、扫码页、查询页、我的、托盘详情页的卡片看起来属于同一套系统
- 不同重要级别卡片能看出主次

---

## 5.4 按钮体系
### 问题
当前按钮虽然可用，但整体仍缺少成品感。

### 要求
统一主按钮 / 次按钮 / 危险按钮规范：

#### 主按钮
- 实心蓝
- 统一高度
- 统一圆角
- 统一阴影和按压反馈

#### 次按钮
- 浅色背景或描边
- 视觉克制
- 不喧宾夺主

#### 危险按钮
- 仅在必要时用红
- 与主按钮拉开明显语义
- 不要随处大面积红按钮并列出现

#### 悬浮新增按钮
- 统一尺寸
- 统一阴影
- 统一离底部和右侧的安全距离
- 不能遮挡列表内容

### 验收标准
- 整个小程序按钮风格统一
- 一眼能看出主次和风险等级

---

## 5.5 状态标签体系
### 问题
当前标签能用，但仍有些偏“临时 badge”。

### 要求
统一以下标签：
- 托盘状态
- 任务状态
- 化验结论
- 第二阶段标签
- 模式标签
- 类型标签

### 样式建议
- 统一高度
- 统一内边距
- 统一圆角
- 文案不要过长
- 标签位置尽量一致

### 验收标准
- 页面间标签不会给人“像不同人做的”的感觉

---

## 5.6 Tab / segmented control 样式
### 问题
当前任务页、扫码页、托盘详情页的切换区虽然结构对了，但视觉还不够成熟。

### 要求
统一：
- 状态切换
- 类型切换
- 作业模式切换
- 托盘详情 Tab

这些切换控件必须形成一套成熟样式，不要再像普通按钮排列。

### 目标
让这些控件更像真正的 segmented control / tab bar，而不是临时按钮组。

### 验收标准
- 任务页、扫码页、托盘详情页的切换组件风格一致
- 激活态、未激活态、禁用态清楚

---

## 5.7 空态 / 加载态 / 异常态
### 问题
当前很多空态只是“空白 + 一行文案”，产品成熟度不足。

### 要求
统一至少三类状态：
1. 未开始查询 / 未开始扫描
2. 查询无结果 / 暂无数据
3. 加载失败 / 请求失败

### 设计要求
- 轻量图标
- 明确文案
- 不要大面积空白盒子
- 不要像系统报错页
- 风格与整体一致

### 验收标准
- 页面空时也显得是“设计过的”
- 用户能理解是“没查”、“没数据”还是“失败了”

---

# 第二部分：逐页视觉重构要求

## 6. 工作台
### 当前问题
- 欢迎卡模板感较强
- 快捷作业卡片主次不够明显
- 最近任务 / 最近扫码 / 系统提醒都像同级模块，缺少视觉重心

### 本轮要求
- 强化首页“主入口感”
- 让扫码相关入口成为真正的第一优先级视觉重心
- 欢迎卡更克制、更高级，不要只是普通蓝色大卡
- 最近任务和最近扫码适当弱化，不要抢主入口视觉
- 卡片图标统一换成新体系

### 目标
让工作台看起来像“现场值班台 / 作业台”，不是普通卡片集合页。

---

## 7. 任务中心
### 当前问题
- 状态与类型切换仍偏按钮化
- 任务卡片信息层级不够利落
- 单条操作与底部批量操作之间关系不够清楚

### 本轮要求
- 重做任务状态和类型切换样式，使其更像成熟的 segmented control
- 优化任务卡片的层级：
  - 托盘码
  - 产品
  - 任务类型
  - 时间
  - 状态
- 单条操作按钮和底部批量栏要形成明确区别
- 底部操作栏的禁用 / 可用态更明显
- 整体更偏“处理页”，而不是“普通列表页”

### 目标
让任务页更干练、更有执行感。

---

## 8. 扫码作业页
### 当前问题
- 主按钮虽大，但不够有“引擎感”
- 作业上下文仍偏普通统计卡
- 空任务池的空态偏弱
- 整体速度感不够强

### 本轮要求
- 强化“开始扫码”主按钮的视觉主导地位
- 本次作业上下文改成更像“本次会话面板”
- 空任务池做更强引导
- 任务池中的任务项按成功 / 重复 / 失败 / 待处理做更明确区分
- 模式切换区风格和任务页 / 托盘详情页统一
- 让页面更像“专业扫码终端”，而不是普通管理页

### 目标
把扫码页打造成整个小程序最有现场作业感的一页。

---

## 9. 查询中心
### 当前问题
- 仍有明显“升级版占位页”感
- 主查询区不够像真正的统一查询入口
- 下方第二阶段入口仍偏说明卡

### 本轮要求
- 强化托盘查询主卡
- 手输 / 扫码 / 详情入口之间关系更清晰
- 库存 / 化验 / 作业记录等入口重新设计成正式查询模块
- 第二阶段标签表达更克制
- 整体更像“查询中心”，而不是“功能跳板页”

### 目标
让查询页成为真正的统一检索入口。

---

## 10. 托盘详情页（继续视觉深化）
### 当前问题
虽然已经按新结构改了，但本质上仍然是：
- 分块后的字段页
- 视觉主次不足
- 卡片和按钮仍是旧视觉语言
- 空态处理偏弱

### 本轮要求
在已完成“摘要 + Tab + 底部操作”的基础上，继续做真正的视觉重构：

#### 顶部摘要区
- 更强首屏闭环
- 更高信息密度
- 更清楚的状态、位置、当前任务关系

#### Tab 区
- 视觉更成熟
- 激活态更明确
- 与任务页、扫码页切换控件统一

#### 基础信息 / 化验数据 / 流转记录
- 基础信息卡不要像表单字段堆叠
- 化验数据更像指标卡或移动端检验结果页
- 流转记录更像生命周期时间线，而不是普通事件列表

#### 底部固定操作栏
- 精致度提升
- 主次关系更明确
- 危险操作更克制
- 随状态动态裁剪仍需保留

### 目标
让托盘详情页真正成为“单码作业总入口”，而不是“换了结构的详情页”。

- 整体偏朴，不够精致

### 本轮要求
- 强化账号卡层级

- 常用入口更像产品设置入口
- 整体更稳、更精致，强化用户中心感
- 危险操作区更克制

### 目标

### 当前问题
- 仍偏资料页 / 文档页

### 本轮要求

- 章节摘要更短更轻
- 避免长文式堆砌
- 与整体视觉保持一致

### 目标
让帮助中心成为“可快速定位问题”的辅助页，而不是说明书容器。

# 第三部分：弹层与背景滚动问题修复

## 13. 当前 bug
所有表单弹层、模态框、底部面板、抽屉式弹出层打开时：

> **背景页面仍然可以上下滑动**

这属于明确交互问题，必须在本轮统一收口。

---

## 14. 修复目标
只要任意弹层 / 模态层处于打开状态，必须做到：

- 背景页面不可滚动
- 背景 scroll-view 不可滚动
- touchmove 不穿透到底层
- 用户不会在弹层上滑动时把底层页面带着走

---

## 15. 修复要求（双保险）

### 15.1 页面级滚动锁定
在页面中使用：

```xml
<page-meta page-style="{{ modalOpen ? 'overflow: hidden; height: 100vh;' : '' }}"></page-meta>
```

当弹层打开时：
- `overflow: hidden`
- `height: 100vh`

---

### 15.2 蒙层与弹层捕获 touchmove
所有弹层遮罩层都必须拦截触摸滑动事件：

```xml
<view wx:if="{{modalOpen}}" class="modal-mask" catchtouchmove="noop">
  <view class="modal-panel" catchtouchmove="noop">
    ...
  </view>
</view>
```

并在 JS 中提供：

```js
noop() {}
```

---

### 15.3 如果页面主体使用了 scroll-view，需同步禁用其滚动
如果底层容器是 `scroll-view`，则不能只锁页面，要同步处理：

- 弹层打开时禁用 scroll-view 的滚动
- 或隐藏 / 冻结底层可滚动容器

示意：

```xml
<scroll-view scroll-y="{{!modalOpen}}">
```

---

### 15.4 必要时采用记录 scrollTop + fixed 锁定方案
如果某些页面在真机上仍有滚动穿透，则采用最终保险方案：

1. 打开弹层前记录 scrollTop
2. 页面主容器切为 `position: fixed`
3. `top: -scrollTop`
4. 关闭弹层后恢复

---

## 16. 修复范围
本轮必须检查并统一处理以下场景：
- 所有表单弹窗
- 所有确认弹层
- 所有底部操作面板
- 所有抽屉式详情面板
- 扫码页中的操作弹层
- 托盘详情页里的表单和处理面板
- 任务页确认 / 取消相关弹层
- 查询或我的页中所有未来扩展弹层

---

## 17. 验收标准（弹层部分）
### 验收 1
弹层打开后，背景页面无法上下滑动。

### 验收 2
弹层中滑动不会带动背景滚动。

### 验收 3
scroll-view 场景下也没有滚动穿透。

### 验收 4
真机与开发者工具表现一致，不只是模拟器看起来正常。

# 第四部分：交付要求

## 18. Codex 输出时必须说明的内容
本轮完成后，输出说明必须明确写出：

1. 哪些是**结构改动**
2. 哪些是**视觉系统改动**
3. 图标、卡片、按钮、标签、Tab 是否已形成统一规则
4. 哪些页面真正被做了**视觉重构**
5. 托盘详情页除了结构外，视觉具体改了哪些
6. 弹层背景滚动问题是否已全局收口
7. 哪些问题仍然明确留到第二阶段

---

## 19. 本轮完成标准
### 视觉层面
- 不能只是“更整齐”
- 必须体现出明显的视觉升级
- 用户一眼能看出这是新版正式产品，而不是内部工具页

### 交互层面
- 弹层滚动穿透问题必须彻底解决
- 所有高频页面的操作反馈和状态表达要更成熟

---

## 20. 总结
本轮的核心不是继续加页面，而是：

> **做一轮真正的视觉重构，并把弹层交互问题彻底收口。**

目标是让当前小程序从：

**结构正确的第一阶段版本**  
升级为  
**视觉更成熟、交互更稳定、可正式试用的现场作业端产品**
