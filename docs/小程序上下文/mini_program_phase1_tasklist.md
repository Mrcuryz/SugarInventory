# 小程序升级改造：第一阶段实施任务单（P0）

## 1. 文档目的
本文件用于提供第一阶段（P0）的小程序改造任务上下文与拆解清单。  
本阶段目标不是“美化旧页面”，而是先把**新小程序骨架**立起来，确保后续所有页面都围绕“扫码驱动 + 任务闭环 + 单码详情”展开。

---

## 2. 第一阶段目标

第一阶段只做 6 件核心事情：

1. 重建小程序整体导航结构
2. 重做登录页
3. 重做工作台首页
4. 搭建公共组件与统一样式体系
5. 实现扫码作业页（连续扫码 + 任务池）
6. 实现托盘详情页与任务中心基础版

一句话总结：

> 先让小程序从“旧式管理小程序”变成“可扫码作业的新骨架”。

---

## 3. 本阶段完成后的目标状态

本阶段完成后，小程序至少应满足：

- 有新的 tabBar 结构：工作台 / 任务 / 扫码 / 查询 / 我的
- 登录页已完成新版视觉与流程统一
- 首页已经变成工作台，而不是旧宫格功能页
- 扫码页可以按模式连续扫码，并把结果加入任务池
- 任务页可以查看待处理任务并执行基础确认/取消
- 扫单个码可以进入托盘详情页
- 公共组件、样式变量、状态标签、空状态等已建立
- 旧页面可以暂时保留，但新结构已经可独立运行

---

## 4. 改造边界

### 4.1 可以保留
以下 JS 资产优先保留并改造：

- 登录鉴权逻辑
- 微信登录、手机号绑定、工号绑定
- request 封装
- token 管理
- api 请求函数
- 枚举与状态映射
- 扫码结果处理逻辑
- 部分页面的 debounce / 数据整理逻辑

### 4.2 建议直接废弃
以下内容原则上不继续复用：

- 旧页面 WXML
- 旧页面 WXSS
- 旧首页布局
- 旧管理列表结构
- 旧查询页结构
- 旧的分页式移动端交互

## 5. 新的小程序结构（第一阶段先搭骨架）

## 5.1 tabBar 目标结构
建议新的一级入口为：

- 工作台
- 任务
- 扫码
- 查询
- 我的

其中：

- “扫码”放中间主入口，视觉上最突出

- “查询”先只放占位页或基础入口，不要求本阶段全实现
- “我的”保留个人信息 / 手册 / 设置占位

## 7. 第一阶段任务拆解（按优先顺序）

---

## 任务 A：重建全局导航与路由骨架

### 目标
让小程序从旧结构切换到新结构，但不破坏旧页面可用性。

### 要做的事
1. 修改 `app.json`
2. 重建 tabBar
3. 挂上新的五个一级页面
4. 保留旧页面路由，不删除
5. 保证登录后默认进入新版工作台
6. 扫码页作为 tabBar 中间核心入口

### 验收标准
- 新 tabBar 生效
- 所有一级页可正常打开
- 不影响登录态
- 不出现页面找不到、路径冲突、样式错乱

---

## 任务 B：重做登录页

### 页面定位
正式的企业系统移动端入口页。

### 页面功能
- 一键微信登录
- 首次绑定说明
- 手机号绑定入口
- 工号绑定入口
- 登录失败提示
- 登录中 loading
- 已登录自动跳转

### UI 目标
- 彻底摆脱旧版“灰底 + 大按钮”样式
- 风格与 Web 端升级后的新版保持一致
- 更像正式产品入口，而不是临时页面

### 开发要求
- 尽量保留现有登录/绑定 JS
- 页面结构和样式重写
- 错误提示、空态、引导文案统一风格

### 验收标准
- 登录流程完整可用
- 首次绑定链路可进入
- 登录页视觉统一
- 异常提示明确
- 小屏手机显示正常

---

## 任务 C：重做工作台首页

### 页面定位
不是“功能宫格”，而是“今天做什么”的现场工作台。

### 页面结构建议
#### 顶部
- 欢迎语
- 当前用户
- 当前日期 / 班次（可先简单显示日期）
- 今日待办任务数（先接任务列表数量）

#### 中部
快捷作业入口卡片：
- 连续扫码入库
- 连续扫码出库
- 连续扫码调拨
- 单码查询

#### 下部
- 最近扫码记录（可先展示最近 3 条）
- 最近任务（最近 3 条）
- 系统提醒 / 使用提示（先静态）

### 要做的事
1. 重写首页结构
2. 去掉旧的多入口管理页思维
3. 首页只保留高频入口
4. 接基础任务计数和最近任务数据
5. 做统一卡片样式

### 验收标准
- 首页不再像旧宫格页
- 高频作业入口清晰
- 进入扫码与任务更顺手
- 信息层级清楚

## 任务 D：搭建公共组件与统一样式体系

### 目标
后续页面全部基于统一组件和样式体系搭建，避免再次出现风格割裂。

### 本阶段至少需要落地的组件
1. `page-shell`
   - 页面容器
   - 统一背景 / 内边距 / 安全区

2. `page-header`
   - 页面标题
   - 副标题（可选）
   - 返回按钮 / 右侧操作位

3. `status-tag`
   - 成功 / 警告 / 危险 / 中性状态标签

4. `empty-state`
   - 空页面统一占位
   - 支持文案 + 按钮

5. `task-card`
   - 任务摘要卡片
   - 用于任务列表与扫码池

6. `pallet-summary-card`
   - 托盘摘要卡片
   - 用于托盘详情顶部摘要

7. `bottom-action-bar`
   - 底部主操作区

8. `action-sheet`
   - 底部弹层 / 操作面板

### 样式体系要求
建议统一抽一份小程序样式变量：

- 主色
- 成功色
- 警告色
- 危险色
- 文本色
- 次级文本色
- 背景色
- 卡片圆角
- 阴影
- 间距系统

### 验收标准
- 至少首页、扫码页、任务页、托盘详情页都用到统一组件
- 不同页面风格一致
- 状态标签样式统一
- 空态不再简陋

## 任务 E：实现扫码作业页（第一版）

### 页面定位
本阶段最重要的页面。

### 页面模式
顶部用明显的模式切换，至少支持：
- 入库
- 出库
- 调拨
- 仅查询

### 页面结构
#### 1. 模式切换区
显示当前模式与说明：
- 入库：扫码后创建入库相关任务
- 出库：扫码后创建出库任务
- 调拨：扫码后创建调拨任务
- 查询：扫码后直接跳转托盘详情页

#### 2. 扫码主区
- 大号扫码按钮
- 最近一次扫码反馈
- 本次累计条数

#### 3. 本次任务池
展示本次连续扫码产生的任务：
- 托盘码
- 产品名
- 任务类型
- 当前状态
- 错误原因（如有）

支持：
- 删除单条
- 清空本次池
- 批量确认
- 批量取消

### 关键交互逻辑
#### 入库模式
- 扫一个码
- 调后端创建一条入库相关任务
- 成功后加入列表

#### 出库模式
- 扫一个码
- 调对应出库创建接口
- 成功后加入列表

#### 调拨模式
- 扫一个码
- 调对应调拨创建接口
- 成功后加入列表

#### 查询模式
- 扫一个码
- 直接进入托盘详情页

### 必须实现的基础能力
- 防止同一批次重复扫码
- 重复码明确提示
- 扫码成功 / 失败 toast
- 可删除某条失败或误扫记录
- 批量确认与批量取消先调用已有后端接口
- 本次任务池可以临时存内存，也可按需做本地缓存

### 验收标准
- 能连续扫码
- 扫一个码能创建一条任务或进入详情
- 任务池列表能正确显示
- 可批量确认 / 取消
- 错误提示明确
- 重复扫码有拦截

## 任务 F：实现托盘详情页（第一版）

### 页面定位
扫码查询模式的目标页，也是小程序的信息总入口页。

### 页面内容
#### 顶部摘要卡
- 托盘码
- 当前状态
- 产品名称
- 产品状态
- 生产日期

#### 位置卡
- 当前库位
- 左 / 右
- 排号
- 层号

#### 化验卡
- 是否有化验
- 最近化验摘要
- 查看化验详情按钮

#### 流转卡
- 展示最近几条流转记录
- 提供“查看全部”入口

#### 当前任务卡
- 当前是否有待处理任务
- 类型
- 状态
- 创建时间

#### 底部操作栏
按当前状态和接口能力动态显示，例如：
- 创建入库任务
- 创建出库任务
- 创建调拨任务
- 查看流转
- 查看化验

### 对接接口
优先使用现有：
- parse
- inventory
- assay
- flows/cycles
- flows
- tasks/list（按托盘过滤，如果已有能力）
- 相关 create / confirm 接口

### 验收标准
- 扫码进入详情成功
- 托盘主要信息完整
- 位置、化验、流转至少能展示摘要
- 能从详情继续执行操作
