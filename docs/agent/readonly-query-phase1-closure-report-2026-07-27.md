## 4. 封板期间关闭的问题

1. UAT 矩阵原称 43 项但实际只有 42 行，补入 `Q10 ASSAY_REFERENCE_DATA` 并完成真实页面验证。
2. 主模型请求中的专家清单是对象列表，旧代码错误地用字符串直接判断成员关系，可能导致 `registeredGoals` 为空；现已按专家名称过滤并增加回归测试。
3. G02 虽已获得最小只读权限，但原始审计能力名进入模型回答后被 Runtime 拦截；现已为所有 52 个工具及 Runtime 审计能力建立用户显示名称，并把结果码、错误码转换为用户语言。
4. Python 测试使用 PyYAML，但项目测试依赖未声明；现已补入 `pyproject.toml`，项目虚拟环境可独立完成全量回归。

## 5. 批判性结论与剩余风险

第一阶段可以封板，但必须区分三种“完成”：

- **产品能力完成**：43 个已登记只读目标在本地/UAT 范围达到当前验收门槛。
- **正式生产部署完成**：尚未完成；仍需同版本发布包、生产角色、密钥轮换、迁移回滚和部署演练。
- **所有自然语言都能回答**：不成立。未登记目标仍应澄清、拒绝或进入后续需求评审，不能由模型自由拼接工具。

当前主要非阻断风险是完整问答延迟。主模型单次路由 P95 已低于 4 秒，但真实页面完整链路仍常见约 10～23 秒，复杂多工具任务可能更长。业务进度事件和已校验答案增量输出改善了等待体验，但没有消除模型串行往返成本。进入报表分析阶段前，应把端到端 P50/P95、模型轮次和工具次数继续作为发布指标，而不是只看路由延迟。
