# 托盘任务 L2 预览持久化基础（2026-08-05）

## 1. 本轮结论

成品入库、成品出库和调拨共用的 `preview_task_transition` 已补齐服务端不可变预览记录。该改动解决的是“短期预览在服务重启后无法恢复和验真”，不是开放 Agent 写操作。

当前结论：

- `L2_PREVIEW_PERSISTENCE_GO`
- `PREVIEW_RESTART_RECOVERY_GO`
- `AGENT_L3_EXECUTION_NO_GO`

## 2. 数据边界

仅当业务服务返回 `READY` 且允许打开既有业务弹窗时，Controller 才写入 `agent_task_transition_preview`。`CONFLICT`、参数错误、权限不足和业务校验失败均不写入。

每条记录保存：

- 随机化、不透明、唯一的 `previewRef`；
- 当前登录用户；
- 由 Agent 委派令牌带入的受信会话标识；
- 固定第 1 版协议和三种已登记 transition 之一；
- `task:view + task:confirm` 最小权限快照；
- 排序后的托盘码实体引用；
- 完整预览响应快照；
- 业务状态摘要、规范化请求 SHA-256 和响应内容 SHA-256；
- 预览时间、5 分钟有效期和创建时间。

不保存密码、JWT、模型提示词、模型思考过程或业务写入参数。表中预留的 `revoked_at`、`consumed_at` 当前始终为空，没有状态迁移代码。

## 3. 安全校验

未来任何确认设计在读取预览前，必须复用服务端校验：

1. 引用格式有效且数据库中存在；
2. 当前用户与记录操作者一致；
3. 记录绑定 Agent 会话时，当前受信会话必须完全一致；
4. 当前用户仍同时具备 `task:view`、`task:confirm`；
5. 记录状态为 `READY` 且尚未过期；
6. 权限快照、内容哈希、状态摘要、transition、协议版本、规范化请求哈希和实体引用全部一致。

任一条件不满足都失败关闭并要求重新预览。前端和模型不可提交用户自报的会话、用户 ID、权限或哈希来覆盖服务端上下文。

## 4. 与 L3 的明确边界

本轮没有新增 MCP Tool、GoalContract、前端动作或公开 API，也没有修改现有业务任务、库存、二维码和单据数据。`previewRef` 不是 `confirmationRef`、`executionToken` 或幂等键。

不能在独立事务中先把预览标记为已消费，再调用既有业务写接口；否则业务事务失败时会产生“确认已消费但业务未完成”的不一致。未来一次性消费、幂等记录、业务写入和执行审计必须先设计统一事务与失败语义，再决定是否开放单一 L3 场景。

## 5. 迁移与验证

数据库迁移：`migrations/2026-08-05-add-agent-task-transition-preview.sql`。

自动化覆盖：

- 等价预览生成不同的不透明引用；
- `READY` 写入，`CONFLICT` 不写入；
- 只保存最小权限快照；
- 服务对象重建后仍可恢复并验真；
- 跨用户、跨 Agent 会话、权限不足、过期和内容篡改全部拒绝；
- Controller 只从已认证用户和受信请求属性传入归属信息；
- 迁移不存在执行令牌和幂等键字段。

本地隔离数据库已执行迁移，并在临时 `38082` 后端完成真实 HTTP 验收：使用当前待处理成品入库样本依次登录、查询任务和生成 `CONFIRM_FINISH_INBOUND` 预览，返回 1 条 `READY` 任务；数据库中的引用格式、最小权限快照、三类 SHA-256、未消费和未撤销状态均校验通过。验收未打开或提交业务弹窗，任务和库存数据未改变；临时服务和技术测试记录均在验收后清理。

预览记录的长期保留与清理策略尚未定义。当前 5 分钟有效期只决定能否继续使用，不等同于物理删除；在进入 L3 设计前必须结合审计留存要求补齐清理策略，不能凭空采用业务系统中不存在的保留口径。
