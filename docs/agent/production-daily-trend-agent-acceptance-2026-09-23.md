## 1. 本批实现与架构边界

- 新增 `PRODUCTION_DAILY_REPORT_ANALYSIS` Goal，归属 `analytics_expert`；复用 `run_registered_report`，定义为 `production_daily_report_analysis_v1@1`。
- 主模型选择目标，专家模型决定工具及参数，Runtime 做受控校验，Java/SQL 生成事实，模型分析结果。未新增关键词直调、自由 SQL 或写入工具。
- 当前共60个Goal、55个Java工具、1个Python进程内知识工具、8个登记报表定义。日报明细/概况继续属于生产专家；趋势及可导出分析属于分析专家。
- Python/MCP 传递车间筛选与独立 `productionDailyReport`，按白名单投影数量、折吨、覆盖和完整日期序列，剔除内部 ID、指标代码及分组键。最多31天、10个系列；不接受未来日期、化验指标/任务筛选或比较参数。
- 模型上下文保留完整后端合计与覆盖，每系列最多6个代表日点；卡片、历史及导出仍保留全部日期。模型不得从代表点求权威合计。
- 多轮追问上下文保存明确日期与车间/产品筛选；只改筛选时沿用日期，明确“全部”时由专家移除对应筛选。
- Web 独立日报分析卡：选择统计项目，独立展示数量/折吨合计，切换图表，展开每日明细和数据说明；能耗不显示折吨。缺日为“无记录”、已有行但空值为“未填报”、明确0保留0。
- 历史列表增加“生产日报分析”，旧订单报表显示“订单登记产出”；历史重开生成同类型趋势卡。导出按钮额外校验日报导出权限，后端仍是最终授权边界。
- 共用图表修复末端日期裁切，并转义 HTML 提示框中的动态文字。
- Goal/schema/工具/报表登记同步；`docs/openapi.json` 从本地实际生成文档同步本次请求、响应及日报聚合嵌套类型，仅更新相关 schemas，不覆盖其他模块。其他早期接口的全面同步不属于本批。

日报的确定性聚合、归档、导出内容及权限实现见 [B1记录](production-daily-trend-backend-2026-09-23.md)。

## 6. 发现与修复

1. **嵌套压缩丢失事实**：新日报比旧报表深一层，通用模型上下文深度限制把日点值变成截断标记。对已白名单、有限额的日报系列独立净化，保留0/null及代表点，不提高全局限制；新增31天×10系列回归。
2. **主模型路由结构失败**：首轮M01、M03出现MAIN_ROUTE/SCHEMA_INVALID根级错误。日报“多项明细”提示原先写得过宽，与只允许明细目标携带dailyReportItems的约束冲突。提示和字段描述明确其他目标必须空数组、趋势工具本身返回多系列；不放宽协议、不静默丢字段。修复后完整五轮通过，随后浏览器独立问题也通过。早期失败记录保留在`output/daily-report-trend-b2/`，不计入通过率。
3. **图表末端日期裁切**：增加边界标签对齐，最终历史重开截图日期完整。
4. **模型schema及报表枚举测试过期**：同步静态schema的完整枚举顺序和测试期望；重建wheel后全量回归通过。
