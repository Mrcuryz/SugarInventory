## 待修复与复验要求

1. **采样日期不能由“刚测”“刚出来的结果”推定。** 应区分检测时间与采样日期；缺少采样信息时问“这份样品是哪天取的？”，允许用户用“昨天”“周五”等回答。有歧义再确认，不强制填写格式化日期。
2. **产品澄清应利用已知限定词。** “袋装”应参与缩小真实候选；仍有多个袋装规格再让用户选择具体规格。录入场景使用“要给哪个产品录化验？”等语言，不显示“查询范围”，不把不可录入的大类作为下一步入口。
3. **自然语言确认必须能接到有效人工确认入口。** “就这样，帮我记上吧”不等于模型可直接执行；如果当前安全设计必须使旧预览失效，就应重新生成有效预览并展示确认按钮，不能指向失效卡片。涉及产品、日期、指标改动时继续强制重新预览和明确确认。

这些是用户体验与事实澄清问题；应沿用“模型理解→专家决策→工具调用→结果分析”的现有架构修复，不新建绕过专家的关键字写入分支、不扩大模型保存权限。

## 下一轮口语场景补测（尚未执行）

- “录个化验”“那批黄糖”：逐步引导产品、采样日期、实测指标，避免一口气索要大量字段。
- “水分零点几，应该是零点三吧”：不擅自确定存疑数值或把业务指标别名直接等同，需澄清。
- “其他没测”和“其他都是零”：保留null与0的区别；不能把缺失填为零。
- “不是昨天，是前天”“酸碱度不改”“产品换成另一种”：准确更新指定字段，保留其余已确认信息并重新判定。
- “这一组都一样”“有一个不一样”：先确认真实化验组、成员与指标适用范围，再生成组预览。
- “算了先别存”“就这样吧”“帮我记上”：分别验证取消、模糊结束、确认引导；无明确人工确认不写入。
- 保存后“刚才那条呢”、重复确认、刷新及会话到期：不重复写入、不沿用过期确认；明确告诉用户下一步。

验收判断应同时看：理解是否正确、缺失信息是否被澄清、候选是否可操作、修改是否准确、保存是否明确确认、结果是否可回查。不能仅以接口成功或一条标准输入成功代替现场使用验收。
