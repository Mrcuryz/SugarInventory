# 化验录入 D2a：共享版本写入边界

日期：2026-09-24。范围：受控保存的前置工作，不代表 Agent 已经能保存化验。未部署、未新增 MCP 写工具、未变更数据库结构或业务权限。

## 为什么先做这一步

原 `AssayServiceImpl` 的导入和修改均为“查询最新 → 版本加一 → 插入”。修改还会在插入后再次更新版本。唯一索引只能拒绝重复版本，不能使并发请求安全地分配版本。

本轮又发现 `InStockServiceImpl` 的旧化验继承分支也直接插入 `assay`。只锁 Agent 或 Web 导入无法覆盖这个入口，因此一起接入共享边界；不启用旧备料池，不改变库存流程或增加入库能力。

## 实现

- 新增内部 `AssayWriteService`，必须在调用方已开启的事务中执行，离开事务直接拒绝。不增加 REST/MCP 接口，不由模型直接调用。
- 先锁实际产品行，再通过 `FOR UPDATE` 当前读获得同产品、同采样日期的最高版本。即使事务此前已建立旧快照，也不使用快照里的旧版本分配。
- 批量导入先按产品 ID 去重、升序锁定全部产品，再逐项写入；检测值、零与未填值原样保留。
- 新记录只插入一次，沿用现有自动判定服务及判定快照字段；插入影响行数不是 1 即失败。非法版本和整型溢出拒绝。
- Web 导入、修改、旧入库化验继承共用该新增边界；删除也加入事务并获取同一产品锁。新增版本不覆盖历史记录。
- Web 修改额外验证路径记录与提交产品/日期一致，避免用一个记录地址写入另一个对象。正常 Web 编辑保留原产品和日期，不受影响。
- 空组、无法解析的成员、已失效的成员不再返回假成功；一次组导入只接受一组检测值，混合载荷拒绝，不静默忽略后续项目。

产品级锁比产品/日期级锁更粗，同一产品不同日期也串行；这是本轮不新增锁表的取舍。批量化验组的 Agent 预览及成员变化检查仍属于 D3，并未因 Web 空组修复而完成。

## 验证与证据

### 单元及预览回归

专项命令：`mvn -o -Dtest=AssayWriteServiceTest,AssayServiceWriteBoundaryTest,AssayEntry*Test test`。

首次专项 64 项通过，其中新增写入边界 19 项、既有预览 45 项。覆盖排序去重锁、输入完整性、缺产品、版本递增、空值/零、异常版本、无判定、插入失败、原子回滚异常传播、组成员异常、修改不二次更新及删除锁边界。

后端全量 `mvn -o test`：589 项，587 通过、0 失败、0 错误、2 跳过。跳过项为显式开关控制的日报 MySQL 与本轮化验 MySQL 集成测试；化验集成测试已另行开启执行并通过，不能将普通回归中的跳过记为通过。完整 XML 存放于 `output/assay-entry-write-boundary/java-regression/`。

本轮未重新打包或重启隔离服务，当前运行的页面/服务仍为上一批 D1 预览版本。以上验证针对本轮源码与测试运行，不是已部署声明。

### 本地真实 MySQL

`AssayWriteMysqlTest` 需显式设置 `ASSAY_WRITE_MYSQL_UAT=true`，且连接 URL 必须为 localhost/127.0.0.1。配置只在测试进程加载，不落盘、不输出口令。

使用一个随机命名 `UAT_ASSAY_LOCK_*` 的专属新产品。读取现有用户 ID 作为合法外键，但不修改该账号。测试直接调用内部服务和真实 Mapper，不调用库存操作；判定服务在本测试中使用固定“无标准”测试结果，所以该项不是质量标准并发验收。

| 输入/步骤 | 输出与判断 |
|---|---|
| 无外层事务直接新增 | `IllegalTransactionStateException`，不写记录 |
| 第二事务先查询专属产品当日化验 | 无记录，建立旧读取快照 |
| 第一事务新增色值 0，其余未填，暂不提交 | 得到版本 1，持有产品锁 |
| 第二事务同时新增相同产品/日期 | 在第一事务提交前不能完成；提交后得到版本 2，无重复版本 |
| 查询数据库 | 恰有版本 1、2；色值为 0，还原糖为 NULL |
| 第三次新增后故意抛异常 | 版本 3 不残留，仍只有 2 条 |
| finally 清理并回查 | 专属产品和其化验记录均为 0 条 |

结果：1 项集成测试通过，未跳过。证据：`output/assay-entry-write-boundary/mysql-concurrency.xml`。它验证真实数据库锁、当前读、Spring 事务与回滚，不等价于浏览器或模型端到端保存验收。

## 下一步

1. 保存不可变精确预览，绑定用户、会话、输入、版本、全部有效标准关联与标准内容、有效期；标准改变要求重新预览。
2. 增加独立人工确认和受控执行控制记录；控制记录与化验新增在同一事务提交，重复提交回查同一结果。
3. 执行时重新核对权限；撤权、失效、取消、旧预览、版本冲突均拒绝。执行默认关闭，不能扩大当前只读委托路径。
4. 前端确认及结果卡接入后，才进行专属本地数据的完整录入验收，再继续 D3/D4。
