# 仓管受控成品入库权限决策

日期：2026-08-13  
状态：`R&D ENGINEERING GO / PRODUCTION RELEASE NO-GO`

## 结论

研发阶段暂无真实仓管、质检或生产主管参与，因此真人岗位验收不再作为本地研发继续推进的前置条件；它仍是正式上线前必须补齐的业务验收项，自动化测试不能替代真人对职责和操作习惯的确认。

仓管角色 `WAREHOUSE_MANAGER` 获得 `agent:finish-inbound:execute`，用于已完成精确预览、由用户在受控界面明确确认的成品入库。它不获得通用 `task:confirm`：后者同时覆盖成品/半成品出库和调拨，若直接授予会造成权限扩大。

## 实际权限边界

- 可以：查询仓储事实、选择既有 `FINISH_IN + PENDING` 任务、填写入库表单、生成不可变精确预览、在受控界面确认并执行成品入库；
- 不可以：人工直接提交、确认出库、确认调拨、创建或取消通用任务、启用固定二维码、调用任意库存写接口；
- 固定二维码模式仍只完成候选选择和独立任务准备，不因本次权限决策自动获得二维码启用或任务创建权限；
- `execute_finish_inbound_task` 仍不注册为 MCP Tool，模型不能自行执行；
- `agent.finish-inbound.s3-execute-enabled` 仍默认关闭，本次角色归属不等于生产发布批准。

## 技术约束

预览允许两条合法权限路径：

1. 既有管理员人工路径：`task:view + task:confirm`；
2. 仓管受控路径：`task:view + agent:finish-inbound:execute`。

服务端把实际采用的权限路径写入预览快照，后续加载时按原快照重新校验。受控 S3 确认和执行只接受第二条路径。任务资格预览仅对 `CONFIRM_FINISH_INBOUND` 接受仓管专用权限；成品出库和调拨仍要求通用 `task:confirm`。

前端同样按权限收口：仓管只显示成品入库安全预览入口，不显示人工直接提交，也不显示出库或调拨处理按钮。后端权限校验仍是最终安全边界。

## 验收要求

研发阶段以自动化和本地隔离数据库验收为准，至少证明：

1. 仓管无需 `task:confirm` 即可完成精确预览与受控成品入库；
2. 同一账号不能预览或执行出库、调拨；
3. 快照、token、幂等、状态重检、事务和审计边界保持有效；
4. 角色迁移不修改现有账号，并且不包含其他写权限；
5. 生产功能开关保持默认关闭，MCP execute 保持未注册。

正式上线前还必须由真实仓管完成岗位 UAT，并单独批准开启生产环境功能开关。

## 本地隔离验收结果

2026-08-13 已完成以下验证：

- 数据库迁移 `45/45`，待执行 `0`；
- 仓管测试角色具有 `18` 项权限，包含 `task:view` 与 `agent:finish-inbound:execute`，不包含 `task:confirm`；
- 仓管完成一次真实受控成品入库，业务写入 `1` 次，审计事件 `3` 条，同幂等键重放成功；
- 仓管请求成品出库预览被拒绝，证明专用入库权限没有扩展到出库；
- 执行期间 MCP execute 工具调用数为 `0`，生产执行工具仍未注册；
- Java 全量测试 `447` 项、warehouse-mcp `72` 项、Web Node `92` 项及前端生产构建通过。

因此当前结论为：仓管受控成品入库在研发环境 `GO`，生产发布仍为 `NO-GO`。
