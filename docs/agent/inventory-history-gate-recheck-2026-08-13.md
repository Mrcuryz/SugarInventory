# 库存趋势可信日终门禁复核

日期：2026-08-13  
结论：`LOCAL_REPLAY_ACCEPTANCE_PASS / NATURAL_DAILY_CLOSE_GATE_BLOCKED`

## 1. 当前现场证据

- `LaibinInventoryHistory-Capture` 与 `Verify` 两个 Windows 计划任务均已注册，状态为 Ready；
- 2026-08-13 03:02 开机后，任务按 `StartWhenAvailable` 补跑；Capture 和 Verify 最近结果均为退出码 2；
- 当前 JAR 的只读 Verify 明确报告：缺少 2026-08-12 的可信日终库存快照；
- Capture 的可信窗口是北京时间 00:00～00:10。03:02 已超出窗口，代码禁止把白天当前库存伪装成前一日日终；
- 因此当前连续通过天数不能推进，也不能通过手工改表或放宽窗口伪造 7 天生产门禁。

## 2. 本地与生产结论必须拆分

本地工程/产品链路已经通过显式模拟回放验收：`inventory_level_trend_v1@1` 能生成 7 个日点、趋势图、逐日明细、历史快照和同快照 XLSX，并持续标注“本地历史回放模拟”。该证据验证算法、卡片和导出，不改变真实门禁。

自然连续 7 天可信日终属于部署运行条件，不是本地开发代码缺失。开发机夜间关机时，当前规则无法形成可信快照；这是正确的 fail-closed 行为。正式环境只有在全天运行，或使用独立于业务进程且能在 00:00～00:10 执行的可靠调度后，才能自然积累并由守恒对账解锁。

## 3. 当前判定

- 报表分析的本地开发验收：不再被“必须让开发机连续开机 7 天”阻断；
- 库存趋势生产发布：继续 `NO-GO`，直到目标环境真实连续 7 天通过；
- 不新增历史回填接口，不扩大可信窗口，不把 `entry_date` 或托盘流转记录包装成库存趋势；
- 计划任务退出码 2 应接入目标环境监控；本地关机后的补跑失败属于预期告警，不应静默忽略。

## 4. 上线后操作要求

1. 确认目标主机/调度器在北京时间 00:00～00:10 可用；
2. 每日 00:00 Capture，00:15 Verify，并保留运行证据；
3. 任何一天缺快照、对账非终态或未通过，都保持/恢复门禁阻断；
4. 连续 7 天通过后再做一次正式仓管/生产主管库存趋势 UAT，方可开放生产口径。
