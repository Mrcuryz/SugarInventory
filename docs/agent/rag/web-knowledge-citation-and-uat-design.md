# RAG-04 Web 知识引用展示与真实 UAT 设计

状态：`COMPLETED / UAT_10_OF_10_PASSED`
基线日期：2026-08-02
适用范围：来宾智能仓储 Web Agent 管理员静态知识问答
风险等级：`L0 静态知识只读`

## 1. 目标

本设计在不扩大 RAG-03C 安全响应面的前提下，让管理员可以在现有 AI 助手中：

- 阅读静态知识回答及对应的现行资料来源；
- 看懂文档标题、页码、步骤或章节定位；
- 区分正常结果、关键词降级、知识库内无证据和知识库不可用；
- 明确静态材料不能替代库存、库位、托盘、化验和生产进度等实时事实；
- 在连续追问、收起再打开、页面刷新后的新会话中继续安全使用。

本阶段不激活正式 corpus，不创建正式 `current.json`，不修改仓储 MCP、业务数据或业务写权限。

## 2. 已冻结的上游契约

RAG-03C 已将 Python 到 Java、Java 到 Web 的知识响应收口为以下安全字段：

| 场景 | Web 可见契约 | Web 不可见内容 |
| --- | --- | --- |
| 有证据 | `cardType=knowledge_evidence`、`title`、`fields` | corpus 路径、document/chunk/evidence ID、分数、向量、原始 JSON |
| 引用字段 | `label=内容/来源`、`value` | 其他未知键、检索诊断、Prompt、凭据 |
| 降级 | 回答包含固定“关键词证据/语义检索暂时降级”提示，仍有安全引用 | embedding 异常细节和堆栈 |
| 无证据 | 固定“现行知识材料中没有检索到……”回答，无引用卡片 | 把无证据解释为事实不存在 |
| 不可用 | 固定“知识库当前不可用……”安全回答，无引用卡片 | 服务异常、路径、provider 和内部错误 |

Web 不从调试事件、审计事件或客户端角色构造知识元数据。身份和最终权限继续由 Java 的当前登录用户和已校验 Agent session 决定。

## 3. 展示结构

### 3.1 知识消息状态

在现有 `AgentMessageBubble` 中增加知识状态提示，但不创建第二套消息容器：

| 状态 | 判定依据 | 页面表达 | 色调 |
| --- | --- | --- | --- |
| `SUCCEEDED` | 至少一个安全 `knowledge_evidence`，且无降级固定提示 | `现行资料` | 蓝色/中性 |
| `DEGRADED` | 有知识引用，回答包含冻结的降级提示 | `关键词检索结果`，说明语义检索暂时不可用 | 黄色提示 |
| `NO_DATA` | 无知识引用，回答包含冻结的无证据前缀 | `现行资料中未找到可核验内容` | 灰色/中性 |
| `UNAVAILABLE` | 无知识引用，回答为冻结的简短不可用文案，或包含冻结的完整不可用前缀 | `知识库暂不可用，实时业务查询不受影响` | 红色提示 |

判定只接受上游冻结文案和卡片类型的组合，不对任意模型文本做模糊分类。SSE `error.message`
可能是“知识库当前不可用。”，完整回答可能是“知识库当前不可用，请稍后重试。……”；两种安全契约均
显式列入白名单。状态提示不覆盖原回答，也不把不可用伪装成空数据。

### 3.2 引用卡片

`knowledge_evidence` 使用专用的 `knowledge_citations` 展示分支：

- 卡片标题显示上游安全标题；
- “内容”作为证据摘录，保留自然换行并允许长文本换行；
- “来源”拆分为文档标题和可读定位；
- `第 N 页`、`步骤/环节`、章节等定位原样作为业务可读标签展示；
- 卡片底部固定说明“静态现行资料，不代表实时业务状态”；
- 不提供下载、打开本地文件、复制内部标识或跳转文件系统的动作。

来源拆分仅用于排版：第一个中文逗号前作为文档标题，其余部分作为定位标签。无法安全拆分时显示完整安全来源，不猜测页码或章节。

### 3.3 前端防御性过滤

即使 Java 已白名单重建卡片，Web 仍只读取“内容”和“来源”，并拒绝展示包含以下模式的值：

- Windows/UNC/Unix 绝对路径、`file://`、`jar:`、`classpath:`；
- `documentId`、`chunkId`、`evidenceId`、`observationId` 等内部标识；
- Bearer、token、password、secret、JDBC 等凭据或连接信息；
- 以对象或数组结构出现的原始 JSON；
- 空值、对象值、数组值和超长异常值。

被拒绝的内容不回退到通用 `card.fields` 渲染，避免专用分支失效后绕过过滤。卡片没有任何安全内容或来源时不应被标记为可展示知识引用。

## 4. 权限与会话边界

- `ADMIN`、`SUPER_ADMIN`：菜单入口可见，组件 `open()` 可启动会话，Java/Python 再次校验角色；
- 其他角色：菜单入口不可见，组件 `open()` 返回，直接调用 Agent API 仍由 Java 返回权限拒绝；
- 收起助手不撤销会话，重新打开复用当前页面内会话和消息；
- 明确结束会话才撤销 session 并清理页面上下文；
- 浏览器刷新不承诺恢复已显示的历史消息。刷新后允许建立新的受信会话并重新提问，这里所称“会话恢复”是服务恢复可用，不是跨刷新持久化聊天记录；
- 若未来要求跨刷新恢复消息，应单独设计服务端安全消息历史、保留期、脱敏和撤销语义，本阶段仅预留扩展空间。

## 5. 自动化测试

新增纯函数测试，至少覆盖：

1. 识别 `knowledge_evidence`；
2. 只提取“内容”和“来源”；
3. 文档标题、页码、步骤/章节拆分；
4. 路径、JSON、内部 ID 和凭据过滤；

6. 任意普通 Agent 回答不被误识别为知识状态；
7. 无安全字段的知识卡不进入可见引用列表。

## 6. 真实浏览器 UAT

RAG-04 固定 10 个场景，均在本地/UAT 环境执行，不连接生产数据库、不执行任何业务写操作：

| 编号 | 角色 | 场景 | 通过条件 |
| --- | --- | --- | --- |
| UAT-01 | ADMIN | 登录并打开 AI 助手 | 入口可见、会话已连接 |
| UAT-02 | ADMIN | 工艺知识命中 | 回答和至少一个安全来源可读 |
| UAT-03 | ADMIN | 企业资料知识命中 | 页码或章节定位可读 |
| UAT-04 | ADMIN | 连续追问 | 仍走知识范围，不泄漏内部上下文 |
| UAT-05 | ADMIN | 无答案问题 | 明确“知识库范围内无证据”，不说事实不存在 |
| UAT-06 | ADMIN | 降级检索 | 显示关键词降级提示，已有引用仍可核验 |
| UAT-07 | ADMIN | 知识库不可用 | 明确不可用且说明实时查询不受影响，不显示堆栈 |
| UAT-08 | ADMIN | 收起再打开、刷新后重建会话 | 页面内会话可继续；刷新后可安全建立新会话 |
| UAT-09 | 非管理员 | 页面入口 | 入口不可见 |
| UAT-10 | 非管理员 | 直接请求 Agent API | Java 明确拒绝，不信任伪造角色 |

每个场景记录实际输入、可见输出摘要、引用、状态、截图或 DOM 证据、是否通过和缺陷编号。UAT 使用临时隔离的候选 corpus 指针时，必须放在工作区正式运行目录之外并在记录中标明；不得把候选版本切为正式 `ACTIVE`。

## 7. 缺陷处理与评测回灌

- 展示、权限、会话和错误语义缺陷进入 `development-log.md`；
- 检索错召回、漏召回或无答案误判进入固定检索评测集后再修复；
- 任何需要扩大 Java 安全字段的缺陷先回到 RAG-03C 设计复核，不在 Web 绕过白名单；
- 页面成功不代表 corpus 可发布，RAG-05 的原子切换、只读挂载和回滚门禁保持独立。

## 9. 长回答后台审阅与异常安全

知识回答最多包含 5 条证据，长度可能显著大于普通实时查询。Web 在发送后台审阅记录前必须按 Java
DTO 契约分别限制：

- `assistantAnswerTextSafe`：最多 10000 个 UTF-16 单元；
- `assistantAnswerSummary`：最多 1000 个 UTF-16 单元；
- 截断点不能保留未配对的高代理项；
- 审阅失败不影响已完成的用户回答。

Java 参数校验错误只返回固定“请求参数校验失败”，其他非业务异常只返回固定“服务异常，请稍后
重试”；Controller 方法签名、字段名、rejected value、路径和异常类型只允许写服务端日志，不得
进入 Web alert。RAG04-WEB-02 的真实页面复验要求长回答仍显示来源且 `alertCount=0`。
