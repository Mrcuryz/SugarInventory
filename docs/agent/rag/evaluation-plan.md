## 1. 评测分层

RAG 评测分为五层：

1. 材料解析正确性；
2. 知识块正确性；
3. 检索召回和排序；
4. Agent 路由、回答和引用；
5. 权限、更新和回滚。

任何一层失败，都不能用最终回答“看起来合理”替代。

## 2. 解析评测

### 2.1 DOCX

每份文档至少验证：

- 标题和文件名；
- 页数；
- 流程步骤数量；
- 步骤顺序；
- 分支、回用和旁路；
- 表格内容；
- CCP/CPP 标签；
- 温度、时间、压力、糖度和金属限值；
- 兼容层重复是否消除；
- 原文是否保留。

### 2.2 PDF

每页至少验证：

- 是否成功渲染；
- OCR 是否生成文本；
- 页面主题是否正确；
- 标题与正文是否归属同一板块；
- 产品卡片是否错误合并；
- 证书和荣誉文字是否与页面对应；
- 低置信度区域是否有质量标记；
- 页码引用是否正确。

## 3. 固定评测集

第一版建议建立 60～100 条问题，按以下类型覆盖。

### 3.1 精确流程

示例：

- 多晶冰糖有哪些主要工艺步骤？
- 单晶体冰糖结晶之后做什么？
- 白砂糖分装从拆包到入库经过哪些环节？

### 3.2 精确数值

示例：

- 多晶冰糖自然结晶需要多久？
- 多晶冰糖浓缩温度是多少？
- 单晶体冰糖结晶时的真空度范围是多少？
- 红糖与赤砂糖的金属探测限值是否相同？

数值题必须验证：

- 数值；
- 上下界；
- 单位；
- 所属产品；
- 所属步骤；
- 来源引用。

### 3.3 相似文档区分

示例：

- 红糖和赤砂糖分装的金属控制限值分别是多少？
- 单晶体冰糖和单晶黄冰糖的流程有什么不同？
- 黑糖在两份相关流程材料中分别出现在哪些工艺范围？

不得因文本相似而把两个文档的参数混合。

### 3.4 标题与内容冲突

示例：

- 单晶黄冰糖材料的文档内部标题是什么？
- 该文件名和内部标题是否一致？

回答必须呈现材料事实，不得替甲方解释冲突原因。

### 3.5 宣传册

示例：

- 企业宣传册主要介绍了哪些内容？
- 宣传册中有哪些产品类别？
- 宣传册是否包含销售网络介绍？

宣传册问题不能引用工艺流程图作为主要证据。

### 3.6 无答案

示例：

- 某产品今天生产了多少？
- 当前仓库还有多少库存？
- 某个批次是否合格？
- 企业明年的销售目标是多少？

前三类应路由到实时工具或说明需要实时查询；材料没有提供的信息不得编造。

### 3.7 权限

至少覆盖：

- ADMIN 可以检索；
- SUPER_ADMIN 可以检索；
- STAFF 不能检索；
- QC 不能检索；
- 未登录用户不能检索；
- 模型伪造 `allowedRoles` 无效；
- 直接提交 documentId 或 chunkId 不能绕过权限。

## 4. 评测数据格式

RAG-02 固定检索 JSONL：

```json
{
  "caseId": "eval-042",
  "category": "NUMERIC",
  "query": "多晶体冰糖自然结晶时间",
  "mode": "HYBRID",
  "role": "ADMIN",
  "expectedStatus": "SUCCEEDED",
  "expectedChunkIds": ["doc-765c02b39c75bdf3e9245d75/control/4"],
  "requiredEvidenceTerms": ["7天"],
  "topK": 5,
  "requiredRank": 3
}
```

还可声明 `expectedDocumentIds` 和 `forbiddenDocumentIds`。成功案例必须有 document 或
chunk 目标；权限案例在检索前检查 `expectedStatus`，不会通过“先召回再删除”来伪造通过。

实时查询边界示例：

```json
{
  "caseId": "RAG-BOUNDARY-001",
  "category": "LIVE_DATA_BOUNDARY",
  "question": "黄冰糖现在有多少库存？",
  "expectedRoute": "MCP_LIVE_DATA",
  "forbiddenRoutes": ["KNOWLEDGE_ONLY"],
  "requiredFacts": []
}
```

## 5. 指标与门槛

### 5.1 解析门槛

- 输入材料处理成功率：100%；
- 关键数值和单位与原文一致率：100%；
- 引用页码有效率：100%；
- 兼容层重复知识块清除率：100%；
- 无来源知识块数量：0。

### 5.2 检索门槛

- 固定评测集 Recall@5：不低于 90%；
- 精确产品和控制点问题 Recall@5：100%；
- 精确数值问题正确文档进入 Top 3：100%；
- 红糖/赤砂糖等相似文档混淆的关键错误：0；
- 非管理员召回证据数量：0。
- 单次知识检索端到端耗时 p95：不高于 3000 ms，不含最终回答模型耗时；
- 本地 lexical/vector 融合阶段 p95：不高于 300 ms。

### 5.3 回答门槛

- 有依据回答的引用覆盖率：100%；
- 关键数值回答准确率：100%；
- 静态知识与实时 MCP 路由准确率：不低于 98%；
- 无答案问题编造率：0；
- 工艺材料被用于判断当前批次合格的次数：0；
- 普通回答暴露路径、chunkId、embedding 或原始 JSON 的次数：0。

### 5.4 更新门槛

- 新版本完整评测通过；
- manifest 与索引 hash 一致；
- 新版本切换成功；
- 上一版本能够回滚；
- 切换失败不会破坏当前版本；
- corpus version 能在审计中追溯。

## 6. 自动化测试范围

### 6.1 离线处理测试

- 相同输入生成稳定 ID；
- 相同输入生成稳定 checksum；
- 兼容层重复消除；
- 数值和单位不被改写；
- 空页和 OCR 低置信度处理；
- 单文件失败时整库构建失败或进入明确阻断状态；
- manifest 计数与实际文件一致。

### 6.2 检索测试

- 关键词召回；
- 向量召回；
- 混合融合；
- domain 过滤；
- product filter；
- role filter；
- status filter；
- limit 上限；
- 无结果；
- 索引损坏和版本不匹配。

### 6.3 Agent 测试

- 知识问题交给 `knowledge_expert`；
- 实时问题不交给 `knowledge_expert`；
- `knowledge_expert` 不能调用业务 MCP 工具；
- 主 Agent 不直接读取索引；
- Evidence 进入 FactEnvelope；
- CompletionEvaluator 在缺少证据时拒绝完成；
- 最终回答包含来源；
- 工具错误不解释为材料没有记载。

### 6.4 Java 与 Web 测试

- Java 入口仅允许 ADMIN 和 SUPER_ADMIN；
- 角色上下文不可由前端覆盖；
- Web 只向管理员显示 Agent 入口；
- 非管理员直接调用 API 返回权限错误；
- 引用卡片不展示物理路径；
- 管理员真实浏览器问答；
- 刷新、连续追问和会话恢复；
- 旧 corpus version 的会话不会伪装成新版本结果。
