# Agent 四领域固定语料性能验收

验收日期：2026-08-03
环境：本地开发数据库、Java Agent Gateway、Python Agent、Warehouse MCP 运行制品
结论：80 条基线业务请求均返回；端到端性能门禁未通过；稳定前缀调整未形成跨领域稳定改善

## 1. 验收方法

固定语料位于 `evaluation/agent-performance-corpus-v1.json`，覆盖库存与库位、化验与质量、生产追溯、登记报表四个领域。每个领域 5 条真实用户问法，每条重复 4 次，共 80 个样本。

每个样本创建独立 Agent 会话，MCP 会话预热不计入消息耗时。消息仍完整执行“主模型理解 → 专家决策 → 工具调用 → 结果分析或受控事实格式化”。采样器只保存用例编号、领域、耗时、阶段次数、卡片类型和受控错误分类，不保存账号、令牌、问题正文或回答正文。

运行入口：

```powershell
$env:AGENT_BENCHMARK_USERNAME = '<本地管理员测试账号>'
$env:AGENT_BENCHMARK_PASSWORD = '<通过进程环境临时提供>'
agent-service\.venv\Scripts\python.exe scripts\run-agent-performance-sample.py `
  --repeats 4 `
  --output docs\agent\evaluation\agent-performance-sample-2026-08-03.json
```

## 2. 基线结果

| 领域 | 样本 | 返回 | 端到端 P50 | 端到端 P95 |
| --- | ---: | ---: | ---: | ---: |
| 全部 | 80 | 80 | 16.547 秒 | 39.016 秒 |
| 库存与库位 | 20 | 20 | 17.094 秒 | 57.187 秒 |
| 化验与质量 | 20 | 20 | 14.687 秒 | 38.484 秒 |
| 生产追溯 | 20 | 20 | 8.531 秒 | 26.328 秒 |
| 登记报表 | 20 | 20 | 22.812 秒 | 37.250 秒 |

全部样本的阶段 P95：

| 阶段 | P95 |
| --- | ---: |
| 主路由 | 16.844 秒 |
| 专家首次决策 | 9.515 秒 |
| 专家结果分析 | 28.359 秒 |
| Java/MCP 工具调用 | 0.267 秒 |

工具 P95 不到 0.3 秒，不能把 26～57 秒业务长尾归因于数据库或 MCP。主要长尾来自主路由和专家结果分析。超过 45 秒的样本仍只有 1～2 次工具调用；长耗时来自结构化模型调用，不是工具扇出失控。

原始安全结果见 `evaluation/agent-performance-sample-2026-08-03.json`。

## 3. 稳定前缀对照

在不删除 schema、专家规则、工具目录、会话上下文或工具观察的前提下，将稳定字段放在动态观察之前，并用相同 80 条语料重新采样。

| 领域 | 基线 P50 | 对照 P50 | 基线 P95 | 对照 P95 |
| --- | ---: | ---: | ---: | ---: |
| 全部 | 16.547 秒 | 16.844 秒 | 39.016 秒 | 37.125 秒 |
| 库存与库位 | 17.094 秒 | 17.578 秒 | 57.187 秒 | 33.438 秒 |
| 化验与质量 | 14.687 秒 | 16.844 秒 | 38.484 秒 | 24.000 秒 |
| 生产追溯 | 8.531 秒 | 9.078 秒 | 26.328 秒 | 37.390 秒 |
| 登记报表 | 22.812 秒 | 22.500 秒 | 37.250 秒 | 32.953 秒 |

整体 P95 下降约 4.8%，但 P50 上升约 1.8%，生产领域 P95 明显恶化。专家结果分析 P95 从 28.359 秒降到 20.547 秒，主路由 P95 则从 16.844 秒升到 23.016 秒。对照中还出现 1 次主路由 45 秒后返回受控 `AGENT_SERVICE_UNAVAILABLE`；它属于兼容模型端点长尾，不能证明由字段顺序直接引起，但也意味着本轮不能通过稳定性门禁。

因此，稳定前缀只作为不改变语义的请求规范化保留，不作为“性能修复完成”的证据。对照结果见 `evaluation/agent-performance-sample-stable-prefix-2026-08-03.json`。

| 门禁 | 状态 | 证据 |
| --- | --- | --- |
| 固定语料与可重复采样 | 通过 | 4 领域各 20 个冷会话样本 |
| 分阶段安全诊断 | 通过 | 只返回耗时和次数，Java 仅向管理员调试请求放行标量 |
| 业务工具性能 | 通过 | 工具调用整体 P95 0.267 秒 |
| 请求返回稳定性 | 有条件 | 基线均返回；对照出现 1 次受控模型不可用 |
| 端到端性能 | 未通过 | 整体 P95 39.016 秒，四领域均超过 15 秒目标 |

不能通过扩大超时、跳过专家、跳过结果分析或把确定性 Router 重新放回主导路径来掩盖问题。

## 5. 下一步

1. 已增加主路由、专家首次决策、专家结果分析三个阶段的独立模型配置。三项默认均复用 `AGENT_MODEL_NAME`；未确认候选模型和相同语料结果前不切换。
2. 若兼容模型端点可提供受控缓存命中与输入 token 指标，只记录数值，不记录 Prompt 或业务内容，用于区分输入体积和上游波动。
3. 保留当前首进度与受控处理步骤，长请求期间继续给用户可见反馈；不展示思维链、工具参数和内部 ID。
4. `today_operations_overview_v1` 的事实边界已明确，但它会组合多个登记事实；在确定阶段模型策略或产品明确接受当前渐进式体验前，不把它标记为性能封板功能。

### 5.1 分阶段模型实验入口

新增的可选环境变量为：

- `AGENT_MAIN_ROUTE_MODEL_NAME`：只影响主 Agent 的结构化路由；
- `AGENT_EXPERT_INITIAL_MODEL_NAME`：只影响专家首次选择工具或提出澄清；
- `AGENT_EXPERT_RESULT_MODEL_NAME`：只影响专家基于工具观察进行结果分析。

Runtime 会显式区分 `INITIAL` 与 `RESULT_ANALYSIS`，而不是根据模型名称改变流程。留空或省略任一变量时，该阶段回落到 `AGENT_MODEL_NAME`，因此当前默认行为、权限、工具边界和“模型理解 → 专家决策 → 工具调用 → 结果分析”架构均不变。

本次只完成配置接线和自动化契约验证，没有指定或切换候选模型，也没有重新解释上面的 80 条性能结果。候选模型必须使用同一固定语料、相同重复次数和同一成功判定进行 A/B；正确率、受控失败率或任一业务领域 P95 恶化时不得发布。
