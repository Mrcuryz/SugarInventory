# Agent v1 只读查询角色 UAT 矩阵

更新时间：2026-07-27
范围：43 个 GoalContract、52 个 L1 只读工具  
当前结论：第一阶段“只读查询”在本地/UAT 范围封板通过。43 个目标完成 3 轮主模型稳定性重放（129/129），52 个工具及事实门禁完成确定性回归；25 项真实页面补充验收全部正向通过，并以独立 `ADMIN`、`QC`、`STAFF` 角色账号完成权限与关键旅程补验。该结论不等同于正式生产部署放行。

## 验收口径

每个用例必须同时满足：

1. 主 Agent 正确理解用户目标并委派唯一负责专家。
2. 专家模型选择 GoalContract 允许的工具；支撑工具不能单独形成完成证据。
3. Runtime 只接受 `evidenceTools` 产生的 FactEnvelope，并由 CompletionEvaluator 判定完成、部分完成、无数据或权限拒绝。
4. 回答与卡片中的数量、状态、日期、实体名称和工具事实一致。
5. 不展示内部 ID、实体引用、工具名、`obs_*`、后端枚举、SQL/HTTP 或模型思维链。
6. 需要选择时使用受控候选卡；选择后不重复追问同一实体。
7. 记录总耗时、模型轮次、工具次数和最终状态，不把权限拒绝或工具错误解释成无数据。

状态说明：

- `自动通过`：GoalContract、工具归属、事实校验和完成门禁已有确定性测试。
- `代表性通过`：已在本地真实 Java/Python/MCP/数据库链路执行过相应用户旅程。
- `交互通过`：已在真实前端页面验证候选、卡片、排版、折叠或错误提示等交互。
- `权限边界通过`：当前测试角色无权查看数据，系统按预期拒绝且没有越权或错误降级。
- `真实角色通过`：使用独立角色账号验证 RBAC 与代表性业务旅程；其余目标由同一权限映射的自动化合同门禁覆盖。

## 封板后的执行顺序

1. 冻结 43 个 GoalContract、52 个 L1 工具、九专家归属和完成门禁；新增只读目标必须先更新注册表、稳定性语料与本矩阵。
2. 保留 129 次主模型路由重放、Python/Java/MCP 全量回归和独立角色浏览器用例作为发布前回归门禁。
3. 第一阶段只读查询只处理 P0/P1 缺陷和部署兼容问题，不再按页面模块继续扩充接口。
4. 下一阶段先定义登记式报表/分析 GoalContract、输入快照、指标口径与证据链；仍不进入 L3 写操作。
5. 正式生产部署需另行执行同版本发布包、真实生产角色、密钥轮换、数据库迁移回滚和部署演练，不能由本地封板结论替代。
