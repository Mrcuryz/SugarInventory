# 生产概况：从明细查询回到业务回答

日期：2026-09-08。只修改本地代码与验收环境，未部署、未提交或推送；不修改库存和现有账号。

## 目标与架构

“今天产量如何”“这几天生产情况怎样”应优先回答业务指标，不是已查到几条填报记录。

沿用主模型理解 → production_expert 决策 → query_production_daily_reports → 事实适配/GoalContract → 模型分析与卡片。增强原有 `PRODUCTION_DAILY_REPORT_RECORDS` 的业务结果和事实要求，不新增专家、工具或任意SQL/HTTP能力，仍为59个目标、55个Java工具。

没有明确其他来源上下文时，产量/生产概况默认根据生产日报回答，并简要注明来源。明确问订单产出或处于订单产出上下文时仍走现有订单分析。无日报数据不能静默改用订单数据，两种来源不相加。“今天整体运营情况如何”的跨域概览仍为现有独立报表，本轮没有替换其产量来源。

## 现有资产核实

- `ProductionDailyReportCatalog` 已定义全厂总产量（件）、多晶冰糖产量（吨）、全厂总耗电量/总耗汽/总耗水量、产品类别和单位。
- `ProductionDailyReportServiceImpl.validateAndBuildMetrics` 只接收所属车间允许的指标、拒绝重复指标，名称及单位取目录快照；dailyActual、convertedTons、月年累计直接保存输入。
- 产品行验证产品及允许状态，类别取目录、数量单位为件，数量和折吨分别保存；它没有自动把各产品明细重算为全厂总产量。
- 本轮只使用四张现有日报表，不读取已弃用备料池，不改变订单/领料/库存语义，不新增损耗或计划等概念。

## 后端统计规则

原只读接口 `POST /api/production/agent-read/daily-reports/query` 的输入、最多31天范围、权限 `production:daily-report:view` 不变。响应新增 overview、overviewTruncated、requestedDays。

| 类型 | 统计字段与维度 | 不允许的解释 |
|---|---|---|
| 全厂总产量 | FACTORY_SUMMARY 下 FACTORY_TOTAL_OUTPUT 的 daily_actual 与已保存 converted_tons，按指标、单位及名称快照分别累计 | 不由明细或小计反推；不能再加上车间产量 |
| 多晶冰糖产量 | POLYCRYSTAL 下 POLY_OUTPUT，同上 | 不补造红糖/单晶的同名指标，不与全厂产量相加 |
| 全厂能耗 | FACTORY_TOTAL_POWER、FACTORY_TOTAL_STEAM、FACTORY_TOTAL_WATER 的当日数量；不读取其通用折吨列 | 不计算吨均能耗、不推断原因，也不展示不适用的折吨缺失提示 |
| 产品分类数量 | 产品行按车间、类别、成品/半成品状态、单位及名称快照分组，对 daily_actual 与已保存 converted_tons 分别求和 | 不跨加工阶段相加，不把已记录分类数量称为车间/全厂完整产量 |

分类汇总始终遵循名称/车间筛选，完全独立于明细分页。没有产品名称筛选时不人为挑选某个产品；有产品筛选时不会顺带返回无关全厂总量。汇总不按产品名称逐一拆卡，具体产品仍可按名称筛选或展开明细。

SUM 保留全空为 null，不用 COALESCE 填0。另返回有效数量行数、有效折吨行数、总行数、数量实际覆盖天数、未提交车间行数及人话覆盖说明。缺行/缺天意味着已记录部分。没有任何产品记录的日期不能解释为现场产量0；即使已有行全部非空，也不能证明所有现场产品均已登记。

只累计当日值与当日已保存折吨，**不累计每天保存的月累计/年累计，不加总或平均产率，不自动做件重换算**。全厂总量优先于分类数量；不存在总量指标时说明未记录，不静默以分类数量代替。

## 有界结果与兼容

- 概况最多10组，超过则 overviewTruncated=true，引导按车间或名称缩小范围。查询至多读11组指标＋11组分类以检测截断。
- 明细最多50行、日报表头最多31日，概况10组与说明8条合计最多100个卡片字段，不提高Gateway全局上限，不裁掉用户明细。
- 概况的值直接来自后端，Python只做字段白名单适配，禁止模型根据当前页重新计算。GoalContract要求概况及请求天数事实，避免旧响应缺概况却宣称完成新能力。
- Java VO、MCP响应模型、Python适配、Web卡片一并更新。工具名称、权限、输入schema不变；不能只部署前端就宣称已具备汇总能力。
- `docs/openapi.json` 历史导出尚未同步此增量；以当前Controller/VO和本说明为准，后续发布需重新导出核对。

## 展示与话术

卡片先展示生产概况，明细默认收起。指标使用“总产量”“冰糖产量”“总耗电量”等真实业务名称；数量/折吨缺失情况紧随对应数值。日报状态和分页放在明细区域，不作为回答主角。

查询具体结晶率等非加总指标时仍返回原值明细，不生成无依据的期间平均率。日报草稿状态与无匹配结果分别表述，不能构造因果。

## 后续边界

本轮是生产概况切片，不是新增全套趋势报表。生产日报按日趋势、同比环比、ReportRun归档及日报来源导出尚需单独接入现有登记报表体系；当前不会把概况卡片伪装成可归档/导出的登记报表。下一步先对概况追问、切换范围、权限不足做稳定性回归，再扩展趋势；现有成品入库闭环继续保留，其他写入不在本轮范围。
