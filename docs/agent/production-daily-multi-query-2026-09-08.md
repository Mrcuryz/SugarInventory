## 2. 修复设计（沿用既有架构）

此前日报 GoalContract 只要求一份日报事实：取得耗电后即满足目标，Runtime 清空下一轮专家工具列表；结晶率没有得到查询。同类型卡片的去重还会保留首张、丢弃后续指标卡片。

本轮仍为“主模型理解 → 生产专家决策 → 受控工具调用 → 模型分析”：

1. 主模型在既有 `MainAgentDecisionV1` 中声明 `dailyReportItems`，表示本次必须覆盖的日报查询主题，不直接调用工具。单主题/普通概况维持空列表兼容旧链路，多主题最多 3 项，禁止空白、重复或用于其他目标。
2. 生产专家根据声明选择既有 `query_production_daily_reports`，每次一个 `itemQuery`。例如耗电与结晶率声明为“电”“结晶率”，使查询可覆盖真实名称“总耗电量”和“冰糖总电耗”，不是后台关键字路由或新增接口。
3. GoalContract 按主题及同一日期、车间、页码、页大小判断覆盖；重复主题、错误范围或错误事实不能替代缺失主题。单项无数据只完成该项，不能终止整组查询。
4. 只有全部主题取得有效结果或明确无数据后才关闭工具入口；提前 FINAL/PARTIAL 走现有有限纠正流程。最终回答需引用各主题对应观察结果。
5. 多主题保留多张业务卡片；保存各主题查询上下文，不把最后一项默认为整组上下文。用户仅说“下一页”时要求明确哪一项；实际多轮行为仍待真实验收。

工具白名单、最多 3 次调用、重试预算和模型超时均不扩张。超过 3 个独立主题需缩小范围；不得静默少查。查询覆盖完成不等于已读取全部分页，存在 `hasMore` 时仍需说明明细展示范围。率按日报原值展示，不自算平均率、累计率或预测；全厂与车间耗电不可直接相加。

涉及文件：`agent-service/app/{schemas,state_models,goal_contracts,runtime,tool_arguments,model,agents}.py`，以及 `agent-service/tests/test_production_daily_reports.py`。不引入新的 Agent 或第二套规划器。
