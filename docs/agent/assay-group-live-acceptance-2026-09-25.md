## 本轮发现及修正

1. 模型曾把“模型没有写工具”表述成“当前没有保存能力”，与页面按钮矛盾。补充组事实中的人工入口说明和既有回答校验，仍由模型有界重新分析，不重调业务工具。新单测覆盖原句、合法的“模型不能保存但用户可以”及一次重新分析。修复后真实 M01～M04 重新通过，回答明确可点击“核对并保存”。
2. 补测保存后只读查询发现 `查询…在2026-09-25的化验记录，只查询已有记录，不录入。` 连续两次失败。旧只读兜底将主模型选定的单日报告强改为历史目标；历史目标只允许记录列表，参数边界又拒绝单日列表，形成冲突。修复为：明确单日的泛称“化验记录”不再仅凭该词覆盖主模型目标；登记历史目标可查询单日列表；单日报告选错工具时返回固定、无敏感参数的纠正信息，由专家重新选择，不直接替它调用工具、不放宽写权限。真实复验结果见下节。
3. 最初验收脚本使用旧同步接口取得不了 SSE 中的 interruptId，属于脚本错误；已改成与前端相同的流式消息与续跑接口。保留其与业务问题的区别。
4. 浏览器网络故障注入产生预期请求失败控制台记录；不能把这些记录说成正常流程零错误。运行日志中的库存可信快照不足警告是独立门禁，未因本次测试绕过。
5. **已修复并完成HTTP复验，页面待补：**本地01:06:02工具审计确认B09直接调用`query_assay_records`，范围为`EXACT_PRODUCT_NAME_GROUP`、名称为`验收0924234934乙糖`，没有先调用产品解析；后端按精确名称返回0，模型又误述为“名称包含”。修复在原参数校验层拒绝普通产品问题未经确认的名称组范围，并给专家固定纠正信息，让其选择`resolve_products`解析完整名称，唯一产品绑定`CURRENT_PRODUCT`后继续。已确认名称组和用户明确要求全部规格的查询保留；“全部版本”不等于“全部规格”。补充专家和工具说明但不只依赖提示词，不新增工具、预算、权限或自动改写产品名，不为验收产品硬编码。新增测试覆盖错误计划被拒绝后由专家解析/查询，以及明确名称组与版本范围的区别。
6. 只读报告原有“未命中任何标准，已按默认标准/优先级选择参考标准”提示，容易被误解为没有配置标准。已核对`AssayStandardJudgeServiceImpl.judgeStandards`：这是存在候选标准但全部未通过的FAIL分支，可能含缺少检测值，不是NO_STANDARD。仅在Agent报告展示层将这个精确旧文案改成“本次检测未满足适用标准的全部要求，已按默认标准或优先级选取参考标准；具体未通过项见下方。”不改变后端判定、存储或历史标准快照，不改其他失败原因。新增测试覆盖单日报告/详情、NO_STANDARD和缺值原文保留。代码及打包源码已同步；尚未重启服务或完成此文案的页面复验，仍受工具审批额度限制。
