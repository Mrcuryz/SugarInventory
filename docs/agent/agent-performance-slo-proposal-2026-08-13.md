# Agent 性能 SLO 分层标准

日期：2026-08-13  
状态：`APPROVED / EFFECTIVE`  
产品确认：2026-08-13  
适用范围：库存、化验、生产、报表四领域的真实模型只读/分析问答。

## 为什么不能直接沿用 P95 15 秒

现有 80 个冷会话复测为 80/80 成功，整体 P50/P95 是 19.953/46.562 秒；工具 P95 只有 187 ms，主要长尾来自主路由、专家决策和结果分析模型阶段。用户已明确表示约 21.8 秒的实测体验可以接受，但这只能支持“典型请求约 20～22 秒可接受”，不能推出“约 46 秒的尾部请求也可接受”。

因此，旧文档中的 P95 15 秒应继续作为长期优化方向，而不应在没有产品确认的情况下被当作当前生产发布标准；反过来，也不能只看平均值或 P50 就忽略长尾。

## 正式采用三层指标

### 1. 正确性与安全硬门禁

- 固定验收语料完成率：100%；
- 事实一致性：100%，不得编造数据库不存在的指标、状态和业务关系；
- 越权/非白名单工具调用：0；
- 实时业务误路由到 RAG：0；
- 超时或失败时产生业务写入：0。

这些指标不允许用更快响应交换。

### 2. 本地/灰度可用性底线

- 首个用户可见进度事件 P95 ≤ 1.5 秒；
- 端到端 P50 ≤ 22 秒；
- 端到端 P90 ≤ 40 秒；
- 端到端 P95 ≤ 50 秒；
- 单次硬超时 ≤ 90 秒；
- Java/MCP 工具执行 P95 ≤ 1 秒。

这一层用于判断“是否足以进入有限灰度”，不是最终体验目标。P95 50 秒只是基于当前 46.562 秒长尾给出的临时上界，必须配合可见进度与取消能力，且不能据此宣称性能优化已经完成。

### 3. 下一阶段优化目标

- 端到端 P50 ≤ 18 秒；
- 端到端 P95 ≤ 35 秒；
- 任何单领域 P95 不得比已批准基线恶化 20% 以上；
- 结果分析阶段 P95 ≤ 20 秒；
- 最慢请求 ≤ 60 秒。

## 测量规则

- 使用相同固定语料、相同模型端点、独立冷会话和至少 80 个正式样本；
- 同时按领域报告 P50/P90/P95，不能只给整体平均值；
- 将主路由、专家首次决策、工具执行、结果分析分别计时；
- 记录失败和超时，禁止只统计成功样本；
- 外部模型或网络环境变化时必须标注，不能把供应端波动误判为代码优化；
- 本标准已经产品确认，自 2026-08-13 起进入正式发布 gate；后续变更必须保留同语料对照证据并重新确认。

## 当前证据状态

现有 80 个正式冷会话 80/80 成功，整体 P50/P95 为 19.953/46.562 秒，工具 P95 为 187 ms，因此仅能确认：

- 整体 P50、整体 P95 和工具 P95 满足本地/灰度底线；
- 旧的单一 P95 15 秒目标不再作为当前发布判定标准，保留为历史优化参考；
- 首个用户可见进度 P95、整体 P90、分领域 P95 回归幅度和最慢请求仍缺少同一批次的完整门禁证据；
- 在上述缺口补齐前，性能 gate 状态是 `POLICY_APPROVED / EVIDENCE_PARTIAL`，不能声明完整通过，也不能据此批准生产发布。

下一轮性能工作继续保留现有架构与安全边界，不恢复关键词 Router、不跳过专家决策或结果分析。优先做同语料的候选模型/供应端 A/B，以及结果分析提示与输出预算的受控实验；每次只改变一个变量，以正确性和事实一致性为前置门禁。
