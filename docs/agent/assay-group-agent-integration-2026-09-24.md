# 化验组录入：专家链路接入与自动化验证

日期：2026-09-24。阶段：D3c-2 代码及自动化验证。**未部署，未完成真实模型及浏览器整组保存验收，不能据此宣布化验录入整体完成。**

## 1. 本次变化

保持现有“主模型理解 → 化验专家决策 → 受控工具 → 结果分析”架构，不新增专家、工具名或业务目标。仍为 61 个 GoalContract、56 个 Java 工具。

- `ASSAY_ENTRY_PREVIEW` 同时支持一个具体产品或一个已选择的化验组。`resolve_products`、`query_assay_groups` 仅提供选择依据，只有 `preview_assay_entry` 能形成预览事实。
- `query_assay_groups` 查询真实配置，目录增加绑定当前登录用户的签名 `groupRef`。不返回原始组 ID 或产品 ID。
- 组录入中的目录查询生成候选卡。用户选择后，通过原有中断恢复机制回到同一化验专家；模型仅能使用 `CURRENT_ASSAY_GROUP`，实际引用由 Runtime 注入。
- 选择后的同一续跑不允许再次发现同类组候选，避免重复选择循环。普通“有哪些化验组”仍只读目录，不变成录入流程。
- 同一个 `preview_assay_entry` 接收产品或组二选一。组预览完整验证所有产品的日期、指标、零值/空值、版本和独立判定；缺项、重复产品、数量不符或返回其他引用均拒绝。
- 整组卡及本轮模型观察保留全部产品，不能沿用普通列表 50 条裁剪。测试覆盖 51 个产品，后端仍以既有组上限配置为准（默认 50，可配置至 200）。
- 产品子卡没有独立保存入口或矛盾的保存指引；只有整组提供人工核对入口。
- GoalContract 增加默认空的 `requiredAnyEntityTypes`，本目标要求 `PRODUCT`/`ASSAY_GROUP` 至少一类已解析；其他目标原规则不变。参数边界仍要求本次实际选择与调用身份一致，不以“存在任意实体”代替绑定校验。

## 2. 接口与权限边界

| 路径/能力 | 本次处理 | 边界 |
|---|---|---|
| POST `/api/quality/agent-read/assay-groups/query` | 返回当前用户签名组引用 | `assay:view`；不赋予保存权 |
| POST `/api/assay/entry/group/from-reference/preview` | 新增签名引用只读预览 | `assay:view AND (assay:create OR quality:test)`；允许 Agent 委托 |
| POST `/api/assay/entry/group/preview` | 保留原组 ID 预览 | 仍不允许 Agent 委托 |
| `/api/agent/sessions/{id}/assay-entry/previews/from-group` 及确认/执行/恢复 | 复用 D3b/D3c-1 人工链路 | 所有人工控制路径仍不允许 Agent 委托 |

签名检查沿用 `AgentEntityRefCodec`：用户、类型、有效期、签名绑定。产品引用不能替换组引用。引用不是确认/执行凭据，模型上下文、候选卡和事实摘要不包含实际 `groupRef`；仅用户选择的内部状态及人工操作卡携带它。

整组使用用户明确提供的同一套检测值，组内产品分别使用现有标准服务判定。没有新建业务字段，没有修改化验标准、库存或数据库结构。

## 3. 可复现验证与输入/输出

以下是脚本化模型决策和模拟工具返回的自动化用例，**不是线上模型实测记录**。组名、产品名、引用和数值均为测试夹具。

| 输入/流程 | 实际断言输出 | 判断 |
|---|---|---|
| “录入冰糖组化验，采样日期2026-09-23，色值268，pH值0” → 查询返回两个组 → 点击冰糖组 | 候选卡 → 恢复同一专家 → 同一预览工具 → 完整组预览和“尚未保存”；完成事实为 COMPLETE | 通过；COMPLETE 仅指预览目标 |
| 同流程返回 51 个产品 | 卡片和模型观察均包含 51 个产品，未被列表默认上限裁剪 | 通过 |
| “录入冰糖组化验，色值268” → 选择组 | 补问采样日期，不调用预览、不再次查组 | 通过 |
| 预览后“色值改成270，其他不变” | 不重新选组；再次预览色值270，pH仍为0，原采样日期保留 | 通过 |
| “有哪些化验组？” | 只读目录回答，没有录入候选中断和预览调用 | 通过 |
| 模型直接提供数字组 ID、签名文本、产品与组混合身份 | 参数阶段拒绝；只有 CURRENT_ASSAY_GROUP 可由 Runtime 绑定 | 通过 |
| 返回组引用/日期不一致、缺少产品、重复产品、无效版本、任一产品被改数值或缺指标 | 整组拒绝，不显示部分成功的预览 | 通过 |
| pH为0、干燥失重未填、第二个产品因缺项不合格 | 0与空分开保留；分别保留预判；“缺项不参与判定”被纠错 | 通过 |
| 保存并恢复 Agent 状态 | 已选组签名在内部状态恢复，模型仅看到符号引用及名称 | 通过 |
| 当前用户目录查询 | 只签发当前用户的真实组引用，不暴露数据库 ID | 通过 |
| 缺少任一所需权限/其他用户引用/产品引用冒充组引用 | 拒绝访问；不进入业务预览 | 通过 |
| Agent 委托尝试确认、执行、人工 from-group 或伪造预览子路径 | 拒绝；仅精确只读预览路径放行 | 通过 |
