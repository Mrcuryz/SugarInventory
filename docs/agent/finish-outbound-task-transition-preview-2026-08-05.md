## 2. 数据与业务校验

成品出库预览完全复用现有真实确认接口的前置条件，不凭空增加业务概念：

- 当前轮次任务必须为 `OUT + FINISH_OUT + PENDING`；
- 托盘必须仍为在库状态；
- 托盘产品状态必须仍为成品；
- 产品和生产日期绑定必须完整；
- 当前托盘库存记录必须仍存在；
- 任一所选托盘不满足条件时整批返回冲突，不生成可继续预览；
- 预览只读取当前库位、位置和数量，不调用 `confirmFinishOutTasks`，不扣减库存，不释放托盘。

最终确认仍由现有“批量确认成品出库”弹窗完成。该弹窗只接收托盘码和可选备注，并在提交时继续使用原权限、校验、事务和审计。

## 3. 交付面安全约束

- Runtime 将后端转换映射为受控组合：`finishOutConfirm + 成品出库`；
- 前端仅在动作和业务类型完全匹配时允许打开弹窗；未知动作或错配标签直接拒绝；
- 普通回答与卡片不展示预览签名、状态摘要、数据库 ID 或原始任务枚举；
- 出库卡片展示当前库位和当前库存数量，不展示入库预设字段；
- 直接“帮我确认出库”等写入请求仍 fail-closed，不调用预览或确认接口。
