# 化验录入 D2b：精确预览存档及状态核对

日期：2026-09-24。前置：[共享写入边界 D2a](assay-entry-write-boundary-2026-09-24.md)。

本轮完成内部服务及本地数据库验证，尚未增加 HTTP/MCP 接口或前端保存按钮，不能从助手实际保存化验。日报已完成的验收范围不变；Goal/工具仍为 61/56，未扩大委托权限。

## 本轮实现

1. 新增独立控制表 `agent_assay_entry_preview`。存储不可变规范输入、完整状态快照、精确公开预览、用户/会话归属、完整性摘要和 5 分钟有效期。未更改 `assay`、库存或既有账号。
2. 新预览在会话锁内替代该会话旧的活动预览；其他用户或会话不能接管已知引用。过期、取消、被替代、内容改变或有效期被改动的预览均拒绝。
3. 会话采用锁定读取，并重新查询数据库中的用户和角色权限；要求可使用 Agent、`assay:view` 及 `assay:create`/`quality:test`，不依赖旧 token 的权限集合，也不默认扩大仓管权限。
4. 精确预览锁定真实产品、最高化验版本、全部产品标准关联、关联的所有标准及指标。启用、禁用和未来生效关联都进入快照；当前实际参与判定的关联顺序另行保存。
5. 判定复用 `AssayStandardJudgeService` 的同一套计算方法。新增纯计算入口仅接受内部已锁定且已排序的标准对象，避免执行事务中的普通读取拿到旧快照；不让模型计算合格结论。
6. 公开预览复用原卡片投影，保留标准缺失、多标准及未填值等提示。存档只表示“待确认”，不生成执行凭据、不插入化验。

事务使用 REPEATABLE_READ。产品行锁及关联/指标范围锁使当前快照在事务内保持稳定；标准按 ID 升序获取。完整确认执行仍需复用同一事务边界并完成并发验证，不能把本轮验证理解为完整保存验收。

## 为什么不能只比较最终判定

两个标准同时关联产品时，当前采用标准可能未变、显示也仍为“合格”，但另一个标准的指标、启用状态、优先级或有效期已改变。旧预览必须重新生成，不能只看 `PASS` 或已采用的标准版本号。本轮快照纳入全部依赖，不改变既有标准选择规则。
