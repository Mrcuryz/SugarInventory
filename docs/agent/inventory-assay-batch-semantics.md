# 当前库存批次与化验语义决策

状态：`CONFIRMED_BUSINESS_RULE / IMPLEMENTATION_PENDING`

确认日期：2026-07-16

适用范围：当前库存、托盘、化验、质量标准、Agent 只读查询与后续报表分析。

## 1. 已确认的业务事实

1. `assay.sample_date` 在业务上表示产品生产日期，不表示化验录入日期或实际操作时间。
2. `product_id + production_date` 是产品批次键；在化验表中对应 `product_id + sample_date`。
3. 同一批次允许有多个化验版本。当前状态查询必须选择最新版本，版本排序固定为：
   - `version DESC`；
   - `created_at DESC`；
   - `id DESC`，仅作为最终稳定排序。
4. 产品可以先入库、后补化验；缺少化验不能阻止入库。
5. 化验更新通过新增版本完成，不覆盖旧版本。
6. 当前库存质量状态不能以 `inventory.assay_id`、`pallet_code.assay_id` 或任务中的 `assay_id` 作为唯一事实来源。这些字段可以保留用于历史追溯、兼容和诊断。

## 2. 当前库存批次日期

目标只读模型统一输出 `batchProductionDate` 和 `batchDateSource`：

| 库存类型 | `batchProductionDate` 来源 | `batchDateSource` |
| --- | --- | --- |
| 上线后的合法当前库存 | `pallet_code.production_date` | `PALLET_PRODUCTION_DATE` |
| 缺少托盘或托盘生产日期 | 空 | `INVALID_CURRENT_INVENTORY_BATCH` |

业务已确认上线时会清除旧库存数据，因此目标模型不再为非托盘历史库存设计 `inventory.entry_date` 回退。上线后的当前库存应满足“一板一码”，生产日期只取 `pallet_code.production_date`；`inventory.entry_date` 保持入库日期语义，不参与批次化验匹配。

但清空旧数据本身不能保证未来没有非托盘库存。上线门禁必须同时满足：

- 清除或迁移旧当前库存；
- 禁用仍可绕过托盘的旧入库入口，或在 Service/数据库增加不可绕过的约束；
- `inventory.pallet_code_id`、托盘 `product_id` 和 `production_date` 在创建当前库存时均有效；
- 上线前检查当前库存中缺托盘、缺生产日期和产品不一致的记录数均为 0。

如果托盘 `production_date` 与库存 `entry_date` 不一致：

- 这不再自动视为批次冲突，因为两个字段分别表示生产日期和入库日期；
- 当前批次匹配只使用托盘 `production_date`；
- 不得改用旧 `assay_id` 掩盖冲突；
- 如果业务流程要求同日入库，应由独立业务规则校验，不能混入化验批次规则。

## 3. 当前有效化验

“当前有效化验”定义为：

```text
latest assay
where assay.product_id = inventory.product_id
  and assay.sample_date = batchProductionDate
order by version desc, created_at desc, id desc
limit 1
```

建议后端形成一个统一的只读事实模型 `inventory_current_assay_fact_v1`，至少返回：

- 库存范围：产品、库位、托盘、板/件、重量；
- 批次范围：`batchProductionDate`、`batchDateSource`；
- 化验范围：是否存在、化验版本、创建时间、7 项原始指标；
- 判定范围：`judgeResult`、`qualifiedStandards`、`failedMetrics`、`standardSnapshot`；
- 证据范围：`assayResolutionSource=PRODUCT_AND_PRODUCTION_DATE_LATEST`；
- 数据质量警告：批次日期冲突、产品不一致、化验版本异常。

第一版可以用固定 SQL、数据库视图或专用 Mapper 实现，不需要建设任意 SQL 或通用查询平台。所有当前库存质量查询必须复用同一模型。

## 4. `assay_id` 的边界

| 使用场景 | 是否可以使用显式 `assay_id` |
| --- | --- |
| 当前库存是否有化验、是否合格 | 否，必须按批次键解析最新版本 |
| 当前托盘的质量状态 | 否，必须按产品和生产日期解析最新版本 |
| 某次历史入库、出库、流转当时关联的报告 | 可以 |
| 用户下钻查看一份已经选定的历史报告 | 可以使用受控 `reportRef`，不向模型暴露内部 ID |
| 数据迁移、旧关联诊断 | 可以，但不得作为面向用户的当前结论 |

只读 GET 查询不应为了“补关联”隐式修改库存、托盘或任务。若未来需要同步缓存字段，应使用独立、可审计、可重放的后台同步任务。

## 5. 两类用户查询

### 5.1 A：符合某个化验标准

默认含义是：当前库存批次的最新化验，在该化验版本生成时保存的判定结果中，命中了用户指定标准。

- 后端的已保存判定和标准快照是事实来源；LLM 不重新计算合格性。
- 一个标准只有在其所有受约束指标都通过时才算命中。
- 任意一个受约束指标不达标或缺失，该标准即不命中。
- 命中任意一个标准，化验兼容结论为合格；没有命中任何标准为 `FAIL`。
- `NO_STANDARD`、`MULTIPLE_CANDIDATES` 和 `FAIL` 必须分别返回，不能都翻译成“不合格”。
- 标准名称可以作为用户输入，但后端应先解析到受控标准引用；标准版本不明确且存在多版本时，应返回歧义，不得由模型猜测。

当前 `qualified_standards` 主要保存标准名称，`applied_standard_*` 只保存最终采用的一个标准。若要稳定支持“指定标准代码 + 指定版本”以及多命中标准查询，需要补充结构化的命中标准快照，至少包含 `standardCode`、`standardName`、`version`。在补齐前，版本级结论必须标记能力限制。

如果用户明确要求“拿历史化验按当前标准重新判断”，这是新的 L2 只读预览能力，不属于当前库存既有判定，也不能覆盖原化验记录。

### 5.2 B：某个原始指标满足数值条件

查询当前库存批次最新化验的原始指标，后端只允许以下受控字段：

- `colorValue`
- `reducingSugar`
- `dryWeight`
- `conductivityAsh`
- `sucrose`
- `insolubleImpurity`
- `phValue`

第一版运算符只允许 `GT`、`GTE`、`LT`、`LTE`、`EQ`、`BETWEEN`，最多 3 个条件，并仅支持 `AND`。参数必须是数值，不接受列名、SQL 片段、表达式或单位换算公式。缺失指标默认不命中，同时单独统计 `missingMetricCount`。

## 6. Agent 工具目标

两个用户意图共享同一个后端事实模型，但保留两个工具，避免形成一个难理解的万能工具：

### `query_inventory_by_quality_standard`

- 风险：L1。
- 输入：产品范围、库位范围、生产日期范围、标准受控引用、分页/分组。
- 输出：匹配库存、批次日期、最新化验版本、命中标准快照、数量和数据质量警告。
- 不支持：按当前标准重算历史化验、修改标准、修改化验、修改库存。

### `query_inventory_by_assay_metrics`

- 风险：L1。
- 输入：产品范围、库位范围、生产日期范围、1 至 3 个白名单指标条件、分页/分组。
- 输出：匹配库存、批次日期、最新化验版本、命中的原始指标、数量和数据质量警告。
- 不支持：任意 SQL、模型生成公式、自动质量判定、趋势归因。

“不合格库存”“缺化验库存”和上述两个工具也必须读取相同事实模型：

- 不合格库存：最新化验 `judgeResult=FAIL`；
- 缺化验库存：批次键没有任何化验版本；
- 无标准：最新化验 `judgeResult=NO_STANDARD`；
- 化验更新后，所有当前查询应立即读取新版本，不依赖回填 `assay_id`。

## 8. 必须通过的验收样例

1. 库存先创建，随后补录 v1 化验：无需更新库存即可从“缺化验”变为对应判定。
2. v1 合格、v2 不合格：所有当前库存和托盘查询统一显示 v2 不合格。
3. v1 不合格、v2 合格：所有当前查询统一显示 v2 合格。
4. 同产品两个生产日期：化验不得跨日期匹配。
5. 产品在日期范围内有其他批次化验：不能掩盖当前库存批次缺化验。
6. 显式旧 `assay_id` 指向 v1、批次已有 v2：当前状态取 v2，历史事件仍可下钻 v1。
7. 托盘生产日期与库存入库日期不一致：按托盘生产日期匹配并返回警告。
8. 指标为空：数值条件不命中，并统计为缺失指标。
9. 标准存在多个版本：未指定版本时返回受控歧义，不自动选择。
10. A 和 B 查询返回的化验版本、批次日期与“不合格/缺化验”查询保持一致。
