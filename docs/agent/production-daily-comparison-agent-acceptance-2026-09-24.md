## 1. 实现范围

- 沿用 `PRODUCTION_DAILY_REPORT_ANALYSIS` → `analytics_expert` → `run_registered_report` → `production_daily_report_analysis_v1@1`。主模型识别目标，专家模型选择工具，后端计算，模型分析。没有新增专家、工具、业务表、权限或报表版本。
- Python 开放 `PREVIOUS_PERIOD` 与 `CUSTOM` 参数。自定义比较须等长、不重叠、非未来，每期最多31天；车间/产品筛选两期一致。运行时另核对响应日期、比较模式及自定义基期是否与实际调用一致。
- 日报适配器保留最多40项比较指标，不沿用其他报表的12项截断；校验有限数值、比较日期、基期及空值约束。内部系列键和代码不展示给用户。
- 本期无系列但对比期有记录时保留对比卡，不能把整个报告判为两期无数据。两期均空仍展示比较范围及无数据说明，不填0。
- REPORT 上下文保存比较模式及基期，支持改变车间/产品后继续比较；取消比较后清除旧比较条件。
- 复用 Web 公共比较区，展示本期值、对比值、后端差额/变化率、独立数量/折吨覆盖及比较说明。历史重建使用白名单投影，保留完整比较；旧无比较快照继续可读。
- 日报来源始终为已保存日报，包含草稿。原订单报表、运营报表的业务口径未修改，不把订单产出叠加到日报。

后端计算规则见 [C1记录](production-daily-comparison-backend-2026-09-23.md)。

## 5. 首轮问题及修复复验

首轮目录 `output/daily-report-comparison-c2/` 虽结构18/18，不直接判通过：

1. 模型把两期都描述为含未提交记录：后端比较说明分别给出本期/对比期已保存行数和未提交行数，专家指令要求分别引用。
2. 产品筛选后分类仍叫“直接成品”，模型错误称没有黄冰糖：明确产品筛选与分类标签的关系，禁止用标签缺少产品名推断无数据。
3. 已有日报行但数值空被写成无日报记录，并出现无关分页措辞：补充空值与记录存在的区分，分析报表不引导分页。
4. 历史比较需限制展示字段：新增白名单映射，剔除内部标识，保留40项指标。

完成修复、打包并重启本轮隔离Java/Python后重跑3轮，复测证据使用独立目录，不覆盖初次失败样本。
