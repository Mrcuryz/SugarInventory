# 成品入库任务正式 L2 预览实现与验收（2026-08-04）

## 1. 结论

在既有 `L2_UI_HANDOFF_GO` 基线上，成品入库待处理任务已经接入第一个正式、版本化、无业务写入的 L2 预览工具：

`主模型理解 → logistics_expert 决策 → preview_task_transition → 安全事实适配 → 结果分析 → 既有业务弹窗`

本切片只回答“用户选中的这些成品入库任务，现在是否仍可进入业务表单继续核对”。它不会确认任务、生成库存、改变二维码、创建单据或提交成品入库。

当前结论：`L2_PREVIEW_LOCAL_UAT_GO / AGENT_L3_EXECUTION_NO_GO / PRODUCTION_NOT_RELEASED`。

这里的 `GO` 只表示本地正式 L2 预览合同、权限、前端交接和无写入验收通过，不代表生产发布，也不代表 Agent 已获得确认入库等 L3 写权限。

## 2. 用户流程

1. 用户先说“处理当前入库任务”等自然语言。
2. 主模型委派物流专家，物流专家调用 L1 `query_pallet_tasks` 查询 `PENDING` 任务。
3. 任务卡按类型分组；成品入库组的按钮明确显示“预览所选”。
4. 用户选择 1～20 条成品入库任务后，前端发送一条用户可见请求：`请预览以下成品入库待处理任务：...`。
5. 该请求重新经过主模型和物流专家，不由前端直接调用预览接口。
6. 专家调用固定第 1 版 `preview_task_transition`；Runtime 和 Java 分别执行 schema、专家白名单、当前用户和业务状态校验。
7. 全部任务仍可处理时，返回“可继续”卡片；用户可打开既有“批量确认成品入库”弹窗。
8. 任一任务不存在或状态已变化时，整批返回“需要重新选择”，不提供打开弹窗按钮。
9. 最终提交仍在既有业务弹窗中完成，弹窗重新读取任务并沿用原接口权限、校验、事务和审计。

其他入库、出库和调拨任务类型暂时保持原 UI 安全跳转，不伪装成已经完成正式 L2 预览。

## 3. 受控合同

### 3.1 工具输入

| 字段 | 约束 |
|---|---|
| `previewVersion` | 固定为 `1` |
| `transition` | 固定为 `CONFIRM_FINISH_INBOUND` |
| `palletCodes` | 用户已经明确选择的托盘码；去重后 1～20 条；只允许大写字母、数字和连字符 |

工具不接受任务 ID、产品 ID、库位 ID、任意操作名、任意接口地址或任意写入参数。

### 3.2 权限与当前事实

- Controller 同时要求 `task:view` 和 `task:confirm`。
- 用户身份只来自当前已认证 `LoginUser`，前端不能覆盖。
- Java 固定重新查询当前轮次的 `FINISH_IN + PENDING` 任务。
- 所选托盘必须全部命中；不允许部分成功后继续处理剩余项。
- 预览最多 5 分钟，业务弹窗打开和最终提交仍需再次读取当前状态。

### 3.3 输出和安全适配

内部工具结果可包含预览状态、状态摘要和短期签名引用，用于协议完整性和后续演进。普通用户回答与业务卡片只保留：

- 用户可读的“可继续 / 需要重新选择”；
- 托盘码、产品、生产日期、重量、预设位置；
- 数量是否受生产登记约束；
- 进入业务弹窗后仍需确认的字段；
- 状态冲突、重新检查和无写入说明。

普通界面和模型可见安全事实不得包含签名引用、状态摘要、原始 `PENDING`、内部任务 ID、数据库 ID、`previewRef` 或 `executionToken` 等实现词。

## 4. 并发与版本边界

现有 `pallet_task` 业务模型没有可直接复用的行版本号或统一 `updated_at`。第 1 版预览因此对当前任务的内部标识、托盘码、任务类型、状态和创建时间生成 SHA-256 状态摘要，并用当前用户、摘要和过期时间生成 HMAC 签名引用。

必须明确：

- 该摘要是第 1 版无写入预览的状态快照标识，不等同于数据库行锁或乐观锁版本；
- 签名引用不会返回普通用户，也不是 `executionToken`；
- 当前没有 `execute_*` 工具读取或消费该引用；
- 预览与业务弹窗之间仍可能发生状态变化，所以弹窗和最终提交必须重新读取并校验；
- 在正式设计 L3 execute 之前，必须补充可消费的确认令牌、执行时状态重检、幂等键和完整审计，不能直接复用本引用冒充执行授权。

## 5. 实现范围

- Java 新增正式 L2 DTO/VO、只读聚合接口、状态摘要和短期签名引用。
- warehouse-mcp 新增闭合 schema 的 `preview_task_transition` ToolCallback。
- Java Internal Gateway 和 Python `logistics_expert` 只给物流专家增加该工具。
- Python 新增 `FINISH_INBOUND_TASK_TRANSITION_PREVIEW` GoalContract、FactEnvelope、CompletionEvaluator、安全适配和确定性卡片。
- 前端成品入库任务组改为“预览所选”，成功预览后才可打开原业务弹窗。
- 工具注册表更新为 53 个无业务写入工具：52 个 L1 只读/登记报表工具和 1 个 L2 预览工具。

验收环境为新构建的本地 `5173 → 8080 → 8091`，全过程只查看、预览和取消，没有点击业务弹窗的提交按钮。

|---|---|---|
| 查询待处理任务 | `查看当前待处理任务` | 返回 6 条任务，其中成品入库 4 条、出库 2 条；按类型分组，成品入库组显示“选择任务后预览” |
| 正向正式预览 | 选择 `BT0019N1`，点击“预览所选 1 条” | 产生可见用户请求 `请预览以下成品入库待处理任务：BT0019N1`；完整经过 6 个受控阶段，返回“可继续”正式预览卡 |
| 既有弹窗交接 | 点击预览卡入口 | 打开“批量确认成品入库”弹窗，托盘、产品、库位、日期、侧、单位、数量和备注字段正确；随后点击取消，未提交 |

| 用户界面泄漏检查 | 检查对话可见文本 | 未出现 `previewRef`、`executionToken`、`stateDigest` 或原始 `PENDING`；预览有效期显示为用户可读时间 |

浏览器控制台没有业务错误，仅有 1 条不影响流程的警告。

### 7.1 验收期间发现并修复的问题

首次正向预览在 ADMIN 已具备 `task:view` 和 `task:confirm` 的情况下仍被权限边界拒绝。根因不是数据库角色或业务接口权限，而是新建的只读 POST 预览路径遗漏在 Agent 委托令牌的精确 `READ_ONLY_POST_PATHS` 白名单中，导致请求在 Controller 之前被 403 拒绝。

修复方式是只登记固定路径 `/api/logistics/agent-read/pallet-tasks/transition/preview`，并补充委托令牌回归测试。没有放宽角色权限、委托 scope 或任意 POST 能力。修复后重新构建并完成上述正向、冲突、越级拒绝和无写入复核。

## 8. 下一步

成品入库样板已经完成本地验收，可以按同一合同分别评估成品出库和调拨预览。不得先抽象成万能任务转换工具；每种 transition 必须先确认真实业务字段、权限、现有表单和提交接口。生产发布需另行完成部署环境验证；L3 execute 继续保持阻断。
