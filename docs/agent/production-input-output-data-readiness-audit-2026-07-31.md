# 生产投入—产出数据成熟度审计

审计日期：2026-07-31
审计切片：`V2A-DATA-04-PRODUCTION-INPUT-OUTPUT-READINESS`
范围：生产订单、成品领料、煮糖批次引用、登记产出、产出二维码、实际入库去向和本地开发库固定数据
不在范围：良率、损耗率、返工率、成本、计划达成率、预测和任何业务写操作

## 1. 结论

本轮结论不是“投入产出报表已经可以无条件发布”，而是分层放行：

| 能力 | 结论 | 说明 |
| --- | --- | --- |
| 稳定登记产出独立序列 | 可用 | 仅统计 `BOUND`、`PART_INBOUND`、`INSTOCK`；`DRAFT` 和 `CANCELED` 不计入 |
| 成品订单确认领用扣减独立序列 | 有条件可用 | `production_order_material` 保存确认领用时数量、件数、重量和产品快照；同一事务完成出库、库存删除和流水登记，必须同时展示订单覆盖率 |
| 旧备料池与消耗留档 | 不进入现行统计 | `semi_prepare_pool*`、`production_consumption_record` 属于已停用流程；旧写入口已拒绝，前端已转向生产订单领用 |
| 半成品订单煮糖批次投入 | 仅订单归属视图可用 | `CONSUMED` 可证明订单最终确认使用，但没有真实投料发生时间，不能生成准确的日历事件序列 |
| 订单维度投入—产出并列比较 | 有条件可用 | 只能并列展示实际领料与稳定登记产出，不计算良率和损耗 |
| 历史产出入库去向趋势 | 暂不放行 | 旧记录依赖 180 天清理的托盘流转；新库存事件尚缺稳定的产出码轮次关联 |
| 良率、损耗率和“同日产出/同日投入” | 不在当前系统范围 | 当前数据库没有对应业务事实；领料和产出日历序列也不是同一时间口径，禁止相除 |

因此，下一份可实施报表应使用“生产领料—登记产出趋势”这类准确名称，而不是把领料直接称为“消耗”，更不能输出良率。用户说“生产消耗—产出趋势”时，Agent 应明确当前可提供的是已登记领料和产出事实。

## 2. 权威来源与业务语义

### 2.1 成品生产订单投入

权威来源为 `production_order_material`：

- 记录由实际领料入口创建，并与库存扣减处于同一事务；
- 保存订单、托盘及轮次、产品、生产日期、板/件、折算总件数、单件重量、总重量和 `picked_at` 快照；
- 当前写入链路创建的状态为 `PICKED`，代码中没有后续改为 `CONSUMED` 或 `RETURNED` 的实现；
- 因而首版可称为“已确认生产领用扣减”或“已确认生产投入”；它证明仓库库存已经扣减，但不提供独立的现场投料时间。

日历流量视图使用 `picked_at`；订单归属视图使用 `production_order_id` 与订单生产日期。当前系统没有领料撤销或冲销接口，报表不得虚构相应数量。

`production_order_material.status` 虽然在初始建表注释中预留了 `CONSUMED/RETURNED`，但当前
Controller/Service 写入链路只产生 `PICKED`，本地 8 条记录也全部为 `PICKED`。登记报表因此只
允许查询 `PICKED`；预留但不可达的枚举值不构成现行业务事实。

### 2.2 半成品生产订单投入

权威来源为 `production_boiling_batch_usage`：

- `RESERVED` 只表示预留，不计为投入；
- `RELEASED` 和 `CANCELED` 不计为投入；
- `CONSUMED` 表示订单完成入库闭环时确认使用，可进入订单归属视图；
- 当前 `CONSUMED` 的更新时间是订单全部产出入库后的确认时间，不是现场投料时间。

因此，首版不能把 `updated_at` 当作实际投料事件时间。若未来要提供按日投料趋势，需要新增真实投料确认事件及业务时间。

### 2.3 已停用备料池流程

`semi_prepare_pool`、`semi_prepare_pool_balance`、`production_consumption_record` 和相关 DTO/Mapper 仍保留在代码与数据库中，但不能据此判断它们仍是现行业务来源：

- `/semi/prepare/create`、`/semi/prepare/confirm`、`/semi/consume/confirm` 的 Service 入口统一调用 `rejectLegacyProductionFlowWrite()`；
- 前端 `createSemiPrepareTasks`、`confirmSemiPrepareTasks` 直接拒绝，并提示改用生产订单领用；
- 智能报数确认当前只留档识别提示，要求在生产订单中确认实际领用二维码；
- 旧余额表仍可能被兼容代码维护，但这些写入不代表当前生产人员使用旧备料池流程。

因此，Agent、MCP 和报表不得读取旧备料池余额或 `production_consumption_record` 作为现行生产消耗。现行权威事实为生产订单确认领用事务生成的 `production_order_material`、`out_stock` 与库存流水。

### 2.4 登记产出

权威来源为 `production_order_output`：

- `DRAFT` 仍可编辑或删除，不是稳定事实；
- `BOUND`、`PART_INBOUND`、`INSTOCK` 已越过草稿阶段，作为稳定登记产出；
- `CANCELED` 不计入；
- 业务日期使用 `production_date`，记录时间使用 `created_at` / `updated_at`；
- 二维码绑定数和入库数是后续流程进度，不重复计为产出数量。

本轮已把既有生产日报从“只排除取消”修正为显式白名单 `BOUND / PART_INBOUND / INSTOCK`，避免草稿造成产量虚增。

### 2.5 实际入库去向

实际去向必须以已完成入库为前提：

- 当前库存只能回答“现在在哪里”，库存出库或移动后不能继续承担历史去向证据；
- `pallet_flow_record` 能覆盖本地旧样本，但旧轮次超过 180 天会清理；
- 2026-07-29 新增的 `stock_movement_event` 可长期保存入库目标库位，但旧产出码没有事件，且事件暂未保存托盘轮次或直接产出码引用。

在补齐 `pallet_code_id + pallet_cycle_no` 或稳定的 `output_code_ref` 关联前，不把该事件表用于长期产出去向趋势。

## 3. 本地数据核验

数据来自用户指定的本地开发库，只执行只读 SQL；这些结果用于验证实现与固定样本，不代表生产环境覆盖率。

### 3.1 规模与状态

| 数据 | 结果 |
| --- | ---: |
| 生产订单 | 19 |
| 煮糖批次 | 2 |
| 煮糖批次使用记录 | 3 |
| 实际领料行 | 8 |
| 产出行 | 13 |
| 产出二维码 | 23 |
| 实际领料 | `PICKED` 8 行，6,840 kg |
| 煮糖使用 | `CONSUMED` 1 行 1,656.8 kg；`RESERVED` 1 行 327 kg；`RELEASED` 1 行 330 kg |
| 产出 | `BOUND` 2 行 2,750 kg；`INSTOCK` 9 行 17,515 kg；`CANCELED` 2 行 11,300 kg |

### 3.2 守恒和唯一性

- 11 条有效产出中，二维码总数、已绑定数、已入库数与产出码明细均无差异；
- 11 条有效产出的折算总件数与产出码折算明细均无差异；
- 领料行未发现非法件数、重量、每板件数、单件重量、领料时间或单位；
- 未发现同一托盘轮次在有效领料中的重复使用；
- 未发现同一托盘轮次在有效产出码中的重复绑定。

这些结果支持事实序列聚合，但不替代上线后的持续数据质量门禁。

### 3.3 订单覆盖率

| 订单类型 | 已完成订单 | 有实际投入 | 有稳定产出 |
| --- | ---: | ---: | ---: |
| 成品生产 | 8 | 3 | 8 |
| 半成品生产 | 1 | 1 | 1 |

成品已完成订单的实际领料覆盖率仅为 `3 / 8`。这 5 个缺口来自本地历史/固定数据，不应由 Agent 推断或补零。首版若查询命中这些订单，必须返回：

- 已完成订单数；
- 有投入事实的订单数；
- 缺投入事实的订单数和订单号；
- `partial = true`；
- 投入合计只覆盖有事实的订单，不能描述成全部订单总投入。

### 3.4 跨日和去向覆盖

19 个已入库产出码中：

- 6 个实际入库日与产出业务日期不同，证明生产日期、登记时间和入库时间必须分开；
- 2 个当前库存行已不存在，证明当前库存不能作为历史去向账；
- 19 个仍能在托盘流转中找到入库事件；
- 19 个都没有对应的新库存事件账记录，因为这些样本早于统一库存事件底座。

不能用历史回填或任务目标库位假装实际去向。上线后数据应从真实写入链路自然积累。

## 4. 首版数据集边界

建议下一切片定义 `production_input_output_flow_v1`，但只包含事实，不包含率：

### 4.1 日历流量视图

- 成品实际领料：按 `production_order_material.picked_at` 的北京时间自然日聚合；
- 稳定登记产出：按 `production_order_output.production_date` 聚合；
- 两条序列并列展示，明确它们不是同一批订单的同期分子和分母；
- 半成品煮糖投入因缺少投料时间，不进入日历投入序列。

### 4.2 订单归属视图

- 按生产订单聚合实际领料或 `CONSUMED` 煮糖使用；
- 按同一订单聚合稳定登记产出；
- 展示订单类型、生产日期、订单状态、投入来源、投入重量、产出重量和完整性状态；
- 未完成订单标记为“进行中”，缺投入或缺产出标记为“数据不完整”；
- 不计算投入产出率、损耗率或差额业务含义。

### 4.3 必须返回的数据质量字段

- `completedOrderCount`
- `ordersWithInputCount`
- `ordersMissingInputCount`
- `ordersWithStableOutputCount`
- `ordersMissingOutputCount`
- `draftOutputExcludedCount`
- `canceledOutputExcludedCount`
- `rowsMissingWeight`
- `rowsMissingConversion`
- `crossDayInboundCount`
- `partial`
- `limitations`

## 5. 发布门禁

首版事实趋势需同时满足：

1. 产出仅使用稳定状态白名单；
2. 所有时间字段明确区分业务日期、领料时间、登记时间和入库时间；
3. 范围、产品和订单筛选由受控参数决定，不让模型生成 SQL；
4. 缺投入、缺产出、缺重量和缺换算均可计数并在卡片展示；
5. 固定数据覆盖正常、空数据、跨日、进行中、缺投入、草稿排除和取消排除；
6. Agent 继续遵守“模型理解 → 专家决策 → 工具调用 → 结果分析”；
7. 同一 `ReportRun` 保存快照并复用现有 XLSX 导出；
8. 不输出任何良率、损耗、因果或预测结论。

当前不设置“达到某个覆盖率即可计算良率”的门槛。即使领料覆盖达到 100%，现有数据库仍没有支撑良率或损耗率的完整事实，这些指标保持不实现，而不是等待业务方补一个百分比口径。

## 6. 本轮改动与下一步

本轮已完成：

- 生产订单、领料、煮糖使用、产出、二维码和去向链路审计；
- 本地固定数据完整性、唯一性、跨日和覆盖率核验；
- 修复生产日报错误包含 `DRAFT` 的风险；
- 增加 Mapper 合同测试，锁定稳定状态白名单；
- 维持 `production_yield_rate` 阻断，不新增写操作。

下一切片建议按顺序执行：

1. 实现只读 `production_input_output_flow_v1@1` 数据集、报表定义和数据质量摘要；
2. 先开放日历独立序列和订单归属并列视图，不开放比例；
3. 复用 `run_registered_report`、`ReportRun` 和同快照 XLSX，不新增报表专用 MCP 工具；
4. 增加 `PRODUCTION_INPUT_OUTPUT_TREND` GoalContract，由生产专家完成“模型理解 → 专家决策 → 工具调用 → 结果分析”；
5. 完成生产主管真实浏览器验收后，再评估产出码与长期入库事件的稳定关联。
