# 库存每日守恒对账与趋势发布门禁实施记录

日期：2026-07-30
实施切片：`V2A-DATA-03-INVENTORY-DAILY-RECONCILIATION`
结论：对账能力已实现并通过本地回归；库存趋势报表仍保持阻断。

## 1. 本轮目标

本轮不直接新增库存趋势报表，也不把当前库存或入库日期分布包装成历史趋势。本轮只回答两个数据可信度问题：

1. 每个自然日是否满足“期初库存 + 当日净事件 = 期末库存”；
2. 在连续若干天均通过守恒对账前，系统是否能阻止库存趋势能力被提前发布。

这是一项内部技术记账和质量门禁能力，不是 Agent/MCP 写操作，也不修改库存、生产、化验等业务事实。

## 2. 新增数据结构

迁移文件：`migrations/2026-07-30-add-inventory-daily-reconciliation.sql`

| 表 | 用途 |
|---|---|
| `inventory_reconciliation_run` | 保存每日对账批次、快照版本、规则版本和总体状态 |
| `inventory_reconciliation_result` | 保存产品全局、产品仓库两个维度的数量和重量守恒结果 |

## 3. 对账口径

业务日期使用北京时间自然日，日终快照由次日 00:00 生成。

数量和重量分别使用以下公式：

```text
期望期末 = 期初 + 入库 - 出库 + 调入 - 调出
差异 = 实际期末 - 期望期末
```

系统同时计算：

- `GLOBAL_PRODUCT`：按产品汇总；调拨全局净影响为 0；
- `WAREHOUSE_PRODUCT`：按产品和仓库汇总；调拨从来源仓扣减并向目标仓增加。

单事件 `TRANSFER` 直接包含来源和目标仓。旧调拨的 `TRANSFER_OUT` 与 `TRANSFER_IN` 使用同一个 `business_action_id`，并在一次业务动作中共享同一 `occurred_at`，避免操作恰好跨零点时被错误拆到两个自然日。

## 4. 数据质量规则

当前规则版本为 `inventory-reconciliation-v1`，至少检查：

- 缺少期初或期末日终快照；
- 快照规则版本不一致；
- 同一来源重复记账；
- 未登记事件类型；
- 数量为零或负数、重量为负数；
- 调拨缺少来源仓或目标仓；
- 旧调拨两条腿缺失或不平衡；
- 产品全局或产品仓库的期末数量、重量不守恒。

发现异常时写入可审计问题并使对应日期阻断，不自动篡改事件、快照或库存来“抹平”差异。

## 5. 调度、补偿和幂等

- 北京时间每日 00:00 先生成前一自然日的日终快照，再尝试执行该日对账；
- 应用启动后会补偿检查最近已关闭日期；
- 相同业务日期、相同终态快照版本不会重复生成对账批次；
- 新快照修订版出现后可以产生新的对账修订版，旧结果保留；
- 启动补偿失败只记录告警，不阻止业务服务启动。

## 6. 发布门禁

`INVENTORY_LEVEL_TREND` 的默认门禁为连续 7 个自然日的最新修订均为 `PASSED`。

门禁状态：

- `BLOCKED`：连续通过天数不足，或窗口中存在失败、数据不足；
- `ELIGIBLE`：连续通过 7 天，只表示可以进入产品和技术评审，不表示报表自动发布。

即使门禁变为 `ELIGIBLE`，仍需确认趋势口径、时间范围、卡片、导出、权限、空数据和异常降级，再登记 `inventory_level_trend_v1`。

## 9. 2026-07-31 运行复核

北京时间 2026-07-31 18:21 再次检查本地库：

- 2026-07-30 对账为 `INSUFFICIENT_DATA`；
- 2026-07-30 缺少期末日终快照；
- 发布门禁仍为 `BLOCKED`、连续通过 0/7 天。

原因不是对账公式，而是调度恢复边界：零点定时任务会先快照再对账，但 `InventoryReconciliationCatchupTask` 在应用启动时只补做对账，不补建错过的日终快照。服务若在零点没有运行，白天启动后将当前库存回填为前一日零点库存会制造虚假历史，因此本次没有执行回填。

后续必须在以下方案中选择并验证一种：

1. 由可靠的外部调度保证日终快照任务执行，并为错过任务建立告警；
2. 基于上一可信快照和不可变库存事件，按版本化规则重建缺失日终快照。

在此缺口关闭前，“库存窗口自然积累”只是部署前提，不是当前已验证事实；库存趋势继续保持阻断。

## 10. 2026-08-01 调度可靠性复核

在实现历史报表跨会话重开时再次复核库存日快照链路，结论不变：

- 进程内 `@Scheduled` 只在 Java 服务跨零点存活时有效；
- 启动补偿只运行对账，不补建日终快照；
- 增加另一个进程内重试仍无法覆盖整夜停机；
- 白天直接读取当前库存回填前一日日终会混入当天变化，禁止采用；
- 当前事件账足以做数量、重量守恒，但还不足以无损重建库存记录数、托盘数和所有历史主数据快照。

因此没有为了推进报表而修改门禁或生成虚假快照。下一底座切片必须提供独立可靠调度与失败证据，或先扩展事件重建所需维度再实现确定性重建；完成前 `inventory_level_trend_v1` 继续保持未登记。
