## 1. 已实施

沿用主模型识别目标 → 生产专家选择工具 → 参数校验 → 现有日报查询 → 模型分析与卡片。仍使用 `PRODUCTION_DAILY_REPORT_RECORDS` 和 `query_production_daily_reports`，不增加专家、目标或工具。

- 日期、车间、产品/指标筛选或每页条数变化后，默认重置到第1页。用户明确指定“第3页/第三页”时保留模型解析的页码；不从自然语言另建业务路由，也不修改模型选择的产品、日期或车间。
- 先严格校验再处理分页：无效页码不能被重置逻辑掩盖成合法请求。
- 只归一化明确的无筛选别名，如参数中的“全部车间”“全部产品”；“全厂汇总”是具体分区，继续保留。实际产品/指标名称不因问句里出现“全部”就被删除。
- 生产专家明确以车间主任填写的日报作为当前生产概况来源，不先要求选择来源，不预测或推算未登记产量。
- 区分后端已完成的“当日值跨日合计”和禁止再次求和的“月/年累计快照”。对旧后端的一条歧义说明，在 Agent 展示适配中按确切文案替换为准确表述，不修改任何数值或业务接口。
- 追问只继承仍适用的条件；答复严格使用本轮工具事实的日期与范围，历史对话不能成为其他日期/车间的最新数据证据。

修改位置：`agent-service/app/tool_arguments.py`、`agents.py`、`model.py`、`daily_report_records.py`；测试为 `agent-service/tests/test_production_daily_reports.py`。真实模型验收脚本追加 D07 连续追问场景。

新增覆盖：

| 场景 | 判断 |
|---|---|
| 改日期、车间、产品、每页条数、清除筛选 | 新范围从第一页开始，原会话查询字典不被原地修改 |
| 明确查询昨天第3页/第三页 | 昨天按业务时钟解析，保留第3页 |
| 全部车间/全部产品；全厂汇总/总产量 | 泛指不成为数据库名称过滤，具体分区与指标保留 |
| 主模型委派后专家发起“改成昨天”查询 | 仍经过模型路由和专家工具循环，实际调用日期和页码正确 |
| 权限拒绝、工具超时、服务错误 | 不能将错误观察引用为“没有生产数据”，失败不保存为成功查询上下文 |
| 上述错误后重试 | 重新调用工具，使用新的成功结果恢复，而非复用失败结果 |
| 当日折吨与月年累计说明 | 区分可跨日合计的当日值和不可重复相加的累计快照 |
| 范围变化同时带无效页码 | 仍拒绝无效请求，不通过重置掩盖错误 |
