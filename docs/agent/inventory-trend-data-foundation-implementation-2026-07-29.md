# 库存趋势数据底座实施与验收记录

日期：2026-07-29
实施切片：`V2A-DATA-02-INVENTORY-MOVEMENT-LEDGER-SNAPSHOT`
结论：**数据底座实现通过；库存历史趋势仍未开放**

## 1. 本轮解决的问题

上一轮审计确认，`inventory` 只能回答当前库存，无法回答历史某日库存；旧调拨使用“出库 + 重新入库”，新托盘调拨则原地移动库存，两者也没有统一的事件语义。

本轮没有直接新增库存趋势报表，而是先落地：

1. 不可变库存事件账本；
2. 版本化日终库存快照；
3. 普通入库、半成品入库、普通出库、生产领料、旧调拨、新托盘调拨的统一事件接入；
4. 上线时的真实库存基线；
5. 去重、调拨净零、快照幂等和失败回滚测试。

本轮没有新增 Agent/MCP 工具，没有开放业务写操作，也没有伪造启用日之前的历史。

## 2. 数据模型

### 2.1 `stock_movement_event`

事件表保存真实库存变化事实，主要字段包括：

- `event_id`：系统生成的唯一事件 ID；
- `event_type`：`INBOUND`、`OUTBOUND`、`TRANSFER_IN`、`TRANSFER_OUT`、`TRANSFER`；
- `business_action_id`：同一次业务动作的关联标识；
- `source_type + source_record_id + event_type`：来源幂等键；
- `occurred_at` 与 `recorded_at`：业务发生时间和系统记账时间；
- 产品、产品状态、生产日期、来源/目标仓库和托盘；
- 整板数、散件数、统一折算件数、重量和折算规则版本；
- 操作人、动作类型和扩展元数据。

事件与库存业务数据在同一个 Spring 事务内写入。业务事务回滚时，事件也回滚；同一来源重试时不会重复记账。

### 2.2 `inventory_snapshot_run`

快照批次保存：

- 快照日期、类型和 revision；
- `data_as_of`、规则版本、行数和内容 SHA-256；
- 构建状态、修订原因、开始和完成时间。

同一日期、类型和 revision 唯一。已完成的同日日终快照再次触发时直接复用，不重复生成。

### 2.3 `inventory_daily_snapshot`

日终快照按以下维度聚合：

- 产品；
- 产品状态；
- 仓库；
- 生产日期。

保存整板数、散件数、统一折算件数、重量、库存记录数、托盘数，以及产品名称、仓库名称和折算参数的当时快照。

## 3. 业务路径覆盖

| 业务路径 | 事件来源 | 事件语义 | 业务动作关联 |
|---|---|---|---|
| 成品入库 | `IN_STOCK` | `INBOUND` | 一次成品入库及其原料扣减共享动作 |
| 半成品入库 | `SEMI_PRODUCT_RECORD` | `INBOUND` | 单次入库动作 |
| 普通/堆垛出库 | `OUT_STOCK` | `OUTBOUND` | 同一次请求内多个批次共享动作 |
| 生产订单领料 | `OUT_STOCK` | `OUTBOUND` | 同一生产订单领料共享动作 |
| 旧调拨 | `OUT_STOCK` + `IN_STOCK`/`SEMI_PRODUCT_RECORD` | `TRANSFER_OUT` + `TRANSFER_IN` | 两条腿共享动作 |
| 新托盘调拨 | `PALLET_TASK` | `TRANSFER` | 单事件同时保存来源和目标仓库 |
| 托盘直接出库 | `OUT_STOCK` | `OUTBOUND` | 优先使用任务批次号，否则使用任务 ID |

`pallet_flow_record` 继续用于生命周期展示，不再承担长期数量账职责。

## 4. 数量口径

统一折算件数沿用现有库存规则：

- 有散件数时：`totalPieces = pieces`；
- 无散件数时：`totalPieces = boardQuantity × piecesPerPallet`；
- 重量：`totalPieces × weightPerPiece`。

板数和散件数互斥记录，避免把一条库存同时计算为整板和散件。

调拨口径：

- 全局产品库存变化为 0；
- 仓库维度从来源仓库扣减、向目标仓库增加；
- 旧调拨两条腿共享 `business_action_id`；
- 新托盘调拨以一条含来源和目标的事件表达。

## 5. 快照时点

- 迁移执行时生成一次 `INITIAL_BASELINE`；
- 基线只代表启用时真实库存，不代表此前历史；
- 日终任务在北京时间次日 00:00 生成前一自然日的 `DAILY_CLOSE`；
- 应用层快照保存内容 SHA-256；
- 迁移基线由 SQL 直接生成，`content_sha256` 保持为空，不伪装成应用层校验结果。

## 7. 当前限制与下一门禁

数据底座通过不等于库存历史趋势已经具备发布条件：

- 启用日前没有历史日终快照，不做虚假回填；
- 还没有落地“期初 + 当日事件 = 期末”的每日对账结果表和发布门禁；
- 尚未积累连续快照窗口；
- 补录、冲正和并发边界仍需在持续运行中观察；
- 当前没有新增 `inventory_level_trend_v1` 报表定义。

下一切片为 `V2A-DATA-03-INVENTORY-DAILY-RECONCILIATION`：

1. 生成每日产品全局和仓库维度守恒结果；
2. 检查重复来源、未知事件、调拨缺来源/目标、负数量和折算参数缺失；
3. 对差异建立可审计状态，不静默修正；
4. 连续快照达到产品确认窗口后，先评审受限的产品总库存净变化，再评审库存水平趋势。
