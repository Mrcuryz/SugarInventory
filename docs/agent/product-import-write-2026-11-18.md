# 产品管理批量导入与受控写入

日期：2026-11-18；界面进展更新：2026-11-19。

## 目标与现状

用户在Agent对话中上传Excel，由模型结合现有产品目录识别同一产品及疑似匹配，展示新增、修改、不变和待确认条目。用户解决歧义并勾选需要应用的条目，核对后批量新增或修改。不删除表格中未出现的产品。

目前完成工作表上传、目录候选检索、基础资料专家逐行核对，以及当前会话内已核对行的整表汇总和勾选。上传和核对默认关闭，试用需同时开启 `agent.product-import.upload-enabled=true` 与 `agent.product-import.matching-enabled=true`，使用更新后的 Java、Python 和 MCP 三端及 LLM 决策模式。没有批量执行入口，不写产品，未部署。

工作树另有安卓及生产日报填报人改动，本任务不修改这些文件。

## 现有业务依据

- `ProductController`：查询使用 `product:view`，新增使用 `product:create`，修改使用 `product:update`。
- `ProductCreateDTO` / `ProductUpdateDTO`：名称、类型、状态、包装、单件重量、每板件数、可堆叠、筛网关联。重量最小0.1、件数最小1；新增重量/件数并非DTO强制必填，不能自行加造规则。
- `ProductServiceImpl.updateProduct`：存在当前库存时，禁止修改单件重量和每板件数。导入执行必须复用并重新检查该业务约束。
- 当前新增做名称唯一性检查；现有修改逻辑及名称唯一性并发保护需在批量执行阶段复核，不能把应用层先查询等同于数据库并发保证。
- `master_data_expert` 可查询产品和筛网，并通过登记的核对工具比对表格，不能直接给模型新增/修改权限。
- 助手已接入临时产品表格界面，所选附件行可进入专家决策链。既有化验的签名引用、预览归档、人工确认、幂等和结果恢复是可参考的控制模式，不能直接复用化验表存产品操作。

## 交互与匹配规则

1. 上传后显示文件名、工作表和记录数；多工作表先选择，不静默读取第一张。
2. 已知列直接识别，未知或重复列要求确认映射；不能默默丢弃数据。前端提供工作表和列对应关系选择，后端按零起始列序号校验字段，拒绝重复目标字段、未知字段及不存在的列。
3. 格式等价先按规则判断，例如全半角括号、首尾空格；格式差异不自动生成改名操作。数字、包装、颜色、等级等语义不能被归一化删除。
4. 不同名称/别名由主模型委派基础资料专家，专家基于服务端提供的候选提出MATCH、NEW或UNSURE。模型不能编造候选引用、字段值或执行指令。
5. 模型匹配建议只影响待核对候选，不构成保存授权。歧义项给出原表名称、现有产品名称、规格和简短依据；用户可选择现有产品、作为新产品或忽略。
6. 未查到精确名称不等于可以直接新增；需完成候选检索和模型匹配。候选分页或截断必须显式标记，不能对不完整目录宣称没有同类产品。
7. 同名但重量/每板件数不同，先询问是更正旧产品还是新规格；有库存时原产品规格变更禁止应用。包装、类型、状态、筛网变化也需显式核对。
8. 空单元格和缺列表示不修改，不表示清空、零或false。明确false保留；本批次不支持隐含清空。单位不明确、未知类型和不合法数值不能猜测修正。
9. 表内重复名称、多个源行匹配同一目标、一个源行有多个候选都需解决冲突，不能最后一行覆盖前一行。
10. 筛网使用名称候选解析，不能把Excel任意数值当作数据库ID。没有提供筛网则保留原值。

## 待实现的接入与执行链

上传接口仅解析有权限用户的文件，临时存储来源行、文件名和内容摘要，不保留原始文件；绑定用户与会话，并设置容量、数量和有效期限制。表格内容是非可信数据，单元格中的“忽略规则”等文字不能作为系统或工具指令。文件解析不访问外部链接，不执行公式或宏。

新增产品导入Goal后，由现有主模型委派 `master_data_expert`，先获取受控导入行及目录候选，再提出匹配建议；后端校验源行、候选归属和引用。专家决定何时补问，不新增关键词直调模型旁路，也不让模型持有任意SQL/HTTP能力。

差异卡分组展示新增、修改、待确认、不变和不能应用。每项显示Excel行号、匹配依据和修改前后值；不变项不占主要视图。可应用项支持逐项选择和全选，未解决歧义或校验失败项禁选。用户修改匹配、输入或选择集合后，旧确认凭据必须失效。

人工确认接口应绑定不可变操作清单、用户、会话、目标快照、内容摘要、有效期和幂等键。批量执行不接受前端提交任意产品对象；根据归档清单重读权限和目标状态，再调用现有产品业务服务。新增和修改按本次勾选操作分别检查权限，不要求只新增的用户同时拥有修改权限。

选中批次默认事务内全成功或全回滚，按固定顺序锁定目标，处理同名并发新增和网页修改竞争。若任一目标已被其他人修改，返回具体冲突并重新预览，不覆盖新数据。数据库约束和旧写入口的并发一致性必须先验收，不能仅锁导入任务。

最终返回每行新增/修改结果及数量。网络中断、刷新、重复点击、服务重启后按同一幂等记录恢复结果，不重复创建产品。审计关联来源文件摘要、工作表/行号、操作者和具体差异，不记录模型原始推理或凭据。

## 本轮代码与验证

- `ProductImportWorkbookReader`：支持xls/xlsx，保留工作表/真实行号与非空原值；支持工作表/列名检查及显式列映射；10MiB/500行/32列/32工作表上限；拒绝公式、错误值、日期单元格、合并区域、隐藏数据行及未命名列中的数据。xlsx在POI创建对象模型前检查ZIP，解压总量不超过24MiB、条目不超过256；拒绝宏项目、嵌入文件及外部引用条目。
- `ProductImportAccessService`：每次读写附件前从数据库重读权限，要求 `agent:use`（遵循既有管理员策略）、`product:view`，以及 `product:create` 或 `product:update`；复用已有会话归属/有效性校验。上传解析完成后再检查一次权限和会话。只新增的用户不需要同时拥有修改权限。
- `ProductImportDraftStore`：Redis中每账号最多3个临时附件，跨会话共享额度；使用原子SET NX和30分钟TTL，不覆盖已有附件，不因读取续期；单份JSON不超过2MiB。删除使用比较后删除，防止槽位过期复用后误删新附件。附件引用不是执行凭据。
- `ProductImportUploadService` / `ProductImportController`：检查扩展名与实际工作簿内容，限制单进程同时解析2份文件；提供工作表检查、上传、当前会话附件列表、分页读来源行和移除接口。返回文件摘要和来源行，不返回内部账号ID。列表用于上传响应丢失、关闭后重开时恢复，不自动重传文件。没有产品保存入口。
- `ProductImportCapabilitiesController`：上传开关关闭时仍能查询能力，返回实际上传和匹配开关；执行始终为false；检查当前权限和会话，前端不通过猜测接口是否存在来展示入口。
- `ProductImportDialog.vue` / `productImportFlow.mjs`：工作表及列映射、上传进度、原始来源行分页、过期提示、列表恢复和移除；异步响应隔离，上传结果未知时先恢复列表，不自动重传。未接模型时不提供对比或保存按钮，源数据0与空值保持区别。
- `app/product_import.py`：格式归一、已知字段类型校验、精确候选歧义、逐字段差异、库存规格保护、重复源行分组、闭合的模型建议结构校验。
- Java产品导入定向测试34项通过；Python定向测试27项为上一轮通过结果，本轮未修改Python。Java测试覆盖权限撤回、跨账号/会话读取拒绝、有效期、20次上传任务在8线程下最多保留3个附件、比较后删除调用、解压上限、列映射、分页、列表恢复及能力开关。Redis测试使用模拟的原子键值存储，不等同于真实Redis集成验收。
- 前端助手相关116项测试通过，其中新增产品表格流程11项；前端生产构建通过。构建保留项目现有Sass旧API及大包体警告。
- 既有会话和权限回归32项通过：`AssayEntryAccessServiceTest` 3项、`AgentSessionServiceImplTest` 28项、`AgentSessionControllerAccessTest` 1项。
- 浏览器界面使用真实Vue组件和模拟HTTP响应验证，不连接数据库。真实Redis/HTTP后端联调、真实模型匹配和完整导入验收尚未完成。
- Python差异计算只是内部预判；不能作为Java最终业务校验、权限或写入授权。本地只读预览不代表持久化或上线。

## 上传接口与本地启用条件

统一前缀：`/api/agent/sessions/{sessionId}/product-import`。这些是人工附件接口，不加入模型工具白名单。

| 方法与路径 | 输入 | 返回或效果 |
| --- | --- | --- |
| GET `/capabilities` | 当前用户的有效会话 | 上传、匹配、执行是否开放及文件/行数上限；上传和匹配按配置，执行始终为false |
| POST `/inspect` | multipart字段 `file` | 工作表名称、隐藏标记、列序号、原标题、建议字段；不占附件额度 |
| POST `/drafts` | `file`、可选 `sheet`、JSON字符串 `mapping` | 随机附件引用、文件名、SHA-256、工作表、行数、到期毫秒时间戳 |
| GET `/drafts` | 当前用户的同一有效会话 | 该会话未过期的附件摘要，用于恢复列表，不暴露其他会话附件 |
| GET `/drafts/{reference}?page=1&pageSize=50` | 当前用户的同一有效会话及附件引用 | 附件信息与来源行；每页最多50行 |
| DELETE `/drafts/{reference}` | 当前用户的同一有效会话及附件引用 | 移除临时来源数据，不影响产品 |

`mapping` 示例：`{"0":"productName","1":"weightPerPiece"}`，表示用户确认第一列是产品名称、第二列是单件重量。仅接受八个既有产品字段；未知列必须映射或由用户修改文件，不提供静默忽略选项。多工作表需先检查并选择，再携带同一文件上传；检查接口不保存文件。

本地联调需显式设置 `agent.product-import.upload-enabled=true`。同时应配置 `spring.servlet.multipart.max-file-size=10MB`、`spring.servlet.multipart.max-request-size=11MB`，并核对代理上传限制；否则Servlet默认文件大小限制可能在业务检查前拒绝请求。当前未修改全局上传配置、部署配置或线上开关。

后续匹配工具必须根据会话身份重新取附件，不能接受前端或模型传入的源行作为可信原文。保存前还必须生成独立、持久化、绑定选择集合和目标快照的操作预览，不能直接执行Redis临时来源行。
