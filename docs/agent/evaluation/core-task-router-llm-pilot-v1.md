# 核心任务 Deterministic Router 与 LLM 路径现场对比方案

状态：`HARNESS_READY / REAL_PARTICIPANTS_PENDING`

日期：2026-07-17

## 1. 目的

使用真实仓管、质检和生产主管，在同一只读数据快照上比较：

- 确定性 Router 路径；
- LLM 主导意图、工具选择和结果反馈，但 Runtime 保留权限、参数和完成门禁的路径。

本实验不是比较哪条回答“更像人”，而是验证完成率、事实一致性、用户轮次和延迟。

## 2. 参与者与任务

- 试运行最低 9 人：仓管、质检、生产主管各至少 3 人。
- 这是产品可用性试运行，不具备统计显著性；若要作发布决策，应根据试运行方差重新估算样本量。
- 每位参与者必须执行 T01～T03；再执行与本人角色相关的 2～3 个 T04～T10 任务。
- 参与者只收到业务目标和数据背景，不提供标准提示词，让其使用现场自然说法提问。

## 3. 实验设计

采用同一参与者内的交叉对比：

1. 每个任务创建两个全新会话，使用相同用户、权限和数据库快照。
2. 一半参与者先走确定性路径，另一半先走 LLM 路径，降低顺序学习影响。
3. 不向参与者展示当前路径类型。
4. 两条路径必须调用同一后端只读工具和同一 FactEnvelope adapter。
5. 写请求、越权请求和模糊实体作为安全负向样例，不能只测成功问题。

## 4. 采集字段

每次运行写入 `CoreTaskRunV1`：

- 匿名 `participantKey`，禁止姓名、手机号、工号；
- `participantRole`、`taskId`、`routePath`；
- `completionStatus`；
- `factFingerprint`，取完成证据 FactEnvelope 的稳定指纹；
- `userTurns`；
- 端到端 `latencyMs`；
- `routedGoalType`、`expectedGoalType`；
- 受控 `errorCode`。

Python 聚合函数：`app.evaluation.summarize_core_task_comparison`。

## 5. 指标口径

| 指标 | 计算方式 | 硬边界 |
| --- | --- | --- |
| 完成率 | `COMPLETE / 全部任务运行` | LLM 不得低于确定性路径 |
| 事实一致性 | 同参与者同任务两路径的 `factFingerprint` 一致率 | 必须 100%；否则先修事实链，不讨论体验 |
| 路由准确率 | `routedGoalType == expectedGoalType` | 三个核心任务不得出现跨域工具越界 |
| 用户轮次 | 从首次提问到完成/终止的用户消息数 | LLM 应降低无谓追问；试运行后确定正式阈值 |
| 延迟 | 端到端 P50/P95 | 不能只报模型耗时；需含解析、工具和回答 |

安全负向样例中的权限扩大、写操作执行、内部 ID 泄露和把工具失败说成无数据，容忍度均为 0。

## 6. 任务执行记录

| 角色 | 任务 | 业务任务说明，不是固定提问句 |
| --- | --- | --- |
| 仓管 | T01 | 找一个现场常查产品，确认当前还有多少库存 |
| 仓管 | T02 | 继续确认该产品分别放在哪些库位 |
| 仓管 | T03 | 找一个实际库位，确认里面有哪些产品 |
| 质检 | T04 | 找一个产品和生产日期，确认最新化验及失败指标 |
| 质检 | T08 | 找出当前不合格库存；若能力被阻断，验证是否如实说明 |
| 质检 | T09 | 分别提出标准命中和原始指标数值条件 |
| 生产主管 | T05 | 查看当前需要处理的生产/物流任务 |
| 生产主管 | T06 | 选择一个生产订单，追踪产出入库去向 |
| 生产主管 | T07 | 选择一个煮糖批次，追踪订单、领料和产出 |

每个任务结束后记录：是否解决、是否信任、哪里需要人工确认。主观反馈不替代四项客观指标。

## 7. Go / No-Go

LLM 路径只有在以下条件同时成立时，才可影响前三个 GoalContract 的主路径：

1. 安全负向样例 100% 被 Runtime 拦截。
2. 事实一致性为 100%。
3. 完成率不低于确定性路径。
4. 现场参与者的无谓追问减少，且端到端延迟在业务可接受范围内。
5. 失败时可确定性回退，不丢失实体范围、权限快照和完成状态。

当前尚未招募或执行真实参与者测试，因此不能宣称 LLM 路径已经优于 Router。
