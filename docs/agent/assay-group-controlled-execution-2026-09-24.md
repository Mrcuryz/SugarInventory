# 化验组录入 D3b：受控保存后端

日期：2026-09-24。状态：本地后端实现及真实数据库验证；未部署，尚未完成组对话/页面接入与整体验收。

## 已实现

基于 [D3a 完整组预览](assay-group-preview-foundation-2026-09-24.md)，扩展现有 `AssayEntryArchiveService` / `AssayEntryExecutionService`，没有另建确认框架：

- 同一用户、同一会话的存档使用既有 `aep1_…` 引用及内容摘要，组载荷显式标记 `GROUP_V1`；旧单产品存档保持原格式，仍可回查。
- 组存档包含完整组名/成员、每个产品检测值、采样日期、已有及拟新增版本、标准与判定。不会只保存第一名成员。
- 确认和执行都会重新读取当前权限、会话、组成员及产品/标准状态，复用既有 5 分钟预览、最长 2 分钟确认有效期。
- 成员增减、组名/标准/版本变化使旧确认失效。组变为空组、删除或成员失效同样返回“状态已变化”，避免反复重试旧预览。
- 组内全部产品在一个事务中保存，任意产品或审计写入失败全部回滚；每项成功记录和整组完成事件均纳入同一事务。
- 幂等确认、并发执行、取消、结果回查以及旧会话中断恢复复用单产品控制链路。恢复只核实成功结果或终止未完成操作，不重新写入化验。
- 执行开关仍默认关闭；没有新增业务权限、修改既有账号、修改库存或变更数据库结构。

## 人工控制接口及返回约定

新增 `POST /api/agent/sessions/{sessionId}/assay-entry/previews/group`，请求为 `AssayGroupEntryPreviewDTO`（groupId + values）。这是人工控制入口，不注册 MCP 工具、不允许 Agent 委托。

后续继续使用同一组接口：

- `POST /previews/{ref}/confirm`
- `POST /previews/{ref}/execute`（只接受确认凭据与幂等键，不接受产品或检测值）
- `GET /previews/{ref}/result`
- `POST /previews/{ref}/cancel`
- `POST /previews/{ref}/recover`

完整前缀同上。权限仍需助手访问权限、化验查看权限及创建/检测权限，并在服务端重新读取当前授权。部分权限、非本人、非所属会话均沿用原控制边界。组预览入口已加入方法权限测试及委托拒绝测试。

整组成功返回 `AssayEntryExecutionResultVO`：顶层 `saved=true`，`assayId/version/productName=null`，不能伪装成单产品结果。`details` 包含：

```json
{
  "entryKind": "GROUP_V1",
  "groupId": 123,
  "groupName": "真实化验组名称",
  "productCount": 2,
  "saved": true,
  "previewOnly": false,
  "products": [
    {"productId": 10, "assayId": 101, "recordVersion": 1, "saved": true, "previewOnly": false},
    {"productId": 11, "assayId": 102, "recordVersion": 4, "saved": true, "previewOnly": false}
  ]
}
```

上例 ID 仅说明结构，非验收数据。每项实际还保留产品名、日期、检测值、标准和判定信息。回查校验成员数量、产品/日期、实际版本与预览对应，并拒绝缺项或重复记录标识。

现有控制表 `normalized_input_json` / `public_payload_json` / `result_json` 容纳组载荷；组确认行的单一 `assay_id` 留空，所有结果记录保存在 `details.products`。无新增迁移。

## 验收输入、流程与判断

### 专项单测

首轮 65 项全部通过，包含旧单产品存档/执行、组存档、控制权限和委托白名单。日志：`output/assay-entry-ui/group-controlled-tests.log`。随后补入空组失效及组人工入口权限断言，最终以全量回归为准。

| 输入/流程 | 判断 |
|---|---|
| 两个产品已有版本分别为空、3 | 存档完整展示拟新增版本 1、4；不把组当成单产品读取 |
| 组成员变化或原有效组变为空组 | 确认/执行拒绝旧存档，要求新预览 |
| 两产品实际保存返回不同记录标识 | 全部保存在结果；顶层不冒用第一条记录 |
| 重复执行、结果回查和恢复 | 返回同一份完整组结果，不再调用写入 |
| 保存结果缺少成员、重复实际记录标识 | 不按成功终态显示，明确报告不一致 |
| 仅具备部分权限或仅角色名 | 人工组预览入口拒绝，与旧控制接口一致 |
| Agent 委托访问人工组存档入口 | 拒绝，模型工具数量和权限不变 |

### 真实本地 MySQL

五项数据库测试全部通过、未跳过：组执行、组预览状态、单产品执行、单产品存档、共享化验写入。日志：`output/assay-entry-ui/group-controlled-mysql.log`。

组执行测试类 `AssayGroupEntryExecutionMysqlTest` 创建独立 `UAT_AGE_…` 前缀的两个产品、一个分组和一个临时会话；只读取现有本地管理员标识，不修改账号。共同输入为采样日期 2026-09-24、色值 10、pH 0，其他未填。测试后删除专属化验、控制记录、审计、分组、产品和临时会话，断言无残留。

| 用例 | 具体过程与实际结果 |
|---|---|
| 预览后成员改变 | 两成员预览后删去一名成员；确认返回 1055，不写化验 |
| 第二产品保存失败 | 第一产品实际 INSERT 后，第二产品注入异常；事务后两产品化验总数为 0，第一条成功审计也为 0，确认仍为 CONFIRMED |
| 整组审计失败 | 两产品和各项审计实际写入，再让整组审计失败；全部回滚，预览仍为 CONFIRMED |
| 并发重复执行 | 两线程同时携带同一确认凭据；一份首次结果、一份回放结果，内容相同，两产品总计只有 2 条化验 |
| 返回事实核对 | 每个返回 assayId 与数据库对应产品记录一致；pH 为 0，干燥失重为 NULL；逐项成功审计 2 条、整组成功事件 1 条 |
| 确认后成员变化 | 确认后修改成员，再执行返回 1055，不新增；最终补测变为空组也按 1055 失效 |
| 取消/恢复后迟到执行 | 恢复将未执行组取消，迟到执行拒绝，不新增记录 |
| 保存与恢复竞争 5 轮 | 每轮要么增加完整 2 条且恢复显示同组结果，要么增加 0 条且显示已取消；没有只增加 1 条 |
| 原会话过期/撤销 | 本人有当前权限时可恢复原成功结果；旧会话不能重新确认 |

最终全量后端回归共 656 项，655 项通过、1 项环境相关跳过，0 失败/错误，BUILD SUCCESS；显式开启的上述五个化验数据库测试均实际通过（包含最后补入的空组变化场景）。日志：`output/assay-entry-ui/group-controlled-final-tests.log`。跳过的是独立环境开关控制的日报数据库测试，不据此声称本轮重新验证了日报数据库场景。
