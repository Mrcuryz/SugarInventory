# 历史报表列表与跨会话重开实施记录

日期：2026-08-01
实施切片：`V2A-REPORT-07-HISTORY-REOPEN`
结论：五类登记报表已支持按当前用户安全列出并跨会话重新打开原始快照；没有新增 MCP 工具、GoalContract 或业务写操作。

## 1. 产品目标

此前系统已经可以用受控 `reportRunId` 读取和导出某一份报表，但普通用户在新会话中没有办法找到自己的历史报表。本切片补齐：

1. 在 AI 助手中查看本人最近 30 天仍有效的历史报表；
2. 按五类登记报表筛选；
3. 跨会话打开生成时的不可变快照；
4. 继续使用原卡片和原 `reportRunId` 导出，不重新调用模型或查询最新业务数据。

“重新打开”与“刷新”严格分开。本切片没有提供刷新按钮；用户需要最新事实时应重新向 AI 助手提问，由原有“模型理解 → 分析专家决策 → `run_registered_report` → 结果分析”链路生成新的 `ReportRun`。

## 2. 后端安全边界

新增 `GET /api/analytics/agent-read/reports`，使用标准 `page`、`size` 和可选 `reportDefinitionId`，每页最多 50 条。

列表只返回同时满足以下条件的记录：

- `owner_user_id` 是当前登录用户；
- `expires_at` 晚于当前北京时间；
- 当前用户仍拥有报表定义要求的全部权限；
- `reportDefinitionId` 属于五个已登记白名单之一；
- 快照 JSON 的 SHA-256 与保存值一致且能够按当前 VO 解析。

列表 VO 只暴露报表名称、日期范围、用户可读范围、生成/到期时间、是否含对比和是否存在数据质量缺口，不暴露 owner ID、权限串、内部数据库 ID、原始 JSON 或内容哈希。

打开和导出仍调用原有按 `reportRunId` 接口，并再次验证所有者、当前权限、有效期和内容哈希。列表不是能力凭证，不能绕过单份快照验证。

## 3. 前端体验

AI 助手标题区新增“历史报表”入口：

- 列表明确提示“历史报表是生成时的不可变快照”；
- 支持生产产量、化验判定趋势、单项指标趋势、生产消耗与产出、流程效率五类筛选；
- 打开后把快照恢复为现有五类业务卡片，而不是展示后端 JSON；
- 卡片继续支持原有展开、收起、跨期比较和 XLSX 导出；
- 对话中明确显示原生成时间，避免用户误认为是实时数据。

快照到期、权限已撤销、内容校验失败时由后端拒绝，前端不降级展示缓存内容。

## 4. 架构判断

历史列表和快照重开属于 `ReportRun` 生命周期与 Web 交付能力，不属于新的自然语言业务目标，因此：

- 不新增 `list_report_history` MCP 工具；
- 不新增 GoalContract；
- 不把列表查询交给大模型；
- 不改变主 Agent、专家和工具白名单；
- 不修改库存、生产、化验、任务等业务事实。

这样既保留智能问答主链路，也避免为页面导航制造低价值工具。

## 6. 真实浏览器验收

2026-08-01 使用本地真实账号完成浏览器验收，结果如下：

1. AI 助手标题区能够打开“历史报表”；
2. 历史列表只展示当前用户仍有效、仍有权限查看的报表摘要，并能够翻页；
3. “生产消耗与产出”等类型筛选能够正确收窄结果；
4. 打开历史报表后，历史弹窗自动关闭，并恢复为原有业务卡片；
5. 对话明确显示原始生成时间，以及“原始结果不会随当前数据自动变化”的提示；
6. 恢复后的卡片保留“导出”入口，不暴露原始 JSON、内容哈希或内部数据库字段。

本次浏览器验收打开的代表性快照为“生产领料—登记产出趋势 · 2026-02-02 至 2026-07-31”。

## 7. 未完成边界

- 未提供“刷新历史报表”；刷新必须创建新的 `ReportRun`，不能覆盖旧快照；
- 未做 PDF/CSV、订阅、分享链接和短时下载凭证；
- 到期记录当前只在读取和列表中隐藏/拒绝，尚未增加物理清理任务；
- 历史列表是本人范围，不支持管理员代看其他用户报表；
- 库存趋势仍未登记或开放。

## 8. 库存日快照调度复核

同期复核确认：`InventoryDailySnapshotTask` 只在应用存活且北京时间 00:00 被正常调度时生成前一日日终快照；应用启动补偿只运行对账，不补建快照。单纯增加进程内重试仍不能覆盖应用整夜停机，白天用当前库存回填又会制造虚假历史。

因此本切片继续保持库存趋势门禁，不把 2026-07-31 之后的自然日期流逝当成可靠窗口。下一数据底座切片必须在两条路线中选择一条并验收：

1. 部署层提供独立于业务进程生命周期的可靠调度、失败告警和运行证据；
2. 扩展不可变事件，使缺失日终快照的所有聚合维度都可由上一可信快照确定性重建。

现有事件能支持数量和重量守恒，但不足以无损重建库存记录数、托盘数和所有历史主数据快照，因此当前不能宣称事件重建已经可用。
