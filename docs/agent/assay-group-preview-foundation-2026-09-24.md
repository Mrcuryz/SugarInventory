## 现有业务资产与边界

- 使用已有 `assay_group.related_products` 展开产品。`standard_name` 在这张表中是化验组名称，不是质量标准；不会据此选择化验标准。
- 一组共同检测值应用到所有成员，各产品分别按现有产品标准判定，分别计算拟新增版本；不允许客户端另外指定成员或产品 ID。
- 只使用现有采样日期及七项检测字段。未填保持空，0 保持 0，超精度拒绝，不进行舍入或单位猜测。
- 重复成员去重并按产品 ID 排序。空组、格式异常、非正整数、产品不存在均拒绝完整预览，不静默跳过成员。
- 默认最多 50 个产品，配置 `agent.assay-entry.group-max-products`，允许 1～200。这是防止大批量预览的技术安全边界，不是已有业务制度；超限拒绝，不截取前若干项。
- 不新增业务表或字段，不修改库存，不访问生产数据库，不改变既有化验组维护页面。

## 接口与权限

`POST /api/assay/entry/group/preview`

请求示例（groupId 必须来自真实查询）：

```json
{
  "groupId": 123,
  "values": {
    "sampleDate": "2026-09-24",
    "colorValue": 10,
    "phValue": 0
  }
}
```

响应 `Result<AssayGroupEntryPreviewVO>` 包含 `previewOnly=true`、`confirmationAvailable=false`、组名、日期、完整产品数量及 `products`。每个产品包含检测值、已有/拟新增版本、采用标准及中文判定。不返回确认凭据。

权限要求：`assay:view` 且具备 `assay:create` 或 `quality:test`。仅有助手权限、角色名、查看权限或单独写权限均不够。

当前不注册为 MCP 工具，不加入 Agent 会话委托白名单；已将组预览/执行路径加入拒绝回归。仍为 61 个 Goal / 56 个 Java 工具。后续接入继续使用模型理解 → 化验专家决策 → 受控工具 → 结果分析，不新增规则直通写入。

## 一致性设计

只读预览使用可重复读事务，完整展开同一快照中的成员、产品和标准。内部 `AssayGroupEntryStateService` 必须在已有事务中使用：

1. 锁定化验组，读取完整成员集合。
2. 按稳定产品顺序锁定全部产品、各产品当前版本及全部标准关联。
3. 对整组涉及的质量标准去重并统一排序，锁定标准及项目，避免逐产品锁标准产生反向锁序。
4. 各产品复用既有标准判定，再将组 ID、组名、成员、各产品完整状态纳入摘要。

成员排序/重复项改变但语义集合不变时摘要保持一致；成员增减、组名变化或标准内容变化时摘要变化，即使最终合格/不合格结论没有改变。**当前仅证明可以检测变化，拒绝旧组确认要到 D3b 存档接入后验证。**
