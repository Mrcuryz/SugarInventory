# 待处理任务 L2 安全跳转实现与验收（2026-08-04）

> 后续状态：本文记录首轮 UI 安全跳转基线。成品入库类型已在同日继续升级为正式 `preview_task_transition` L2 合同；其他任务类型仍保持本文边界。最新设计与验收见 `finish-inbound-task-transition-preview-2026-08-04.md`。

## 1. 结论

首个写入阶段切片已按“只读预览 + 既有业务弹窗”落地并通过本机真实浏览器验收：

`模型理解 → logistics_expert 决策 → query_pallet_tasks → 待处理任务卡片 → 用户选择 → 既有业务弹窗`

该链路属于 L2 用户界面跳转，不是 Agent 写操作：

- Agent 只查询 `PENDING` 任务并生成选择卡片；
- 用户选择后，前端只传递托盘码和任务类型给现有业务弹窗；
- 弹窗重新查询任务，并沿用原业务表单、权限、校验和提交接口；
- Agent、Python Runtime 和 MCP 均不调用任务创建、确认、取消、入库、出库或调拨接口；
- 本轮浏览器验收打开弹窗后选择“取消”，没有提交任何业务写入。

当前结论：`L2_UI_HANDOFF_GO / AGENT_L3_EXECUTION_NO_GO`。

## 2. 本轮修复

### 2.1 自然语言边界

以下表达进入受控任务处理预览：

- “帮我处理当前入库任务”
- “确认当前待处理出库任务”
- “办理待确认调拨任务”

Runtime 将其识别为 `pallet_task_processing_preview`，但实际只调用既有 L1 工具 `query_pallet_tasks`，并强制：

- `status=PENDING`；
- 根据用户表达限定入库、出库或调拨类型；
- 由 `logistics_expert` 处理；
- 返回 `pallet_tasks` 业务卡片；
- 明确说明本轮未确认、取消或执行任务。

不带“任务/待处理”语义的普通写入指令，例如“帮我出库”，仍按未开放写操作拒绝，不会因为本切片而放宽。

### 2.2 业务接口权限

对既有任务页面接口补齐项目已经定义并分配的细粒度权限：

| 接口类别 | 权限 |
|---|---|
| 任务列表 | `task:view` |
| 创建任务 | `task:create` |
| 确认任务 | `task:confirm` |
| 取消任务 | `task:cancel` |

权限来自既有 RBAC 迁移和前端权限目录，本轮没有创造新角色或新权限语义。反射矩阵测试覆盖任务列表、半成品/成品出库创建与确认、调拨创建与确认、入库确认和取消接口，防止后续遗漏注解。

## 3. 真实浏览器验收

环境：当前本地 `5173 → 8080 → 8091`，ADMIN 账号，RAG 与业务工具均启用。

### 3.1 正向链路

输入：`帮我处理当前入库任务`

结果：

1. 主 Agent 将请求交给物流专家；
2. 返回 4 条当前待处理成品入库任务；
3. 回答说明“此次仅查询任务记录，未确认、取消或执行任何入库、出库和调拨”；
4. 任务卡按“成品入库”分组，支持展开、逐条选择和全选；
5. 选择托盘 `BT0019N1` 后，按钮变为“处理所选 1 条”；
6. 点击后打开既有“批量确认成品入库”弹窗，弹窗展示相同托盘并重新加载业务字段；
7. 点击“取消”，未提交。

### 3.2 负向链路

输入：`帮我出库`

结果：明确提示出库属于未开放写操作，当前无法直接执行；仅建议用户先查看待处理出库任务。未显示可执行卡片，未调用写接口。

- Python 既有回归：普通写入请求不得执行。
- Java 新增权限矩阵：任务列表、创建、确认和取消接口必须使用对应 `task:*` 权限。

## 5. 本文封板时尚未实现

本切片不应被描述为正式 `preview_*` 工具或 L3 写能力。以下能力仍未实现：

- 版本化 `preview_task_transition` GoalContract；
- 不可变预览摘要、过期时间和确认 token；
- 持久化幂等键；
- preview 与 execute 间的实体版本/状态冲突检查协议；
- 可恢复的持久化 HITL；
- Agent `execute_*` 工具；
- 主动触发、自动批量执行或无人值守写入。

下一阶段应先把本次 UI 跳转作为边界样例冻结，再从单一任务类型设计正式 preview 合同；L3 继续保持 `NO-GO`。
