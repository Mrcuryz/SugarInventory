## 本次实现

- 仍沿用模型理解 → 化验专家 → `preview_assay_entry` → 结果分析。模型不获得保存工具，工具数量仍为 61 个 Goal / 56 个 Java 工具。
- 人工页面单独调用受控确认接口。只有 `assay:view` 且具备 `assay:create` 或 `quality:test` 的用户显示入口；服务端仍重新鉴权。
- 预览工具返回 `confirmationAvailable`。关闭功能时不生成可保存动作；开启时返回既有 `AgentEntityRefCodec` 签名产品引用。引用限定用户、用途、类型和有效期，不进入模型事实。
- 新增 `POST /api/agent/sessions/{sessionId}/assay-entry/previews/from-product`，请求为 `{productRef, values:{sampleDate, 七项已填指标}}`。服务端校验引用后解析产品，拒绝客户端另传产品 ID，再生成精确存档。已有 `/previews` 不变。
- 浏览器显示存档后的产品、日期、七项指标、已有/拟新增版本及服务端判定；确认、执行只传服务端引用或凭据，不重传业务值。成功后采用实际保存结果，不把预览当成功。
- 保存过程禁止重复提交。执行响应不确定时先回查，无法核实则阻止盲目重试。新消息会使旧未保存预览失效，已存档预览先查结果再取消。
- 取消后隐藏保存入口；保存后显示实际版本且不再显示保存按钮。较矮窗口下弹窗正文独立滚动，确认按钮保持可见。

执行开关为 `AGENT_ASSAY_ENTRY_EXECUTE_ENABLED`，默认 false；隔离启动脚本新增显式 `-EnableAssayEntryExecute`，没有变更生产环境配置。

## 验收中发现并修复的问题

1. **确认按钮缺失**：公开响应过滤器会删除原始 `productId`，使初版卡片无法构造请求。改用已有签名实体引用，不放宽全局过滤规则、不使用隐藏字段绕过。
2. **模型仍称没有保存操作**：区分“模型没有保存工具”和“页面支持人工保存”，增加事实指引与结果校验。
3. **把保存化验说成入库**：真实模型曾输出“如需入库，请在预览卡片上核对并保存”。已补业务边界指引及回归校验；修复后的两轮真实模型输出正确区分化验保存与产品入库。
4. **弹窗按钮超出矮窗口**：限制正文高度并保留滚动；修复后 1037×703 窗口截图中取消/确认保存按钮可见。
5. 本地启动曾因两项迁移未登记而被 readiness 拒绝，随后使用标准迁移脚本在本地补齐登记/迁移。最终 readiness 为 50 项迁移通过，没有关闭校验。
