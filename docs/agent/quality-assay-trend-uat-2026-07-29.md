## 1. 验收边界

本次验收只回答“已经登记的化验记录如何判定和变化”，不回答尚无事实支撑的生产批次化验覆盖率、质量原因、改善/恶化结论或预测。

权威口径保持为：

- `assay.sample_date` 是生产日期，按北京时间解释相对日期；
- 合格率固定为 `PASS / (PASS + FAIL)`；
- 无标准、标准多候选和缺少受控判定的记录不进入合格率分母，必须单独展示；
- 历史判定按每条记录当时实际采用的标准名称和版本展示，不使用当前标准重算历史；
- 报表只统计已经登记的化验记录，不能据此推断哪些历史生产批次缺少化验；
- 单次最多查询 366 天；31 天以内按日聚合，更长范围按月聚合；
- 核心数字由 Java/SQL 确定性聚合，模型负责理解范围、选择登记报表并分析受控结果。

## 3. 验收中发现并修复的缺陷

| 缺陷 | 影响 | 修复 |
|---|---|---|
| 新增质量报表 Mapper 不在 `@MapperScan` 范围 | 单测通过但整包启动失败，质量报表服务无法创建 | 将 `analytics.mapper` 纳入应用 Mapper 扫描；重新打包并执行启动级验收 |
| MCP 可执行包未随源码变更重新构建 | Java 报表接口直接返回 2 条，但 Agent 卡片被旧响应模型映射成 0 条 | 重建 `warehouse-mcp-0.1.0-exec.jar`，结束旧会话并让新会话加载新包 |
| 稀疏/空数据卡片展示所有零记录日期 | 30 天空结果产生 30 行无效信息，关键事实被淹没 | 后端继续保留完整时间序列；前端只呈现有记录的日期或月份，空结果只显示权威空状态 |

## 5. 性能与限制

本轮真实模型回答约为 18～37 秒。进度阶段会先于最终结果出现，但当前速度仍不应视为达标；样本量也不足以形成正式 P50/P95。后续应通过 Agent 审计中的主模型、专家模型、工具调用和整轮耗时做可重复统计，优先减少不必要的模型往返。
