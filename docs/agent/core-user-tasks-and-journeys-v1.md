# Agent 核心用户任务与多轮旅程 V1

状态：`PRODUCT_HYPOTHESES / CORE10_CONTRACTED / READONLY51_CONTRACTED / FIELD_VALIDATION_IN_PROGRESS`

日期：2026-07-23

## 1. 使用边界

以下十项来自产品判断、现有页面和代码能力，不是已经由真实用户研究证明的“真实需求”。在仓管、质检和生产主管完成现场任务测试前，应称为“高优先级用户任务假设”。

当前已为十项核心任务建立 17 个核心目标合同；全系统 52 个 L1 只读工具已归入 43 个用户目标合同。一个用户任务可以对应多个不同完成语义，例如 T09 的“满足完整标准”和“单个原始指标满足条件”必须使用两个合同，不能合并为模糊的质量查询。

目标合同不是按 MCP 工具逐个生成。Resolver、目录发现和详情下钻可以作为 `supportingTools` 归属目标；只有 `evidenceTools` 的安全结果可以形成 FactEnvelope 和目标完成证据。机器可读全量登记见 `readonly-goal-contract-registry.yaml`。

## 3. 十项核心任务的 17 个 GoalContract

### G01 `CURRENT_PRODUCT_INVENTORY`

- 对应任务：T01。
- 必需实体：唯一 `PRODUCT`。
- 必需事实：`CURRENT_PRODUCT_INVENTORY`。
- 允许工具：`resolve_products`、`get_inventory_overview`。
- 完成：权威库存事实为 `AVAILABLE` 或明确 `NO_DATA`。
- 不完成：产品歧义、事实字段不完整、工具失败。

### G02 `PRODUCT_INVENTORY_DISTRIBUTION`

- 对应任务：T02。
- 必需实体：唯一 `PRODUCT`。
- 必需事实：`PRODUCT_INVENTORY_DISTRIBUTION`。
- 允许工具：`resolve_products`、`get_inventory_distribution`；旧库存总览的 locations 仅作兼容。
- 完成：返回按库位分组的当前库存分布，或明确无匹配库存。
- 限制：不是历史库存流水。

### G03 `WAREHOUSE_INVENTORY_DISTRIBUTION`

- 对应任务：T03。
- 必需实体：唯一 `WAREHOUSE`。
- 必需事实：`WAREHOUSE_INVENTORY_DISTRIBUTION`。
- 允许工具：`resolve_warehouses`、`get_inventory_distribution`。
- 完成：返回库位内按产品分组的当前库存，或明确空库位。
- 限制：不自动包含批次化验或质量放行结论。

“库位库存 + 化验”仍是受控复合配方，不合并成单一库存事实。当前 `inventory_current_assay_fact_v1` 可用于不合格库存、指定标准和原始指标筛选；普通库位库存旅程仍不得把“产品最近化验”冒充当前库存批次质量。

## 4. 五条完整多轮旅程

### J01 产品库存与质量旅程

`T01 产品库存总览 → T02 产品库存分布 → T04 批次化验 → T10 异常 → 后续针对性处理`

- 当前可完成：库存总览、分布、单批次化验，以及当前不合格库存/指定标准/原始指标筛选。
- 受控上下文：产品可复用；单份化验详情使用 Runtime 保存的受控报告引用。
- 停止条件：没有化验、无适用标准或标准多候选时，不得表述为不合格。

### J02 库位盘点与质量旅程

`T03 库位库存 → 筛指定产品 → T04 批次化验 → T10 异常 → 后续处理`

- 当前可完成：库位库存、产品筛选，以及限定库位范围的当前库存质量筛选。
- 上下文变化：从库位范围缩小到单产品/批次；不得在追问中扩大到全部库位。
- 停止条件：要求单份报告详情时，产品存在多个生产日期必须选批次；聚合质量筛选可直接返回多个批次卡片。

### J03 生产批次与产出去向旅程

`T07 煮糖批次 → 生产订单 → 原料消耗与产出 → T06 产出入库去向 → 报表/趋势/计划`

- 当前查询：登记追溯节点、订单进度和实际领料/产出。
- 未确认能力：损耗率、产出率、趋势归因和下一生产计划。
- 停止条件：不能用未确认公式生成生产建议。

### J04 托盘生命周期旅程

`托盘现状 → 当前轮次流转 → 历史轮次 → 流程效率分析`

- 当前查询：托盘状态、库存、任务和登记流转。
- 已验收路径：通过 `pallet_expert` 验证“明确托盘码查现状 → CURRENT_PALLET 受控引用查历史流转”，并分别登记托盘现状和历史流转目标。
- 未确认能力：流程效率指标和扫描日志完整性。
- 停止条件：没有登记事件时只能报告证据缺口，不能推断实际没有发生。

### J05 化验与趋势旅程

`T04 产品/生产日期化验 → 具体指标合格情况 → 历史化验 → 报表/趋势分析`

- 当前查询：单批次最新版本、历史版本/记录、已保存判定。单产品 + 生产日期查询直接返回可展开/收起的完整报告卡，不再要求用户追问指标和标准。
- 开发期试点：已验证“产品 + 生产日期化验 → 最近 30 天记录 → 展开第一条指标”；真实 `recordRef` 只保存在 Runtime 状态，模型仅使用 `CURRENT_ASSAY_REPORT`。历史列表使用摘要卡，避免默认展开长时间范围内的全部指标或产生 N+1 查询。
- 展示语义：`NO_STANDARD` 不得直接展示，也不得表述为合格或不合格；统一说明为“未配置适用标准，暂无法判定”。
- A 标准命中与 B 原始指标条件必须分开表达。
- 停止条件：历史记录列表不能冒充趋势分析；按当前标准重算历史化验必须进入 L2 预览。

上述合同实现和自动化回归不等于全部真实角色 UAT 已完成。库存、化验、生产和托盘已有浏览器验收证据；十项任务仍需按仓管、质检、生产主管形成统一验收矩阵。

## 5. 完成定义

一个目标只有同时满足以下条件才是 `COMPLETE`：

1. 所需实体已唯一解析，或用户明确选择。
2. 所需 FactEnvelope 存在且 schema 有效。
3. `NO_DATA` 与 `TOOL_ERROR` 被严格区分。
4. 事实范围没有在多轮追问中被悄悄扩大。
5. 回答引用的是安全事实，不是展示标签、旧上下文或模型常识。

模型可以负责理解、工具选择建议和自然语言反馈，但不能覆盖上述完成门禁。

合同中的 `allowedTools` 定义整个目标可用的最小工具集合；`evidenceTools` 只包含能够证明目标完成的主查询工具。解析候选和目录发现即使调用成功，也不能让 CompletionEvaluator 宣布目标完成。
