# 03 产品、批次、托盘、库位关系

## 基本关系

- 产品表示库存的业务对象，规格用于区分同名产品的包装、重量和板件换算。
- 批次用于追溯生产、入库或质量来源，常与生产日期、化验记录有关，但不能简单等同。
- 托盘承载具体库存，托盘上通常包含产品、规格、数量、库位、状态和流转信息。
- 库位存放托盘或库存，是回答“货在哪”“某库位有什么”“容量还剩多少”的关键对象。
- 化验状态通常与产品和日期 / 批次相关，也可能由托盘库存上下文间接关联。

## 产品与规格

用户说“黄冰糖”时可能表示：

- 一个产品大类；
- 名称为“黄冰糖”的多个规格；
- 某一个具体规格，例如“黄冰糖（袋）”。

如果 resolver 返回多候选，必须让用户选择或说明当前支持的范围，不能自行选择。跨规格汇总时不要虚构统一板数，应使用总件数、总重量或“跨规格”摘要。

## 批次、日期与化验

- 批次可用于追溯库存来源，但当前只读工具不保证支持任意批次查询。
- 用户问“今天有没有化验”“某日期是否合格”时，应识别日期并查询化验状态。
- “无化验”是风险提示，不等于自动禁止出库；最终能否出库需业务制度和人工流程确认。

## 上下文指代

用户说“这个 / 它 / 这些 / 刚才那个 / 该产品 / 这个库位”时：

1. 优先使用结构化会话状态中的最近产品、库位、托盘或化验上下文。
2. 若上下文唯一且仍符合当前问题，继续只读查询，不要求用户重复输入。
3. 若上下文缺失、过期或存在多个候选，只问一个最关键问题。
4. 不得把自然语言指代映射为内部 ID；内部实体必须来自 resolver、候选选择或已保存的结构化状态。

示例：

- 上轮查了“黄冰糖（袋）库存”，用户追问“这些在哪些库位？”：沿用该产品，查库存分布。
- 上轮查了“1号库位有什么”，用户追问“这个库位满了吗？”：沿用 1号库位，查库位状态。
- 没有上下文时用户问“它今天化验了吗？”：追问“你想查哪个产品的化验？”
