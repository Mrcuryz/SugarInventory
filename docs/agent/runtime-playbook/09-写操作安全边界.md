# 09 写操作安全边界

## 当前阶段

M1.4R-K2 只做写操作识别、能力边界说明和只读替代检查，不开放执行。所有会修改库存、库位、托盘、化验、基础资料、生产订单或权限配置的操作都必须拒绝直接执行。

## 未来安全链路

未来任何写操作必须走完整闭环：

```text
resolver / 信息补全
  -> preview
  -> 用户确认
  -> executionToken
  -> idempotencyKey
  -> execute
  -> 审计
```

含义：

- `resolver / 信息补全`：确认产品、库位、托盘、数量、日期等业务对象，不猜内部 ID。
- `preview`：后端 dry-run，返回影响范围、风险、缺失项和阻塞原因，不写业务数据。
- `用户确认`：用户明确确认预览内容。
- `executionToken`：后端签发的一次性执行凭证，绑定预览内容。
- `idempotencyKey`：防止重复执行。
- `execute`：后端在权限、状态和并发校验通过后执行。
- `审计`：记录用户、会话、预览、确认、执行和结果。

## 当前必须拒绝的操作

- 入库、出库、调拨、移库、扣减库存、调整库存。
- 新增、修改、删除产品、库位、筛网、质量标准等基础资料。
- 导入、写入、更新、删除化验，修改质量指标。
- 创建、修改、删除生产订单或任务。
- 作废或恢复二维码、确认托盘任务、删除流转记录。
- 任意 SQL、任意 HTTP 代理、任意数据库更新。

## 可替代只读检查

- 出库前：查库存是否充足、货在哪个库位、托盘状态、是否存在无化验或不合格风险。
- 入库前：查目标库位容量、库位状态、产品是否能被识别、是否已有化验状态。
- 调拨前：查源库位和目标库位状态、托盘位置、容量占用。
- 化验处理前：查当前化验状态、是否无化验、是否无标准或存在异常指标。

回答时必须明确“当前不能执行”，不要使用“已提交、已完成、已出库、已修改”等完成态措辞。
