# 10 常见失败案例

这些案例来自真实页面验证和 Review Lite 反馈，用于后续回归测试和 playbook 修订。

| 失败场景 | 错误表现 | 正确处理 | 建议归因 |
| --- | --- | --- | --- |
| 用户问“你是什么？” | 误判为库存缺参，要求补产品、库位、托盘码 | 判为 `capability`，直接回答助手身份和能力边界 | `INTENT_MISS` |
| 用户问“你现在能做什么？” | 误判为库存查询，进入业务缺参兜底 | 判为 `capability`，不调用工具，不反问业务参数 | `INTENT_MISS` |
| 用户问“查一下库存” | 一次要求产品、库位、托盘码、生产日期 | 判为 `ambiguous`，只问按产品还是按库位查，并给示例 | `CLARIFICATION_TOO_BROAD` |
| 用户问“1号库位有什么？” | 查成库位容量或只回答状态 | 判为库位库存内容，走 `resolve_warehouses -> get_inventory_distribution` | `TOOL_SELECTION_MISS` |
| 用户问“1号库位满了吗？” | 查成该库位产品分布 | 判为库位容量 / 占用率，走 `resolve_warehouses -> get_warehouse_status` | `TOOL_SELECTION_MISS` |
| 用户问“帮我出库” | 误判为托盘查询缺 `PALLET_CODE` | 判为 `write_operation`，`business_domain=outbound`，`planned_tools=[]`，说明不能执行并给只读检查路径 | `INTENT_MISS` |
| 工具结果非空 | 回答“暂无数据” | 用工具安全摘要组织回答；若无法渲染，记录展示问题 | `ANSWER_SYNTHESIS_MISS` |
| 只调用 resolver | 解析库位或产品后直接结束 | resolver 成功后必须继续主查询；多候选才暂停追问 | `TOOL_NOT_CALLED` |
| 用户说“这些在哪些库位？” | 没有使用上轮产品上下文 | 使用结构化会话状态；缺上下文才追问 | `CONTEXT_NOT_USED` |
| 用户反馈“数据不对” | 继续重复原回答或当作闲聊 | 判为 `feedback`，记录 Review，并引导用户提供期望范围或重新只读查询 | `USER_FEEDBACK` |
| 工具失败或权限失败 | 被解释成“没有库存” | 说明查询失败，不能把失败当作无数据 | `ERROR_HANDLING_MISS` |
| 普通 UI 展示内部字段 | 出现 toolName、productId、warehouseId、raw JSON、SUCCESS | 普通 UI 只展示业务回答和安全卡片；调试信息仅管理员可见且脱敏 | `SECURITY_PRESENTATION_MISS` |

## 反哺规则

- Review Lite 中出现 `TOOL_NOT_CALLED`、`INTENT_MISS`、`CONTEXT_NOT_USED`、`ANSWER_SYNTHESIS_MISS` 的高频案例，应补充到本文档。
- 每个新增失败案例至少补一个行为断言，不做过度精确文案断言。
- 文档只记录安全摘要和业务字段，不记录 raw tool result、token、Authorization、堆栈或 chain-of-thought。
