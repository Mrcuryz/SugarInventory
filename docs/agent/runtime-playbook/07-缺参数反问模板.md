# 07 缺参数反问模板

## 原则

- 一次只问一个最关键问题。
- 给一到两个贴近业务的例子。
- 不要一次要求产品、库位、托盘码、生产日期全部补齐。
- 只在用户明确发起库存、库位、托盘或化验查询且确实缺范围时反问。
- 不要对 `capability`、`smalltalk`、`write_operation`、`unsupported`、`unrelated`、`feedback` 使用业务缺参兜底。

## 常用模板

| 场景 | 模板 |
| --- | --- |
| 库存缺查询范围 | 你想按产品查，还是按库位查？例如：黄冰糖（袋）库存，或 1号库位有什么。 |
| 产品库存缺产品 | 你想查哪个产品的库存？例如：黄冰糖（袋）库存。 |
| 库位内容缺库位 | 你想查哪个库位？例如：1号库位有什么。 |
| 库位容量缺库位 | 你想查哪个库位的容量或占用率？例如：1号库位满了吗。 |
| 托盘查询缺托盘码 | 请提供托盘码，我可以帮你查托盘位置、产品、数量和状态。 |
| 化验查询缺产品 | 你想查询哪个产品的化验？例如：黄冰糖（袋）今天有没有化验。 |
| 化验查询缺日期 | 你想查哪一天的化验？例如：今天，或 2026-07-08。 |
| 上下文指代缺失 | 你说的“这个”具体指哪个产品、库位或托盘？可以发产品名、库位名或托盘码。 |
| 产品多候选 | “黄冰糖”有多个规格，你想查哪一个？请选择具体规格后我再继续查。 |
| 库位多候选 | 这个库位名称匹配到多个候选，请选择具体库位后我再继续查。 |

## 不应使用的反问

- “请补充产品、库位、托盘码或生产日期”过宽，只能作为内部兜底思路，不能直接展示给用户。
- 对“你现在能做什么？”反问产品或库位。
- 对“帮我出库”反问托盘码并暗示可以执行出库。
- 对无关问题要求补业务参数。
