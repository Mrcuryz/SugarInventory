# 04 库存查询规则

## 查询口径

- “某产品库存”：先解析产品，唯一确认后查产品库存概览。
- “某产品在哪些库位 / 分布在哪”：先解析产品，唯一确认后查库存分布，按库位聚合。
- “某库位有什么 / 有哪些产品 / 放了什么”：先解析库位，再查该库位的全部产品库存分布，按产品聚合。
- “某库位还有多少容量 / 满了吗 / 占用率多少 / 状态怎样”：先解析库位，再查库位状态。
- “某托盘在哪 / 什么状态”：需要托盘码，调用托盘状态查询。
- “某产品今天有没有化验 / 是否合格”：先确认产品和日期，再查化验状态。

## 缺范围处理

用户只说“查一下库存”“看下库存”“库存怎么样”时，业务方向明确但范围不足。只问一个关键问题：

> 你想按产品查，还是按库位查？例如：黄冰糖（袋）库存，或 1号库位有什么。

不要一次要求产品、库位、托盘码和生产日期全部补齐。

## 库位内容与库位容量

必须区分两个问题：

- “1号库位有什么？”问的是该库位当前库存 / 产品 / 托盘分布，应走 `resolve_warehouses -> get_inventory_distribution`。
- “1号库位满了吗？”问的是容量、占用率、剩余容量，应走 `resolve_warehouses -> get_warehouse_status`。

如果用户同时问“1号库位有什么，满了吗”，可以先查库存分布，再补查库位状态；回答中分开说明库存内容和容量状态。

## 产品范围

- 具体产品规格：需要唯一产品或用户选择。
- 产品名称组或产品大类：必须来自 resolver 支持的范围或用户候选选择，不能模型自行构造。
- 全部产品：仅在工具支持的受控聚合范围内使用，例如明确库位的“这个库位有什么”或用户明确问“全部产品库存分布”。

## 日期、批次和状态

- 日期可用于化验状态或受控过滤；如果用户说“最近30天化验趋势”，当前批量趋势分析不支持，应说明能力缺口。
- 批次可以作为业务对象识别；没有支持工具时不能假装查询成功。
- 无化验、不合格、无标准等状态可以作为风险提示或过滤条件，但不能作为写操作放行结论。

## 结果表达

- 正文只做摘要，不重复卡片明细。
- 明细优先放在业务卡片或列表。
- 风险信息只提示一次，避免正文、卡片、底部重复。
- 工具返回非空时不得回答“暂无数据”；工具失败时不得解释为空数据。
