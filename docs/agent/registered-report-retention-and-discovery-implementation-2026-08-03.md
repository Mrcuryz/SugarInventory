# AI 助手能力发现与登记报表生命周期收口（2026-08-03）

## 1. 目标与边界

本切片补齐两个用户体验和运行治理缺口：

1. 用户打开 AI 助手时能够直接看到高价值问题示例，不必先理解系统有哪些 Agent 或工具；
2. 已超过 30 天有效期的 `ReportRun` 不再只依赖读取时拒绝，而是由后台任务分批物理清理并留下运行审计。

本切片没有新增 GoalContract、MCP 工具、业务指标或写入业务数据的能力，也没有改变既有 Agent 架构。推荐问题只是自然语言入口，后续仍严格经过“主模型理解 → 专家决策 → 工具调用 → 结果分析”。

## 2. 能力发现

AI 助手空会话展示以下四条可点击推荐问法：

- 今天整体运营情况如何？
- 查看当前待处理任务
- 查看最近30天化验质量趋势
- 查看最近30天生产领料和产出趋势

推荐项覆盖当前最有价值且已登记的任务、质量、生产和跨域当日概览。点击后使用现有 `send` 链路发送普通用户消息，不引入前端关键词路由、固定工具调用或特殊权限。

真实浏览器首轮曾使用“查询黄冰糖当前库存总览”作为推荐项。模型正确选择库存专家和产品解析工具，但把工具参数生成成“黄冰糖总览”，暴露出解析器会把展示意图尾词误当产品名的问题。MCP 产品解析入口现会在调用产品 API 前剥离末尾的“当前库存总览、库存总览、当前库存概览、库存概览、总览、概览”，且保留非空校验和原有候选选择语义。该修复不改变模型决策或权限边界。

修复后浏览器复验已恢复黄冰糖多候选卡片；继续选择具体产品时又发现现有会话引用会提示“该选择已失效”。该问题不属于能力发现或报表清理，不能因为候选卡已显示就宣称产品多轮链完整通过。为避免把已知不稳定链路置于首页推荐位，本切片将该项替换为已封板的“查看当前待处理任务”；产品选择引用另行排查。

欢迎语、入口副标题和输入框占位同步说明库存、库位、托盘、化验、生产和运营报表能力。发送首条消息后推荐项隐藏，避免持续占用会话空间。

## 3. 权限结论

当前 AI 助手入口在前端和 Java Gateway 均只允许 `ADMIN`、`SUPER_ADMIN`，本切片不擅自扩展角色。

“今天整体运营情况如何？”继续采用全有或全无策略：用户必须同时拥有当日生产、化验质量、生产领用—产出、当前库存和当前待处理任务五个事实分支所需权限，才可运行和重开该报表。不能把无权限分支伪装为空数据，也不在本切片实现部分权限概览。

## 4. 过期快照清理

### 4.1 清理对象

清理任务只删除满足 `expires_at <= cutoffAt` 的 `agent_report_run` 记录。候选先按到期时间和主键排序并限制批量大小，删除时再次校验到期条件，避免把选择后发生变化的有效记录误删。

以下内容不会被本任务删除：

- `agent_report_export_audit` 导出审计；
- 库存、生产、化验和任务等业务表；
- 未到期或没有进入本批次的 `ReportRun`。

导出审计当前继续保留。项目尚未定义其法定或业务保留期限，在策略明确前不能把它和 30 天报表载荷生命周期等同处理。

### 4.2 调度与配置

默认按北京时间每日 02:30 执行，每批最多处理 1000 条，可通过以下环境变量调整：

- `AGENT_REPORT_CLEANUP_ENABLED`：是否启用，默认 `true`；
- `AGENT_REPORT_CLEANUP_CRON`：Spring cron，默认 `0 30 2 * * ?`；
- `AGENT_REPORT_CLEANUP_BATCH_SIZE`：批量大小，默认 `1000`，代码上限 `5000`。

服务夜间停机不会导致数据错误：过期快照在读取时本就被拒绝，下次服务运行到调度时间时继续清理。若部署环境需要在启动后立即补清，应该增加受权限保护的一次性运维入口或外部任务，不应把任意清理接口暴露给 Agent。

### 4.3 清理审计

迁移 `migrations/2026-08-03-add-agent-report-cleanup-audit.sql` 新增 `agent_report_cleanup_run`，记录：

- 清理运行引用和截止时间；
- 请求批量大小、选中数量和实际删除数量；
- `STARTED`、`SUCCESS` 或 `FAILED` 状态；
- 开始、完成时间和受限长度的失败原因。

正常清理在同一事务内写入开始和完成状态。调度异常由独立事务记录失败；失败内容会移除换行和控制字符并限制为 500 字符，不记录报表正文、用户问题、模型内容或凭据。

## 5. 验收证据

- `RegisteredReportRetentionServiceTest`：覆盖有数据清理、空批次、批量上限和失败信息清洗；
- `RegisteredReportRetentionTaskTest`：覆盖成功调度及异常不逃逸、失败审计；
- `RegisteredReportArchiveServiceTest`：回归 30 天有效期、所有者、权限、哈希和今日概览五权限边界；
- `WarehouseToolsTest`：覆盖产品解析剥离“总览/概览”意图尾词后再查询产品；
- 前端生产构建：验证推荐问题与响应式样式可编译。

真实浏览器已验证四条推荐问题在空会话各显示一次，点击后推荐区立即隐藏并生成普通用户消息；“查看当前待处理任务”完整返回 6 条真实待处理记录及按类型分组卡片，并明确未执行任何业务写操作。本地登录、Java/Python 双向鉴权、SSE 连接和 MCP 运行制品校验均正常。产品候选选择引用问题按上文保持为独立待修复项。

真实非零五领域数据的浏览器验收不能用虚构业务记录替代。当前自动化测试已覆盖非零综合事实；真实环境应在当天五个分支均有实际数据时补做一次 UAT，并记录原始问法、五区块事实和导出一致性。
