## 2. 复用接口和计算规则

仍调用 `POST /api/analytics/agent-read/reports/run`，定义 `production_daily_report_analysis_v1@1`。在原有日期、车间、产品参数上增加后端支持：

```json
{
  "reportDefinitionId": "production_daily_report_analysis_v1",
  "reportVersion": 1,
  "startDate": "2026-09-08",
  "endDate": "2026-09-10",
  "departmentName": "多晶车间",
  "productQuery": "黄冰糖",
  "comparisonMode": "PREVIOUS_PERIOD"
}
```

该输入前期为09-05至09-07。自定义模式 `CUSTOM` 必须同时提供比较起止日期，两个期间等长、不重叠、各不超过31天，不查未来。不允许前期模式夹带自定义日期，孤立日期也拒绝。参数错误在日报聚合读库前拒绝。

比较期复制同样的车间和产品筛选，读取相同日报聚合。按现有 `seriesKey` 匹配，不能按显示名称合并不同单位、分类、状态或车间。取两期系列并集，单边缺失保持null，不补0；每期最多10个系列，比较最多20个维度、40项数量/折吨指标。系列截断时停止计算所有变化率，提示缩小范围。

每个维度单独比较数量和已保存折吨；能耗保持原单位，无折吨。两期有值时可返回已记录值差额。只有两期对应指标覆盖所有日期、所有记录行均有值、无系列截断、基期值大于0时才计算百分比；缺值/缺日不计算日均。数量完整不意味着折吨完整，反之亦然。草稿本身不作缺失处理，但标明包含未提交数据。

差额为本期减前期；变化率为差额除前期乘100，后端计算并保留最多4位小数。不对不同维度加总，不据此推出损耗、质量、效率、原因或预测。前期质量提示带“对比期”前缀进入快照的数据质量说明。

`comparison.metrics`复用已有字段：名称/单位、本期值/前期值、差额/变化率、条件满足时日均、说明。说明包含两期各自的覆盖行数/天数。原v1无比较快照仍可读取与导出，版本不变。

## 3. 本轮发现并修正的问题

1. 原通用比较的查询复制遗漏新加的 `departmentName`，会导致跨车间比较。现复制并在日报比较前核对两期筛选标签。
2. 日报XLSX分支提前返回，比较表在后面不会输出。现先输出共同比较表，再生成日报工作表；补充“比较说明”工作表。
3. 原通用变化率逻辑没有日报覆盖门槛，且允许负基期。本次以小型日报比较策略复用响应契约，不改变旧报表数值语义。
4. 单看本期质量会漏掉前期缺失；现汇集前期质量说明。
