# 化验录入 D2c：人工确认与受控保存后端

日期：2026-09-24。范围：单产品、单采样日期的受控新增化验。当前是后端增量，不代表完整对话录入已验收或已上线。

## 实现边界

- 继续沿用模型理解 → 化验专家 → 只读预览工具 → 结果分析。新增接口只供登录用户操作，不注册为 MCP 工具，不加入 Agent 委托路径白名单；仍为 61 个 Goal、56 个 Java 工具。
- `agent.assay-entry.execute-enabled` 默认 `false`。关闭时控制 Controller 不注册，服务层确认/执行也拒绝调用。没有打开现有本地运行服务或服务器上的写入开关。
- 精确预览保留 5 分钟；确认凭据最长 2 分钟，且不晚于预览到期。凭据绑定用户、会话、预览内容及到期时间，数据库只保存凭据摘要。签名复用已有实体引用密钥配置，但采用独立用途前缀。
- 用户确认不会写入化验。执行只接受服务端凭据与幂等键，不接受再次提交的产品、日期、检测值或判定结果。
- 确认和执行均核对当前权限、会话归属、预览完整性、现有版本以及完整标准依赖。已有化验或标准变化时必须重新预览，不自动覆盖。
- 会话行锁序列化同会话的确认、执行、替代和取消；产品行锁与既有 Web 化验写入共用。保存使用已锁定状态下的判定，避免重新进行普通快照查询。
- 化验新增、成功结果与成功审计在同一事务内提交。重复确认返回同一凭据，重复执行返回同一记录，不新增版本；网络异常后可回查保存结果。
- 保存后的质量警告继续保留；仅将“尚未保存”提示替换为“已保存”。取消和替代后旧凭据不可执行。成功结果可在预览到期后回查，但仍要求当前用户权限及有效会话。

## 接口清单

统一前缀：`/api/agent/sessions/{sessionId}/assay-entry`。需要登录、Agent 使用权限（管理员沿用既有豁免）以及 `assay:view AND (assay:create OR quality:test)`；服务层再从数据库读取实际权限。

| 方法与路径 | 输入 | 返回与业务影响 |
|---|---|---|
| POST `/previews` | 单产品、采样日期、七项可选实测指标；至少一项 | 服务端精确预览、引用、到期时间；只写控制存档，替代同会话旧活动预览 |
| POST `/previews/{ref}/confirm` | 无业务载荷 | executionToken、idempotencyKey、到期时间；只登记用户确认，不写化验 |
| POST `/previews/{ref}/execute` | 仅 executionToken、idempotencyKey | 实际化验 ID、版本、保存时间及详情；事务内新增一版 |
| GET `/previews/{ref}/result` | 无 | 已保存结果，或尚未保存/已取消/已失效/已过期；不触发业务写入 |
| POST `/previews/{ref}/cancel` | 无 | 取消当前 READY/CONFIRMED 预览；不删除已保存化验 |

响应沿用 `Result<VO>`；错误码 1054～1059 分别覆盖预览失效、状态变化、权限、会话、确认凭据、功能关闭。控制层内部状态不作为界面文案。禁止在日志中记录执行凭据。

新增迁移 `migrations/2026-09-24-agent-assay-entry-execution.sql` 仅增加确认结果表及审计表，未修改 assay 业务表或授予账号权限。该迁移已由本地数据库测试执行；未连接生产数据库。
