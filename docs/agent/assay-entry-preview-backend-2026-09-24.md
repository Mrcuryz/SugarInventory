# 化验录入 D1a：后端只读预览

日期：2026-09-24。状态：后端预览已完成本地接口验收；MCP适配及专项测试已实现但未注册开放。D1整体尚未完成，尚未接入Agent目标、候选交互或前端卡片。无化验写入/执行令牌，未部署生产。

## 接口与边界

新增`POST /api/assay/entry/preview`，请求DTO为`AssayEntryPreviewDTO`，响应为`Result<AssayEntryPreviewVO>`。权限必须同时满足`assay:view`和`assay:create`/`quality:test`二者之一。不授予新权限、不修改账号、不将新增入口设为公开。

请求只接受具体产品ID、采样日期及现有七个检测字段。ID在将来的Agent链路中必须由受控产品候选确定，不能让模型猜测。未知字段（包括旧导入的`selectType/relatedId`）拒绝，不静默忽略化验组意图。

数值先通过共享校验器，保留未填项和0；严格检查数据库有效小数位与整数位，不自动舍入。五项现有非负限制及pH0～14保留；不新增科学上限或单位换算。至少提供一个实测值是本受控入口的输入完整性要求，不改旧导入表单的业务规则。采样日期不由后端默认补今天，不凭空增加未来日期禁用规则，仅校验可存储范围。

预览服务标记只读事务，仅调用产品查询、化验最新版本/MAX版本查询及现有`AssayStandardJudgeService.judge`。不调用`importAssays/updateAssay`或Mapper写方法。由于现有“最新”按创建时间排序，若与MAX版本不一致则拒绝预览，避免拟新增版本与旧写逻辑冲突。

输出包括产品名称及规格、日期、7项实测值与是否已填、已有/拟新增版本、中文预判、采用标准名称和版本、未通过指标及原因。单位仅取采用标准的明确唯一单位；无标准时不虚构。现有判定服务的无标准、多个匹配标准、缺少检测值原样保留语义。

`previewOnly=true`始终成立，响应明确提示未保存，**不签发快照引用、确认令牌或执行凭据**。拟新增版本仅是当前读到状态的预估，不能直接作为后续写入授权。D2还需控制快照、版本/标准重检、幂等、事务、当前权限及审计。

新增业务码：1051输入无效、1052版本状态冲突、1053无法取得判定。控制器基本Bean Validation失败沿用业务400封装，不把HTTP200等同成功。

## 测试记录

- `AssayEntryInputValidatorTest`：有效小数精度、存储上限、非负/pH边界、0/空值、日期/产品缺失、未知/化验组字段、输入不变性。
- `AssayEntryPreviewServiceTest`：四类既有判定、7个指标完整展示、标准单位、缺测原因、新增版本提示、版本不一致/溢出、缺产品/缺判定、只读事务及无Mapper写调用。
- `AssayEntryPreviewPermissionTest`：实际Spring方法鉴权代理验证5种不完整权限拒绝，2种合法组合允许；不是只做注解字符串检查。
- 现有`AssayStandardJudgeServiceImplTest`保持通过，不重写判定算法。
- 第一次专项运行测试桩错误模拟了SQL MAX空结果（Mockito默认Integer为0），导致5项失败。改为显式NULL并新增不一致状态测试，未放松正式版本检查。
- 第一次全量回归发现旧`AgentReadPermissionMatrixTest`未纳入已实现的日报查看权限。核实控制器和归档逐报告权限后同步断言；没有修改正式权限。

真实本地HTTP验收脚本：`scripts/verify-assay-entry-preview.ps1`。仅SELECT与预览调用，不创建测试化验。每项保存完整请求/响应；测试前后核对化验总行数、最大ID、版本和，此聚合检查不冒充逐字段指纹。
