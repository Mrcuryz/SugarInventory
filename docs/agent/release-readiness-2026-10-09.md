## 发布与回滚方案

1. 保存当前完整发布版本、镜像标识和配置备份，完成数据库备份及可恢复性检查；保留所有敏感内容在服务器。
2. 核对迁移账本与结构，仅执行确认缺失的发布迁移。
3. 将同一份当前源码构建的 Java、MCP、Python、Web 产物组成版本包并记录哈希，排除本地环境文件、测试夹具和数据库内容。
4. 验证新 Python 镜像与线上 RAG 资源、Java Gateway 和 Redis 的兼容性；保留模型主导架构，不退回旧路由。
5. 成组切换并检查健康、鉴权、协议握手、日报查询、化验查询和口语化录入预览。
6. 化验执行只对已有相应权限的账号开放，不向全体仓管批量授权。开启 `AGENT_ASSAY_ENTRY_EXECUTE_ENABLED` 前确认权限及人工确认流程。
7. 生产真实保存测试必须使用获准的测试对象；未获准时只做查询和预览，不向真实产品写入虚构化验。真实保存的验收边界需明确记录。
8. 如健康或兼容性检查失败，回滚成组产物和配置；保留新增控制表及审计，不用删数据回滚。
