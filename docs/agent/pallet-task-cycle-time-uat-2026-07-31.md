# 托盘任务处理耗时趋势验收记录

## 1. 验收边界

本报表只描述系统已登记托盘任务的处理耗时，不代表现场全部流程效率，也不用于员工绩效、责任归因或 SLA 逾期判断。

- 队列按任务 `created_at` 落入查询日期范围；
- 完成耗时为有效 `confirmed_at - created_at`；
- 进行中任务只计算截至 `dataAsOf` 的已等待时长，不混入完成耗时；
- 取消任务只计数量。当前没有独立取消时间，不计算取消耗时；
- 首版支持全部入库、半成品入库、成品入库、出库、调拨、产品名称和最长 366 天范围；
- 完成样本展示平均数、中位数、P90、最大值，并分别展示任务类型、实际有任务日期和最长等待任务；
- 报表继续复用唯一 `run_registered_report`、`analytics_expert`、`ReportRun` 和同快照 XLSX，没有新增报表专用 MCP 工具。

## 2. 真实浏览器用例

本地服务使用北京时间、真实本地数据库和管理员测试账号，通过 AI 助手完整执行“模型理解 → 分析专家决策 → 工具调用 → 结果分析”。处理过程卡片显示 6 个受控阶段，不展示模型思维链、工具参数或内部 ID。

| 用例 | 用户输入 | 关键结果 | 结论 |
| --- | --- | --- | --- |
| PTC-01 | 最近90天托盘任务处理耗时如何，哪些还在等待？ | 33 条：完成 27、进行中 6、取消 0；完成中位数 33 秒，P90 约 59 天，最长等待约 85 天 | PASS |
| PTC-02 | 最近90天只看成品入库任务处理耗时 | 21 条：完成 17、进行中 4、取消 0；任务范围正确收窄为“成品入库任务” | PASS |
| PTC-03 | 最近90天黄冰糖（袋）的托盘任务处理耗时 | 23 条：完成 17、进行中 6、取消 0；产品范围为“当前产品名称包含黄冰糖（袋）” | PASS |

三组结果都把完成耗时、进行中等待和取消数量分开。没有把“已等待”说成“逾期”，没有输出员工绩效或现场完整流程结论；没有完成样本的出库类型显示“暂无有效样本”，不伪造为 0 秒。

本轮浏览器观察到前两次回答约 12 秒，第三次产品筛选约 24 秒。样本量不足以形成 P50/P95 结论，但第三次仍明显偏慢；后续性能验收应继续拆分记录主模型、专家决策、工具查询和最终分析耗时，不能仅用“功能通过”替代延迟目标。

浏览器对 Blob 下载事件的自动捕获超时，因此没有把该现象误判为接口失败。改用相同本地账号和真实 HTTP 接口验证最新产品筛选快照：

- 文件头为 `50 4B 03 04`，即有效 XLSX/ZIP；
- 导出只读取已保存 `ReportRun`，不重新运行报表。

临时导出文件验证后已删除。

## 4. 验收中发现并修复的问题

### 4.1 Spring 构造器选择失败

为了固定时钟测试，服务保留了生产构造器和测试构造器。首次真实整包启动发现 Spring 无法推断注入构造器。现已为生产构造器显式增加 `@Autowired`，整包启动通过。

### 4.2 统一报表入口遗漏任务权限

报表服务和归档层已要求 `task:view`，但统一报表 Controller 的运行、读取和导出入口仍只允许生产或化验权限。现已为三条入口补充 `task:view`，并加入 `AgentReadPermissionMatrixTest`，避免只有管理员能使用流程效率报表。

### 4.3 双运行时模型环境变量同名

验收时发现 Python 的旧变量 `AGENT_MODEL_MODE=openai_compatible` 会被 Spring 宽松绑定为 Java 旧路径的 `agent.model.mode`。现已新增 Python 专用变量 `AGENT_PYTHON_MODEL_MODE` 并更新联合部署样例；旧变量只保留为进程级兼容输入，不再用于共享环境文件。该修复不改变“Python 主模型理解和专家决策”的运行架构。

## 6. 发布结论与剩余限制

`pallet_task_cycle_time_v1@1` 通过当前本地只读报表验收，可以作为第五份登记报表进入后续阶段。以下能力仍保持阻断：

- 生产订单阶段耗时；
- 标签打印到实际入库耗时；
- 取消耗时；
- SLA 逾期；
- 批量作业耗时（本地 31 条样本缺少操作批次号）；
- 员工绩效、责任归因和现场全部流程效率。

库存趋势仍受连续 7 天日终快照与守恒对账门禁约束，不因本报表通过而解除。
