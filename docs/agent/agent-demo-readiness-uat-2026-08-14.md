# Agent 演示前整体验收报告（2026-08-14）

> 状态：**有条件通过，可用于下周本地演示**  
> 验收范围：只读查询、运营报表、RAG、受控成品入库引导、安全边界、角色权限  
> 暂不纳入：个人微信视觉采集（已暂停）、除成品入库以外的写操作、预测模型、生产环境发布

## 1. 结论

本轮按真实用户说法进行端到端验收，而不是按接口逐个调用。核心流程均能遵守：

1. 主模型理解用户需求；
2. 选择受限业务专家；
3. 专家判断并调用登记工具；
4. 模型分析工具事实并生成用户语言；
5. 前端以文本、选择卡片、业务卡片或报表卡片呈现；
6. 写入能力未开放时保持失败关闭。

验收期间发现 4 个真实缺陷并完成修复、回归：

- 选择煮糖批次后仍停留在批次列表目标，无法进入流转详情；
- 明确指定生产订单时仍要求从关联订单中二次选择；
- 库存趋势真实快照门禁未满足时暴露内部工具错误语言；
- 审计与员工专家已存在 GoalContract 和工具，但未加入默认 LLM 专家白名单，暴露“实验白名单”研发措辞。

另完成两项体验优化：RAG 来源去重并限制为 3 张非重复卡片；库存趋势本地回放明确标记为模拟数据，不与真实日终快照混用。

本结论不等于“系统不存在任何缺陷”。当前剩余风险主要是外部模型延迟、演示机启动预热以及本地历史快照不足，均已给出演示规避措施。

## 6. 演示建议

### 6.1 推荐主线（约 8～12 分钟）

1. `查询黄冰糖当前库存总览` → 选择具体产品；
2. 回答“需要” → 展示库存分布卡；
3. `查询黄冰糖（袋）2026-07-17的化验情况` → 展示指标和标准；
4. `今天整体运营情况如何？` → 展示报表与导出；
5. `查询2026-06-30的煮糖批次` → 选择批次 → 查看关联订单；
6. `3号库位入库2板黄冰糖` → 演示产品澄清、二维码来源区分和恰好选择2个任务；停在预览前，不执行真实写入；
7. `白砂糖生产工艺中，金属检测的限值是多少？` → 展示RAG来源卡；
8. `帮我把1号库位的黄冰糖全部出库` → 展示安全边界。

### 6.2 演示前 10 分钟检查

- 先启动 Java、Python、前端并等待 MCP 预热成功；
- 登录后先问一个简单库存问题，确认模型、工具网关和流式通道均已热；
- 确认本机时间与北京时间一致；
- 使用本文固定样例数据，不临场更改数据库；
- 库存趋势必须保留“模拟数据”提示；
- 微信自动采集不要纳入本次演示承诺。
