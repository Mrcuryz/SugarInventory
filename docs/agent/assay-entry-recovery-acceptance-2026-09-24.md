# D2e 化验保存中断后的核实与恢复

日期：2026-09-24。前置：[D2d 单产品主流程](assay-entry-ui-acceptance-2026-09-24.md)。本轮为本地隔离验收，未部署、未改库存或现有业务化验。

## 已解决的问题

旧页面仅在内存保存确认引用：保存响应丢失后刷新会丢失回查入口；原结果接口要求会话仍有效，无法处理刷新创建新会话或会话到期后的核实。

本轮没有放宽确认/执行的会话与权限规则，而是增加**人工“核实结果并结束”**：

- 已经提交成功：返回原化验记录和实际版本，不再次执行。
- 未保存：取消本次待确认/待执行状态，再允许重新录入。
- 与迟到执行竞争：复用相同会话行锁、预览锁与事务。执行先获得锁则回读成功；恢复先获得锁则后续执行被拒绝，不允许核实后又迟到写入。
- 不确定时显示“待核实”，不能把未知结果称为“未保存”。

## 接口与权限

新增 `POST /api/agent/sessions/{sessionId}/assay-entry/previews/{ref}/recover`，不接受业务检测值，不创建化验。它不是纯查询：尚未保存时会将**控制记录**取消并写审计，因此使用 POST、由明确标注作用的按钮触发。

旧会话可以已撤销/到期，但必须仍属于当前用户。仍重新读取当前用户、Agent使用资格、`assay:view`与`assay:create`/`quality:test`，验证引用归属和存档完整性；撤权、换用户不返回数据。确认与执行仍要求ACTIVE且未到期的会话。恢复路径未加入MCP委托白名单，不增加模型写工具。执行开关默认关闭、控制Controller的开启条件不变。

## 页面恢复记录

- 在发送确认请求**之前**，浏览器持久化当前账号的会话引用与预览引用；不能可靠写入时不发确认。
- 不持久化检测值、产品名、执行口令或保存结果。按账号隔离，服务端归属校验才是安全边界，不信任客户端账号字段。
- 每个操作使用独立存储项，避免多标签页读写一个数组导致引用丢失；兼容本地上一版数组格式。多标签页存储行为本轮通过模块测试，未冒充真实多标签页端到端验收。
- 成功或明确取消后删除对应引用；结果未知时保留。再次打开助手显示核实入口，未核实前阻止继续发送新录入请求。
- 明确结果返回前不会自动重新保存。恢复按钮说明“已保存的会显示原记录，尚未保存的会取消本次操作”。

当前恢复依赖同一浏览器保留的站点存储，**不承诺清除浏览器数据/更换设备后自动找回中断入口**；实际已保存化验仍可通过现有查询核对。会话和控制记录保留策略、执行开关关闭后的恢复入口需在发布检查中明确，不能把永久可恢复作为保证。
