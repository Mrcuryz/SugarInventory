## 本轮发现并修复的问题

1. 多轮“最近 N 天”补充范围时，活动目标可能保留但全局产品/库位范围缺省，导致参数校验失败。现按活动 GoalContract 补齐受控 `ALL` 范围。
2. 模型已得到权威空结果但连续漏引证据时，Runtime 原先会返回完成校验错误。现只在 FactEnvelope 已完整、无工具错误且证据工具明确返回 `NO_DATA` 时使用安全空结果兜底。
3. 主模型识别到正确 GoalContract、但错误选择目标归属专家时，原先直接拒绝。现允许一次受控路由纠正，不放宽专家工具白名单。
4. “仓管员名单”和“角色权限目录”、“指定库位最近操作”和“全局业务审计日志”存在语义混淆。主模型提示已明确业务边界。
5. 仓库近期操作工具把北京时间 RFC3339（例如 `2026-07-18T00:00:00+08:00`）直接转发给只接受本地时间的 Java DTO，导致 400。仓储 MCP 现统一转换为北京时间本地日期时间后再调用后端。
6. 本地验收启动配置必须显式启用 9 个已登记只读专家；只启用默认 6 个专家会让基础资料、后台管理和审计目标被错误拒绝。
7. G03 中专家模型曾把用户语言“待复核”转换成 `reviewStatus=PENDING`，而真实受控枚举是 `OPEN`，导致 498 条数据被误报为空。现已在模型可见 schema、专家约束和 Runtime 参数边界统一限定枚举，并将常见别名归一为 `OPEN`。
8. 项目虽然导入了 MyBatis-Plus 分页类，但没有注册分页拦截器，导致 G03 返回 `total=0、records=498`，安全层截断后模型误报为 50 条。现已注册 MySQL 分页拦截器；真实审计记录确认修复后为 `total=499、recordCount=20`。
9. 专家模型曾在同一消息中对相同成功条件重复调用两次审计工具。Runtime 现按工具名与规范化参数签名阻止同轮重复成功查询，并要求模型引用既有观察完成分析；真实回归已从两次工具调用降为一次。
