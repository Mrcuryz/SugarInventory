## 未完成与限制

- 尝试输入 `0` 时设备进入锁屏，尚未核实该值是否进入输入框、是否与空白区分，以及切换日期、退出再进入后的本机草稿恢复。
- 备注列、指标详情、其他三个分区的逐项浏览、日历历史、Excel 导入导出、权限只读角色和网络异常仍待实机检查。
- 保存、提交、版本冲突及多人并发属于真实业务写入场景，需在隔离测试服务与明确的测试数据上完成，不能凭本轮只读结果宣称可上线。
- 三星手机不能验证 DT50 左右实体扫描键、ScanWedge 输出和连续扫码稳定性。

结论：`0.3.0-debug` 在本轮三星实机上完成安装、登录、日报总览及一个固定指标组的阶段验收；完整生产日报实机验收尚未完成。

## 2026-11-05 续验与错误提示修复

用户手动解锁设备后继续验收。先在 10 月 31 日的多晶车间“出糖油 / 当日实绩”输入 `0`，页面显示“未保存”；四个分区均可进入，日历弹层可打开。随后切换日期时，页面显示了英文技术异常 `Value JWT of type java.lang.String cannot be converted to JSONObject`，且停留在原日期。代码核对确认：后端 JWT 过期时返回 HTTP 401 纯文本，Android 客户端此前先强制按 JSON 解析，致使 401 状态丢失。

已在 Android 客户端修复非 JSON 错误响应的状态保留及提示转换，并统一处理 API 回调中的技术异常。401 显示“登录状态已失效，请重新登录”，403、版本冲突、网络异常和服务端错误也转换为中文用户提示；业务校验的中文原因仍可显示。Excel 本机读写失败不再拼接底层异常消息。修复后 `testDebugUnitTest assembleDebug --offline` 成功，23 项单测、0 失败；Debug 包已覆盖安装到同一设备。过期会话在修复版上的自动跳转尚未单独制造条件复验，本轮通过单测和后端响应代码验证该路径。

用户重新登录后，11 月 5 日日报总览正常加载，切换到 11 月 4 日成功，无技术错误。多晶、红糖、单晶、全厂汇总四个分区及日历再次通过实机浏览。11 月 4 日多晶车间“出糖油 / 当日实绩”在本机输入 `0` 后显示“未保存”；重启 Debug App、返回同一日期和分组后，`0` 仍存在，其他空白字段仍显示“点击填写”。横向滑动可显示“备注”列；单项详情弹层完整展示五个数值字段和备注；半成品组的产品选择弹层成功加载对应产品候选。上述过程没有触发服务器保存或提交。
