# DT50 扫码入库验证方案

更新时间：2026-08-29

## 1. 现场目标

仓库管理员手持优博讯 DT50，按以下固定顺序完成作业：

1. 扫描一个库位码，锁定本批次的目标库位。
2. 连续扫描多个托盘码。
3. 在设备上核对待确认清单。
4. 点击“确认入库”，整批提交。

会议已决定不再区分库位左右侧，也不记录库位内部的排、层等精确位置。因此现场只贴一张库位码，App 不显示、不采集也不提交左右侧、排号和层数。现有数据库结构暂不调整；兼容坐标由后端统一生成，App 不感知该实现细节。

## 2. 首版边界

首版用于验证 DT50 是否能降低仓管录入成本，同时作为后续正式 App 的代码基础。

包含：

- 姓名、统一口令登录和 JWT 鉴权；
- 服务地址可配置；
- 库位码解析和库位锁定；
- 托盘码连续扫码、排队校验、去重、失败提示；
- 展示托盘码、产品、生产日期、生产标签数量；
- 最多 20 个托盘的整批确认；
- 成功、重复、失败的颜色、提示音和振动反馈；
- 扫错库位时明确提示清空当前清单后再切换；
- 登录失效时停止操作并返回登录页。

不包含：

- 创建新的入库任务；
- 绑定空闲二维码；
- 修改产品、数量或生产日期；
- 出库、调拨和其他作业；
- 离线执行写入；
- 对现有库存表或库位模型进行结构改造。

## 3. 复用与调整

视觉和交互参考微信小程序 `LaibinSugarInventoryWxAPP/pages/scan/index`：蓝色作业卡片、扫码反馈、统计区、任务池和底部确认栏。

小程序使用 `wx.scanCode`，不能直接获得 DT50 物理扫描头输出。因此 Android 版复用了业务顺序和视觉语言，扫码输入层改为原生键盘事件缓冲，并增加一个不弹出软键盘的焦点接收器，以兼容 ScanWedge 的“文本框优化”模式。当前不写死优博讯广播 action/extra；首轮真机已经证明键盘输出可稳定完成业务闭环，暂不需要厂商广播适配器。

## 4. 后端最小增量

库位码内容采用版本化格式：

```text
LSI|WAREHOUSE|1|<warehouseId>
```

二维码只保存稳定的库位 ID，不保存库位名称。扫码后必须请求后端解析，以数据库中的实时名称、状态和容量为准。

新增接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/warehouse/{id}/location-code` | 获取库位码及实时库位信息 |
| GET | `/api/warehouse/location-code/resolve?code=...` | 扫码解析库位 |
| GET | `/api/warehouse/{id}/location-qrcode.png` | 下载库位二维码 PNG |
| GET | `/api/warehouse/{id}/location-qrcode-label.pdf` | 下载可打印库位标签 PDF |

PNG/PDF 下载沿用 `qrcode:print` 权限；查询和解析沿用仓库控制器的 `warehouse:view` 权限。

托盘校验与写入复用现有接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/pallet-codes/parse?code=...` | 将二维码内容解析为标准托盘码并检查状态 |
| POST | `/api/pallet-codes/tasks/list` | 获取唯一的待入库任务及显示信息 |
| POST | `/api/pallet-codes/tasks/confirm` | 整批确认入库，任一失败整体回滚 |

当托盘来自生产订单标签时，确认服务会采用 `production_order_output_code` 中的单位和数量，仓管无需再次录入。没有生产标签记录的旧任务继续沿用现有默认规则，本次不改变其业务口径。

## 5. 设备验收用例

### V01 启动和登录

- 输入：服务地址、仓管姓名、统一口令。
- 期望：登录成功进入扫码页；退出后清除 JWT；App 不保存口令。

### V02 扫描库位

- 输入：有效 `LSI|WAREHOUSE|1|<id>` 库位码。
- 期望：页面从“第 1 步”切换到“第 2 步”，显示实时库位名称、状态和容量。

### V03 未扫库位先扫托盘

- 输入：直接扫描托盘码。
- 期望：不加入清单；红色提示“请先扫描库位码”；失败音和长振动。

### V04 连续扫描

- 输入：快速连续扫描 3 个不同的待入库托盘码。
- 期望：扫码进入队列并按顺序校验；3 个托盘均展示；不会因上一个请求未完成而丢码。

### V05 重复扫描

- 输入：重复扫描同一托盘码。
- 期望：清单只保留一条；重复计数增加；不执行写入。

### V06 异常托盘

- 输入：不存在、已入库、已取消或无待入库任务的码。
- 期望：不加入清单；显示后端返回的用户语言原因；后续扫码仍可继续。

### V07 切换库位

- 前置：已锁定库位并扫描至少一个托盘。
- 输入：扫描另一个库位码。
- 期望：必须明确确认“清空并切换”；取消时保留原清单；确认时只清空本地清单，不写库存。

### V08 整批确认

- 前置：使用隔离测试数据准备多个待入库托盘。
- 输入：点击确认、核对摘要、再次点击确认入库。
- 期望：后端返回数量与清单一致；页面提示完成并要求扫描下一库位。

### V09 整批回滚

- 前置：确认前让其中一个托盘在另一终端先完成或取消。
- 输入：原设备整批确认。
- 期望：本批次全部不执行；设备保留清单并提示失败原因，方便重新核对。

### V10 物理扫描输出

- 输入：DT50 左右扫描键分别扫描库位码和托盘码。
- 期望：键盘输出模式下均能稳定接收；有无 Enter 后缀均不粘连；连续 20 次扫描无丢码。
