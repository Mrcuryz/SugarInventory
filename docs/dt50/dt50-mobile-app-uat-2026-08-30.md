# DT50 现场 App 阶段验收记录（2026-08-30）

## 1. 验收范围与环境

- 设备：优博讯 DT50，Android 11；
- 扫描方式：ScanWedge 按键输出，App 使用隐藏焦点接收扫码；
- App：`dt50-app`，版本 `0.2.0`；
- 服务：本机后端 `http://127.0.0.1:38082`，通过 ADB reverse 供设备访问；
- 数据：当前本地研发库；
- 原则：本轮只执行查询和写入前校验，不点击出库或调拨的最终确认，不改变库存数据。

| D02 | 打开仓库概况 | 调用仓库容量汇总接口 | 展示 87 个库位、当前容量 27、总容量 13340、79 个空库位；低占用率显示为 `<1%` | 通过 |
| D03 | 从仓库概况进入 4 号库位 | 查询库位库存和最近业务操作 | 展示 2 条库存和 6 条最近操作，不展示左右、排、层 | 通过 |
| D04 | 打开产品查找 | 调用库存台账查询，不使用容易产生歧义的聚合结果 | 逐托盘展示产品、托盘码、当前库位、数量、生产日期和入库日期 | 通过 |
| D05 | 打开化验查询 | 调用受控化验记录查询 | 返回 4 条记录，判定使用中文用户语言；空标准不显示为 `null` | 通过 |

## 3. 本轮发现并修正的问题

1. 仓库总容量很大时，整数占用率会错误显示为 `0%`；已改为有库存且不足 1% 时显示 `<1%`。
2. Java JSON 字符串值为 `null` 时会被错误渲染成文本 `null`；已统一按缺失值处理。
3. 产品查找若使用库存聚合结果，不足以回答“哪块托盘在哪个库位”；已改为库存台账结果，逐托盘展示。
4. 出库和调拨初始页缺少当前扫码阶段反馈；已增加“等待扫描在库托盘码/目标库位码”。

## 4. 尚未执行的写入验收

出库和调拨已完成 App 接入，但以下用例需要在隔离数据或明确可回滚的测试数据上执行后，才能标记为可上线：

1. 成品整批出库：创建任务、确认任务、库存扣减和流转记录一致；
2. 半成品普通出库：只走普通出库，不进入已废弃备料池；
3. 整批调拨：原库位扣减、目标库位增加、默认兼容侧别为“左”，App 不显示侧别；
4. 重复确认、并发状态变化、目标库位失效和部分托盘冲突；
5. 创建成功但确认失败：清单锁定，只允许重试确认，不能重复创建任务；
6. 401、403、断网和超时：不得静默重试或在恢复网络后自动写入；
7. 10～20 个托盘连续扫码：无丢码、无重复写入，确认摘要可核对。

## 5. 阶段结论

DT50 已从单一入库验证版扩展为仓管现场工作台。已验收的入库基线和本轮只读能力可以继续作为后续开发基础；出库与调拨目前达到“可扫码、可校验、可预览、可调用接口”的状态，但最终写入仍需完成第 4 节的隔离验收。正式现场试点前还需补弱网策略、签名发布和受控升级。

## 6. UI 复验补充

针对首版工程验证 UI 不满足上线标准的问题，已按旧小程序新版页面重新建立 Android 视觉基线，并在 DT50 真机复验：

- 工作台：渐变值班卡、权限状态、主作业入口、图标化次级入口和快速查询分区；
- 扫码入库：步骤胶囊、当前目标主卡、四项作业统计、任务池空状态和固定底部操作栏；
- 仓库概况：总体占用主卡、实时状态和可点击库位卡片；
- 产品查找：统一查询条件、结果状态和逐托盘业务卡片；
- 全局：统一页头、色彩、圆角、阴影、输入框、反馈条和确认弹窗。
