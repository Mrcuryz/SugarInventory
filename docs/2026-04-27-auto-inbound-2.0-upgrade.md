# 智能报数入库 2.0 升级说明

## 背景

旧版自动入库在确认阶段直接调用传统半成品/成品入库服务，没有进入二维码任务链路，也不会从固定产品二维码池分配二维码。升级后，智能报数入库统一遵守“一个二维码 = 一个库存占位 = 一条 inventory 记录”的规则。

## 本次改造

1. 报数解析后仍使用 Redis 保存临时批次，不直接创建正式任务。
2. 每条报数明细会按产品每板件数拆分为多个单二维码任务项：
   - 整板：`1板`
   - 散件：`N件，占1板位`
3. 草稿中展示需要二维码数量、当前可用固定产品二维码数量、缺失字段和风险提示。
4. 用户确认后，系统按产品从固定产品二维码池中锁定 `FREE` 二维码。
5. 每个二维码先创建真实 `pallet_task`，再直接调用现有二维码入库确认链路。
6. Web 自动入库页新增侧别、二维码需求、拆分结果和执行结果展示。

## 保留边界

第一阶段仍不做成品自动绑定半成品来源。成品报数入库可以完成二维码分配、任务创建和成品入库；半成品来源消耗仍建议走二维码任务中心的既有链路人工处理。

## 验证
