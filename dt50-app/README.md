# DT50 扫码入库 App

本目录是优博讯 DT50 的原生 Android 验证版，也是后续现场扫码 App 的开发基础。

当前 `v0.2.5` 以已真机验收的扫码入库为基线，扩展为仓管现场工作台：

- 扫码入库：先扫入库库位二维码，再连续扫待入库产品二维码，核对后一次确认；
- 扫码出库：连续扫描在库产品二维码，核对后一次确认；
- 扫码调拨：先扫调入库位二维码，再连续扫在库产品二维码，核对后一次确认；
- 仓库概况与库位详情：查看实时容量、库存明细和最近业务操作；
- 产品查找：按名称模糊查询，直接显示产品二维码、具体库位和数量；
- 化验查询：查看产品、采样日期、判定、标准和异常指标；
- 操作记录：展示二维码对应产品的入库、出库和调拨记录。

界面以旧微信小程序较新的工作台、扫码和查询页为视觉参考，并针对 DT50 竖屏、实体扫描键和单手操作重新布局；只复用视觉语言，不迁移旧业务。

应用名称统一使用“来冰仓储扫码”。内部英文工程名 `laibin` 在用户界面中统一解释为“来冰”；启动图标与登录页标志采用“数字仓储平台”品牌素材中的独立图形标志。

工作台操作入口复用微信小程序现有图标，并移除不影响判断的重复副标题。页面仅保留当前用户、扫码步骤、处理结果和异常提示等现场作业所需信息。

各入口按服务端返回的权限编码控制。App 不展示备料池、左右侧、排、层或底层审计 JSON。

扫码入库不创建新入库任务，也不要求仓管重复填写产品、日期、数量或库位内部位置。
出库和调拨使用现有“创建任务 → 确认任务”接口；如果任务已创建但确认失败，App 会锁定清单并提供重试确认，不会静默重复创建。

## 现场文案口径

- App 页面不展示设备型号、接口步骤、内部枚举或后端对象名；
- 后端 `pallet`/“托盘”概念在现场统一展示为“二维码”或“产品二维码”；
- 入库使用“入库库位”，调拨使用“调入库位”，避免含义不清的“目标库位”；
- `PREPRINTED`、`USED_UP` 等内部状态在展示前统一转换为中文；未知内部枚举不直接透传；
- 技术文档仍保留类名、接口字段和已验收设备型号，便于维护和追溯。

## 构建

需要 JDK 17+ 和 Android SDK。项目自带 Gradle Wrapper：

```powershell
cd dt50-app
$env:ANDROID_HOME = "C:\Users\<用户名>\AppData\Local\Android\Sdk"
.\gradlew.bat testDebugUnitTest assembleDebug
```

调试 APK：`app/build/outputs/apk/debug/app-debug.apk`。

甲方试用包使用项目专用签名，密钥只保存在本机 `dt50-app/.signing/`，并由 Git 忽略。后续升级包必须继续使用同一密钥签名，否则无法覆盖安装；不得将密钥随 APK 交付。

## DT50 扫描配置

当前验证版已经在 DT50（Android 11、ScanWedge `V2.1.21_20241106`）完成实体扫码和整批入库验证。App 使用 Android 键盘事件和隐藏焦点接收器接收扫码内容，不依赖厂商私有广播参数。请在 DT50 的扫描设置中：

- 启用 ScanWedge 和默认配置中的扫描头；
- 将输出方式设置为“按键输出”；
- 键盘类型使用“文本框优化”；
- 建议启用 Enter 回车后缀；
- 保留扫码成功音，App 还会根据业务校验结果发出成功或失败提示音和振动。

隐藏焦点不会弹出系统软键盘。即使设备未配置 Enter 后缀，App 也会在字符流停止约 180ms 后提交本次扫码。

## 登录与服务地址

登录页不向现场用户展示服务地址，正式包固定连接 `https://ccgl.site`。本机联调时通过构建参数覆盖，例如 `./gradlew.bat assembleDebug -PserverBaseUrl=http://127.0.0.1:<后端端口>`，不在 App 页面暴露技术配置。

登录状态有效时直接进入工作台。登录页提供“记住我”选项，默认不勾选；用户主动勾选后，姓名和口令使用 Android Keystore 生成的本机密钥加密保存，下次登录自动填充。取消勾选会立即清除已保存的登录信息。服务地址不保存在本地。

## 迁移边界

旧微信小程序只作为扫码交互和视觉参考，不是业务事实来源。不得迁移历史备料池、生产中半成品占用、左右/排/层定位、微信授权或旧手工入库流程。完整边界和分阶段验收口径见 `docs/dt50/dt50-mobile-app-product-plan.md`。
