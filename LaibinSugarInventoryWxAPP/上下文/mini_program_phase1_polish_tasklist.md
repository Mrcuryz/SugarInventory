# 小程序第一阶段收口优化任务单

## 1. 文档目的
本文件用于给 Codex 提供**小程序第一阶段收口优化**的上下文与任务清单。  
当前小程序第一阶段骨架已经基本完成，包括：

- 新 tabBar 与五个一级入口
- 登录 / 绑定页
- 工作台首页
- 扫码作业页
- 托盘详情页
- 任务中心
- 查询页 / 我的页占位版本
- API / utils / 公共组件基础层

现在进入的不是“继续扩页面”阶段，而是：

> **第一阶段运行期收口 + 交互修正 + UI 精修阶段**

本阶段目标是把当前“能跑的骨架”，推进成“真正可投入使用的第一阶段成品”。

---

## 2. 当前阶段判断

当前小程序状态可以概括为：

- 架构方向正确
- 扫码、任务、托盘详情主线已立住
- 新旧页面已开始分离
- 统一组件层已经抽出来

但仍存在这些问题：

- 部分默认值逻辑不安全，可能误操作
- 扫码页职责未完全收口
- 查询页 / 我的页仍偏占位
- 使用手册仍是旧式长文页
- 图标体系未统一
- 移动端空状态、异常态、加载态还不够成熟
- 设计系统还未彻底统一
- 现场连续作业的细节稳定性还不够

因此，本阶段必须优先做“收口优化”，不要直接进入第二阶段大扩展。

---

## 3. 本轮优化总目标

本轮优化目标分为四类：

### 目标 A：修正会导致误操作的问题
包括：
- 默认选中第一项
- 数量规则不统一
- 查询入口职责混乱
- 缺少“转入备料池”作业模式

### 目标 B：收口扫码主流程
让扫码页真正成为“纯作业中心”，而不是作业与查询混合页。

### 目标 C：把查询页、我的页、手册页从占位状态升级成正式页面
统一风格与信息层级。

### 目标 D：统一图标、状态、颜色、组件语义，提升整体产品感
使小程序看起来像正式的现场作业终端，而不是重构中的演示版。

---

## 4. 必做问题清单（用户明确提出）

以下是必须落实的问题，不允许遗漏。

---

## 4.1 扫码成功后，表单中的“产品状态”和“产品”不要默认选中第一条
### 问题
当前扫码成功后，相关表单字段会默认选中第一条，这会导致误操作。

### 要求
- 产品状态默认空，展示淡灰色占位文本：`请选择`
- 产品默认空，展示淡灰色占位文本：`请选择`
- 只有当后端明确返回**唯一可选值**时，才允许自动带出
- 否则必须人工选择

### 验收标准
- 进入相关表单时，不再自动选中第一项
- 用户能明显感知“还未选择”
- 唯一值场景自动带出逻辑正确，不影响效率

---

## 4.2 所有与数量有关的操作都必须统一规则
### 问题
数量规则不能只在某一个页面生效，必须全局统一。

### 全局规则
- 当单位为 **板** 时：数量固定为 `1`，不可修改
- 当单位为 **件** 时：数量可编辑
- 数量必须为 **正整数**
- 数量上限 = 产品表中的 **每板件数**

### 作用范围
以下所有表单、弹层、确认面板都必须统一：
- 扫码作业页中的相关创建 / 确认表单
- 任务确认页
- 托盘详情页中的相关操作弹层
- 任何移动端入库 / 出库 / 调拨 / 转入备料池相关表单

### 验收标准
- “板”模式下数量无法编辑
- “件”模式下只能输入正整数
- 超过每板件数时明确提示
- 所有页面规则一致，不出现一处能改、一处不能改的情况

---

## 4.3 查询页必须同时支持“手动输入托盘码”和“扫码查询”
### 问题
当前查询能力不完整，扫码查询与查询页职责没有统一。

### 要求
在查询页正式支持：
- 手动输入托盘码
- 一键扫码托盘码
- 点击查询
- 查询成功后进入托盘详情页

### 说明
扫码是一种“进入方式”，不应只存在于扫码页。

### 验收标准
- 查询页内可手输托盘码
- 查询页内可扫码托盘码
- 二者查询结果一致
- 都能正确进入托盘详情页

---

## 4.4 优化使用手册页面，使其 UI 风格与新小程序整体风格一致
### 问题
当前手册页仍然是旧式长文滚动页面，风格明显割裂。

### 要求
将使用手册页重构为更统一的帮助中心风格，建议包含：
- 标题头
- 章节目录
- 折叠内容区
- 常见问题
- 核心流程说明
- 更好的间距与文字层级

### 第一阶段本轮要求
本轮至少完成：
- 视觉重构
- 章节样式统一
- 与首页 / 我的页风格一致

### 验收标准
- 手册页不再像“贴一整页说明文”
- 结构清晰，可阅读性提升
- 与新小程序整体风格统一

---

## 4.5 补上“半成品转入备料池”的批量扫码入口
### 问题
当前扫码模式中缺少该业务入口，会导致现场流程不完整。

### 要求
在扫码作业页新增独立模式：
- 转入备料池

### 说明
该模式不能简单混在普通出库里，因为这是不同业务场景。

### 验收标准
- 扫码页模式中出现“转入备料池”
- 扫码后创建对应任务
- 进入本次任务池
- 可批量确认 / 取消

---

## 4.6 扫码查询不应继续放在扫码页中，而应归入查询页
### 问题
当前扫码页同时承担“作业”和“查询”，职责混杂。

### 要求
#### 扫码页
只保留作业模式：
- 入库
- 出库
- 调拨
- 转入备料池

#### 查询页
承担：
- 手输托盘码查询
- 扫码托盘码查询
- 库存查询入口
- 化验查询入口
- 作业记录入口

### 验收标准
- 扫码页不再出现“查询模式”
- 查询页成为正式的统一查询入口

---

## 4.7 不再复用旧小程序图标，需按新 UI 重新配置
### 问题
旧图标风格与当前新版小程序不匹配，会拖累整体质感。

### 要求
重做小程序图标体系，包括：
- tabBar 图标
- 首页快捷入口图标
- 公共功能图标
- 状态辅助图标（若有）

### 图标规则建议
- 线性图标为主
- 粗细统一
- 圆角统一
- 默认深灰，激活主蓝
- 不再混用旧的实心图标、彩色老图标、粗线条图标

### 验收标准
- tabBar 图标风格统一
- 首页入口图标统一
- 不再出现明显旧图标痕迹

---

## 4.8 “查询”和“我的”页面 UI 比较丑，需要优化
### 查询页要求
- 从占位入口页升级成“查询中心”
- 结构更完整
- 托盘查询区更突出
- 下方模块分组更清晰
- 空态 / 暂未开放内容表达更自然

### 我的页要求
- 重构为三段式结构：
  - 账号卡
  - 常用入口
  - 系统操作
- “退出登录”不要过于突兀
- 页面层级更稳
- 不要只是简单白卡堆叠

### 验收标准
- 查询页和我的页不再显得像临时占位页
- 风格与工作台、任务页、扫码页统一

---

## 4.9 整体 UI 继续精修，体现高级、高效、简洁、快捷的感觉
### 要求
继续统一以下内容：
- 页面留白节奏
- 卡片圆角与阴影
- 按钮高度与主次关系
- 状态标签样式
- 搜索区与列表区关系
- 文字层级
- 主色 / 状态色语义

### 目标
让小程序体现：
- 高级
- 高效
- 简洁
- 快捷
- 现场作业感
- 企业系统感

## 5. 需要补充的隐性问题（必须纳入本轮）

以下是运行期和移动端体验中必须补充的问题。

---

## 5.1 扫码成功 / 失败反馈需要更“现场化”
### 当前问题
主要依赖文字提示，不够直观。

### 要求
- 成功：清晰 toast / 颜色反馈 / 可选短震动
- 重复：黄色提醒
- 失败：红色并明确原因
- 新增任务后自动滚动到最新一项（如适用）

### 验收标准
- 操作员不用反复盯列表判断是否扫成功
- 重复、失败能快速区分

---

## 5.2 本次任务池需要有“本次作业上下文”
### 当前问题
任务池只是列表，缺少会话感。

### 要求
在扫码页顶部或任务池上方增加：
- 当前模式
- 本次已扫数量
- 成功数量
- 失败 / 重复数量（如已有能力）
- 当前操作说明

### 验收标准
- 用户能理解自己正在处理什么作业
- 不只是看到零散任务项

---

## 5.3 批量确认 / 批量取消 / 清空需要防误触
### 要求
- 批量确认前弹二次确认
- 批量取消前弹二次确认
- 清空只清本地任务池，不影响已创建任务时，文案要写明
- 明确告知将操作几条任务

### 验收标准
- 用户不容易误点造成大面积误操作

---

## 5.4 考虑断网 / 弱网场景的基本处理
### 问题
现场小程序必须考虑接口失败后的用户感知。

### 要求
至少支持：
- 请求失败时明确提示
- 扫码创建任务失败后保留本地记录并可重试（如当前结构允许）
- 不因网络失败导致用户误以为已经创建成功
- 避免“重试造成重复创建”的歧义

### 验收标准
- 弱网时页面行为可理解
- 错误不会悄悄吞掉

---

## 5.5 托盘详情页要明确内容优先级
### 要求
页面分层：

#### 第一屏最重要
- 托盘码
- 状态
- 产品
- 位置
- 当前可执行操作

#### 第二层
- 化验摘要
- 当前任务
- 最近流转

#### 第三层
- 全量流转
- 更多扩展信息

### 验收标准
- 第一屏不拥挤
- 用户一进页就能知道“这是哪个托盘，现在能做什么”

---

## 5.6 托盘详情页操作按钮必须动态裁剪
### 要求
不同状态只显示必要操作，不允许所有按钮同时展示。

例如：
- FREE：绑定入库
- PENDING：确认 / 取消
- INSTOCK：出库 / 调拨 / 查看化验
- INVALID：仅查看历史

### 验收标准
- 按钮数量少而准
- 不让用户在大量动作中犹豫

---

## 5.7 查询条件需要支持快捷筛选，减少表单负担
### 要求
记录、查询类页面后续统一支持：
- 今天
- 近7天
- 近30天
- 待处理
- 异常
- 有化验 / 无化验

不要长期保留“默认就展开很多输入框”的移动端交互。

### 本轮要求
可先在查询 / 记录相关页面中预留样式和结构，不要求一次性全部做完。

---

## 5.8 空状态必须区分 3 种情形
### 需要区分
1. 还未查询
2. 查询无结果
3. 加载失败

### 验收标准
- 不再出现“空白页像坏掉了”的感觉
- 用户知道现在是没数据，还是没查，还是失败了

---

## 5.9 长列表需要考虑悬浮按钮遮挡与回顶体验
### 要求
- 悬浮新增按钮不能挡住最后一项操作区
- 列表底部预留安全区域
- 长列表后续应支持回到顶部（本轮可先留结构）
- 从详情页返回时，尽量不丢失原滚动位置（如当前框架允许）

### 验收标准
- 长列表页更适合实际使用

---

## 5.10 统一状态字典和文案口径
### 问题
后续很容易出现“待处理 / 待确认 / 已完成 / 已确认 / 已取消”等文案混乱。

### 要求
将以下内容统一抽字典：
- 托盘状态文案
- 任务状态文案
- 任务类型文案
- 产品状态文案
- tag 颜色映射
- 错误文案
- 按钮文案

### 验收标准
- 页面之间状态表达一致
- Web 与小程序更容易保持口径统一

---

## 5.11 页面文案要更“现场化”
### 当前问题
部分文案仍有后台/开发思维痕迹。

### 要求
将关键文案调整得更贴近现场使用习惯，例如：
- 本次已扫描
- 待确认托盘
- 重新扫码
- 未找到可处理任务
- 该托盘当前不可出库
- 请先选择产品状态
- 请先选择产品

### 验收标准
- 用户更容易理解下一步动作
- 页面不显得“开发味太重”

---

## 7. 设计系统与视觉统一要求

### 7.1 图标体系
- 全站统一为线性图标
- 粗细一致
- 风格一致
- 激活态统一主蓝
- 不混用旧图标

### 7.2 色彩语义
建议明确：
- 蓝：主操作 / 选中 / 主入口
- 绿：确认 / 成功
- 橙：待处理 / 警告
- 红：删除 / 失败 / 危险
- 灰：禁用 / 次要信息

### 7.3 卡片规范
统一：
- 卡片圆角
- 阴影
- 内边距
- 模块上下间距
- 标题字号与副标题字号

### 7.4 按钮规范
统一：
- 主按钮
- 次按钮
- 危险按钮
- 禁用按钮
- 悬浮新增按钮

## 10. 本轮验收清单

### 验收 1：默认值与数量规则
- 不再默认选第一项
- 板 = 固定 1
- 件 = 正整数且 <= 每板件数

### 验收 2：扫码主流程
- 扫码页无查询模式
- 新增转入备料池模式
- 扫码成功 / 失败 / 重复反馈清晰

### 验收 3：查询能力
- 查询页支持手输托盘码
- 查询页支持扫码托盘码
- 查询后进入托盘详情

### 验收 4：托盘详情
- 第一屏信息清晰
- 操作按钮随状态变化
- 化验 / 流转 / 位置展示完整

### 验收 5：页面 UI
- 查询页不再像占位页
- 我的页信息结构清晰
- 使用手册页风格统一
- 图标体系统一

### 验收 6：全局体验
- 空态不再简陋
- 异常态可理解
- 长列表页不被悬浮按钮遮挡
- 页面文案更符合现场使用习惯
